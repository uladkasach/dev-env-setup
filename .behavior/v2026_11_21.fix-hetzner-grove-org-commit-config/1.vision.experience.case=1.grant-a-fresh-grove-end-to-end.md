# case=1 — grant a fresh grove, end to end

happy × critipath · crosses provision · token read · meter · crew gate

## .narrative

a new ahbode grove comes up. the provisioner runs `grove.provision --mode apply`. on the crew seat,
`5.26.commitorgs` asks github which orgs the grove's token can push to, and allows each one in the
seat's org commit meter. no human types a grant:

```
├─ 5.26.commitorgs.configure.upsert
   • allowed orgs '<org3>', 'ahbode', 'ehmpathy' on camper@<grove> — the token can push to each
├─ 5.26.commitorgs.configure.verify
   • the token on camper@<grove> can push to orgs '<org3>', 'ahbode', 'ehmpathy'
   • the commit gate allows org '<org3>' on camper@<grove> ✔
   • the commit gate allows org 'ahbode' on camper@<grove> ✔
   • the commit gate allows org 'ehmpathy' on camper@<grove> ✔
```

a crew of ehmpathy reaches its done gate. `git.commit.set --push` passes the org gate, the commit
lands, and the push opens its pr. the token's push scope is the grant: it is set where the token
is minted.

## .bdd sketch

```
[t0] given  <grove>, fresh; camper; a token that can push to <org3-on-github>, ahbode, ehmpathy; no meter
[t1] when   rhx grove.provision --what 5.26.commitorgs --mode plan
[t2] then   ✋ the commit gate finds no grant for orgs '<org3>', 'ahbode', 'ehmpathy'
[t3] then   the fix is the bundle's own apply; the meter is still absent
[t4] when   rhx grove.provision --what 5.26.commitorgs --mode apply
[t5] then   each token org reads allowed, the gate's way; rc 0
[t6] when   the same apply again
[t7] then   no write; rc 0
[t8] when   a crew of ehmpathy runs git.commit.set --mode apply --push
[t9] then   the org gate passes; the commit lands; the push opens the pr
```

the extant hetzner grove walks the same timeline from `[t1]`, by a re-apply (proven live: the meter
already allowed ahbode and ehmpathy, so the apply allowed <org3> alone).
