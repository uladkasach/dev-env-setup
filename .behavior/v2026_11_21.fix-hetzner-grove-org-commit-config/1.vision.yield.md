# 1.vision — every grove names the org commit grant it owes, and the commander grants it in one command

> ⚠️ **superseded by seed S5.** this vision records the check-only design (a declared org table, a
> verify, and a laptop grant skill). what ships instead:
>
> - `5.26.commitorgs` reads the orgs the grove's github token can push to, and on a cloud crew seat
>   **writes** `allowed` into the org commit meter for each one the meter holds unset
> - a block the human set is kept; a damaged meter is never written over; a local grove, a ci
>   runner, and the admin seat decline
> - no org table and no laptop skill: `git.grove.auth.commit.set` is removed; the human types no
>   command
>
> the live experience catalog (`1.vision.experience.case=_.md`, `…dimensions.md`) and
> `5.3.verification.yield.md` hold the shipped design. the text below stays as the record of the
> design S5 overruled (fulcrums F1, F2).

## .what this builds

two pieces, one fact: **which orgs may commit from this grove's crew seat.**

1. **a bundle, `5.26.commitorgs`** — declares, per `GROVE_ORG`, the orgs whose crews ship from this
   grove (`ahbode) ahbode ehmpathy`). its verify reads the seat's org commit meter and grades each
   declared org. it also reads the `org:` each crew tree on the seat declares — the org the commit
   gate will check — and names any outside the table, with the decision that unblocks them (a
   fail-safe: every hetzner crew tree declares `ahbode` or `ehmpathy`, per the execution yield). it never writes the meter, and never adds a row.
2. **a laptop skill, `rhx git.grove.auth.commit.set <grove>`** — the one command the commander
   types. it opens a direct `ssh -t` to the grove's crew seat and runs `git.commit.uses --org <org>
   allow` for each declared org, on HIS terminal, then reads the meter back.

`grove.provision` reports the absent grant by name on every grove it builds or re-applies. the
grant itself stays one human keystroke away, never zero.

## .why it works

- **the cause is one file.** hetzner's `camper` holds no
  `~/.rhachet/storage/repo=ehmpathy/role=mechanic/.meter/git.commit.uses.org.jsonc`. the ec2 grove's
  `camper` holds `{"orgs": {"ahbode": "allowed", "ehmpathy": "allowed"}}`. `check_org_blocker`
  (`git.commit.operations.sh:2140`) refuses an absent file with `no org config for <org>`. every
  hetzner crew tree already holds its local quota and its sponsor — the org meter is the only absent
  gate.
- **the ec2 grant was typed by hand.** no bundle writes it (grep of `src/grove.provision` for
  `commit.uses --org` / `org.jsonc`: zero hits). so a new grove inherits no grant, and no check
  reports that it lacks one. the forest holds two groves; hetzner is the one no human hand-granted.
- **why it surfaced now.** #203 gave hetzner `~/.grove/purpose = work` (`5.25.purpose`), so the
  crew boot gate began to land crews there. that bundle answers *may a crew LIVE here*; no bundle
  answered *may a crew SHIP from here*. `5.26.commitorgs` is that peer, on the same seat, with the
  same admin-seat decline (`grove_env_seat_is_admin`).
- **the grant is the commander's alone.** `git.commit.uses --org … allow` refuses any caller with
  no tty on stdin (`guard_actor_is_human_via_stdin`, `git.commit.operations.sh:1025`), and
  `rule.forbid.self-grant-human-gates` lists `--org` grants as human-only, and forbids a grant sent
  into a mechanic shell. so provision may DETECT and NAME the grant; it may never WRITE it.
- **`ssh -t` carries the commander's own tty to the box.** the remote guard then sees a real pty
  and passes on its own terms — no `__I_AM_HUMAN`, no flag that asserts a human the code cannot
  see. the laptop skill refuses first if ITS stdin is no tty, so a clone cannot drive it.
- **this repo owns it.** ahbode/infrastructure builds the box and the `camper` user; it holds no
  reference to any rhachet meter (`git.repo.get --in ahbode/infrastructure --words git.commit.uses`:
  24 hits: permission allowlists, route notes, one skill comment). the meter is per-seat state under `~`, which
  this repo's bundles converge — `5.18.openhours` already drives the GLOBAL meter here.

## .the one command the commander types

on his laptop, at his own terminal (never through a duct, never as a `!` command):

```sh
rhx git.grove.auth.commit.set <grove> --mode apply
```

it runs as `camper@<grove>` and grants `ahbode` and `ehmpathy`.

⚠️ **the 2026-11-21 15:00Z mark has passed** (the grove's clock read 15:27Z at the last read). the
skill lands with this pr, so the unblock that needs no merge goes to the commander as ONE ask: the
same two grants, typed by hand, once, on the box as `camper`:

```sh
ssh -t <grove>
# then, as camper, from the crew tree the skill's own plan names on its `cwd` line
# (rhx git.grove.auth.commit.set <grove> — read-only — finds one that links the mechanic role):
cd <the cwd its plan names>
rhx git.commit.uses --org ahbode allow
rhx git.commit.uses --org ehmpathy allow
```

⚠️ not from `~/git/more/dev-env-setup.wip`: a `git.grove.push` tree carries no `.git` and its role
links dangle (`machine_openhours_reconcile` header), so `git.commit.uses` refuses there with
`not in a git repository`. the org meter is one file per seat, so any crew tree grants it for all.
the skill owes the same: a cwd that is a git repo with `repo=ehmpathy/role=mechanic` linked —
`5.18.openhours` builds exactly such a dir.

## .the outcome world

**before.** a crew on hetzner finishes its route, reaches `git.commit.set`, and stops on
`✋ no org config for ehmpathy`. the crew cannot fix it — the gate is human-only. `grove.provision`
on that box printed green; no line anywhere said this seat cannot ship. the commander learns of it
from a crew's pane, mid-incident.

**after.** `grove.provision` on any new grove ends with:

```
   ✋ ConstraintError: the commit gate finds no grant for org(s) 'ahbode ehmpathy' on camper@grove-x
      ⇒ a crew of each is refused at its done gate: 'no org config for <org>'
      fix: the human, at his own terminal (an org grant is his alone):
         rhx git.grove.auth.commit.set grove-x --mode apply
   • all 46 crew tree(s) with an org on camper@grove-x belong to a declared org ✔
```

he types it. one ssh session, two `✔ allowed` lines, a read-back. the next `grove.provision`
prints, per org, `• the commit gate allows org '<org>' on camper@grove-x ✔`. the first crew
commits. (claims 2b · 2c · 2j · 2l · 2n · 2e of `prove.commitorgs-reads-the-meter-as-the-gate`
pin these lines.)

**the aha:** the grant was never the defect — the SILENCE was. a human gate is fine; a human gate
nobody announces is an incident with a delay fuse.

## .mental model

- **commander's words:** "the box needs its commit grant." "the grove tells me what it lacks; i
  type one line."
- **analogy:** a new hire's badge. facilities builds the desk (infra builds the box); the
  onboard checklist (`grove.provision`) lists *"badge: needs your signature"*; the manager signs
  (the commander types the grant). the checklist never forges the signature.
- **our terms vs theirs:** org commit meter ↔ "commit grant", "the org config" (the crew's word,
  from the refusal text). the skill name keeps `auth`, beside its `github` / `keys` / `ssh` peers.

## .evaluation

**goals**

| goal | met? |
|---|---|
| ahbode + ehmpathy crews commit on hetzner | ✔ after the one command |
| provision applies the config on every grove | ✔ the DECLARATION + the check land on every grove; the WRITE is the human's by rule |
| the human's part is one exact command, with box and user | ✔ `git.grove.auth.commit.set`, named in every ✋ |
| no other step left to him | ✔ local quota + sponsor are already set at sprout (read on hetzner's crew trees) |

**pros**
- the next grove cannot ship silent; the gap is a ✋ at build time, not an incident at done time
- the grant path asserts a human by a real tty, never by a flag
- the org set is one per-org table, walked by `prove.org-scoped-rows`

**cons**
- a provision that ends in ✋ until a human acts reads, at first glance, as against
  `rule.require.one-command-provision`. it is the seam that rule allows: the seat that CAN grant is
  the commander's terminal (`rule.require.seam-claims-have-an-owner`)
- a second org list beside `5.10.repos` (`ahbode) ehmpathy ahbode otherorg`). they answer different
  questions (clone vs ship), so they may differ; the clamp must walk both

**edgecases → pit of success**
- corrupt file: verify ✋ malfunction, skill refuses before write (no overwrite of orgs it cannot read)
- unknown org: zero rows, never a fallback
- a block: honored and reported, never re-granted by the skill
- unreachable grove: the skill names `git.grove.wake`

## .open questions & assumptions

1. **[answered — director, S1] [fulcrum F1] which orgs does an ahbode grove declare?** ahbode and
   ehmpathy only. uladkasach repos stay off hetzner by a rule already in force; otherorg waits
   until the commander names it. the original reason for the pick: `ahbode ehmpathy` — the wish
   names both, and the commander's own ec2 grant holds exactly both. (ahbode's reach opt-in into
   the ehmpathy demo account is a different gate; it is no evidence for commit.) a crew tree of
   another org would meet the refusal; a read of every hetzner manifest finds none (each declares
   `ahbode` or `ehmpathy`). to add an org is a one-row change, and the commander's call.
2. **[answered — director, S2] [fulcrum F2] verify-only bundle, never a write.** held: the org
   grant stays the commander's. the alternative is the
   `5.18.openhours` precedent: enact a declared human instruction with `__I_AM_HUMAN`. rejected —
   openhours enacts a schedule the human authored; a declared org list in a clone-authored pr is
   not his grant. the wish's text leans this way; the commander confirms at the end.
3. **[answered] does `rhx` hand its skill the caller's tty?** yes, on stdin. `executeSkill.ts:78`
   at rhachet v1.51.0 (the version HEAD pins) spawns a stream-mode skill with `process.stdin`;
   only stderr is piped. ⇒ at the commander's terminal the laptop skill sees `-t 0` true, and its `ssh -t` gets a
   tty to forward. a clone's tool call has no tty, so the same guard refuses it.
4. **[research] `ssh -t` from a tty yields a pty on the box, so the remote guard passes.**
   `git.grove.auth.github.set:568` relies on the same, and the commander has used it. to confirm on
   hetzner in execution, with a `get` (read-only) under `ssh -t`, before any grant.
5. **[answered] measured:** hetzner's checkout declares `org: ahbode` in `.agent/keyrack.yml`
   (`.play/temporary/read.grove-org`), so `GROVE_ORG` resolves and the table yields rows there. a
   grove pushed with `--from src` carries no manifest, gets `GROVE_ORG` empty, and declines with
   zero rows — the bundle must say so loudly, as `5.10.repos` does, never pass silent.
6. **[research] the meter file's shape (`{"orgs": {…}}`) holds across the role versions a grove
   runs.** the verify reads the FILE, as `machine_openhours_reconcile` does for the global meter,
   never the skill's prose. a shape it cannot read is ✋ malfunction, never ✔. to confirm: the
   role version hetzner's crew trees run.
7. **[answered] the crew seat** is the grove's non-`.ground` ssh alias (`git.grove.list`:
   `grove-x → camper@…`). the skill derives it from the forest, never hardcodes `camper`.
8. **[answered — director, S3] an ungranted declared org is a hard stop (✋)** that prints the
   exact grant command, never a 🌙.

## .what is awkward

- **a bundle whose apply changes no byte.** `configure.upsert` has no work; the bundle is a declared
  table plus a verify. `prove.cloud-tailscale-is-verify-only` is the precedent, but a reader may
  still expect `--mode apply` to fix it
- **the deadline is gone before the fix lands.** the hand grant above is the real unblock today;
  the pr is the next-grove fix
- **two org lists per grove** (`5.10.repos` clones, `5.26.commitorgs` ships) — honest, and a place
  where the two will drift unless the clamp walks both
- **the human guard is a tty test, and a duct pane is a tty.** the skill's own door refuses a
  clone; a grant typed down a duct by a clone would still pass the box's guard. only the rule
  holds that line (case=3)
