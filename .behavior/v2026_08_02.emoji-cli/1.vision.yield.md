# 1.vision — emoji cli

## .the outcome world

### day in the life

vlad types a commit message. he wants the turtle.

```
$ git commit -m "feat(kitty): new tab keeps cwd :turt<TAB>
$ git commit -m "feat(kitty): new tab keeps cwd 🐢
```

one tab. the emoji lands inline, at the cursor, in the buffer he was already
typing. no popup opened, no window switched, no clipboard touched, no hand
moved to the mouse.

later he wants "that happy one" but cannot recall its name:

```
$ echo "ship it :happ<TAB>
                  ┌────────────────────────────┐
                  │ 😀  grinning face          │
                  │ 😃  grinning face big eyes │
                  │ 😄  grinning face smiling  │
                  │ 🙂  slightly smiling face  │
                  └────────────────────────────┘
```

arrow, enter, done. still inline. still in the same buffer.

### before / after

| | before | after |
|---|---|---|
| know the name | ctrl+shift+u, type, enter | `:turt` + tab |
| know a vibe word | open browser, search "happy emoji", copy, paste | `:happ` + tab |
| want to browse | scroll a web page | `emoji` → fzf |
| custom set (🐢 🌊 ✋ 💥) | remember + retype, or copy from an old file | `:turt` `:wave` `:stop` `:boom` |
| "happy" finds 😀 | ❌ kitty is names-only | ✅ CLDR keywords |
| 🚀 reachable in the picker | ❌ not in kitty's 80-char emoji tab | ✅ |

### the aha

**the emoji arrives without leave of the line you were typing.**

every prior option is a *detour* — a picker to open, a page to visit, a
clipboard to route through. the detour costs more than the emoji is worth, so
in practice the emoji goes untyped. remove the detour and emoji become
free-to-use rather than a small chore.

second aha, smaller but real: `:turt` already works. CLDR carries `turtle`,
`tada`, `lit`, `boom`, `stop` — the slang register, not just the formal names.
no hand-curated list required.

## .user experience

### usecases

| # | goal | invocation | result |
|---|------|-----------|--------|
| 1 | insert a known emoji inline | `:turt<TAB>` | 🐢 replaces `:turt` in the buffer |
| 2 | insert one recalled only by vibe | `:happ<TAB>` → pick | 😀 replaces `:happ` |
| 3 | browse when clueless | `emoji` | fzf over all 1,536; selection to stdout + clipboard |
| 4 | one-shot lookup to stdout | `emoji rocket` | prints 🚀 (pipe-able) |

### the contract

```sh
emoji                        # fzf picker over the full index -> stdout + clipboard
emoji <query>                # best match -> stdout (silent, pipe-safe)
emoji <query> --pick         # force the picker even on a unique hit
```

that is the whole v1 surface. **no alias subcommands** — see below.

### why no alias file (scope cut, evidence-driven)

the wish asked for custom aliases and named the set: 🐢 🌊 ✋ 💥. each was
checked against CLDR before we build:

| char | CLDR keywords | reachable? |
|------|---------------|-----------|
| 🐢 | animal, terrapin, tortoise, **turtle** | ✅ `:turt` |
| ✋ | 5, five, hand, high, raised, **stop** | ✅ `:stop` |
| 💥 | **boom**, bomb, collide, collision, comic, explode | ✅ `:boom` |
| 🌊 | nature, ocean, **surf**, surfer, water, **wave** | ✅ `:wave` |
| 🎉 | awesome, birthday, celebrate, hooray, party, **tada** | ✅ `:tada` |
| 🔥 | af, burn, **fire**, flame, hot, **lit** | ✅ `:fire` |

**6 for 6, zero custom entries.** CLDR even carries the slang register
(`tada`, `lit`, `boom`, `stop`) that the wish feared it would lack.

so the alias *subsystem* is unjustified. what survives is a deferred escape
hatch for genuine gaps (`:rhx`, `:me`) — an optional extra TSV concatenated
ahead of the index, ~20 lines, added when a real miss shows up. not v1.

inline completion is a **zsh widget**, not a command — it never appears as
text you type. bound to `TAB`, active only when the word under the cursor
**matches** `^:[a-z0-9_+-]+$` — that is, *begins* with the colon. every other
tab falls through to normal completion, untouched.

⚠️ **the word-start anchor carries the load.** measured over 20,499 real
commands: 66 contain a colon, **0 begin a word with one** (see §open questions).
`test:unit`, `git@github.com:ehmpathy`, `arn:aws:s3`, `scp host:path` are all
safe *because* the colon sits mid-word. relax `match` to `contains` and every
one of those 66 becomes a live collision.

### timeline of a single insert

```
keystroke ':'          -> inert, just a colon in the buffer
keystrokes 'turt'      -> inert
TAB                    -> widget wakes
                          ├─ regex the word under cursor        (~0 ms, in-shell)
                          ├─ grep the TSV for '^turt\t'         (one fork)
                          ├─ exactly one hit -> splice into LBUFFER
                          └─ redraw
total                     one fork; measured 8.8 ms, felt as instant
```

on multiple hits the widget hands off to fzf; on zero hits it falls through to
normal tab completion, so a stray `:` never eats your tab.

### the mental model

> "it's like `:shortcodes:` on github or slack — but in my actual shell,
> and i can add my own."

that analogy is the whole onboarding. `:` + word + tab is a gesture every
developer already owns from slack/github/discord. we borrow the muscle memory
and change none of it.

| they say | we say |
|----------|--------|
| shortcode | keyword |
| "the emoji list" | the index (generated TSV) |
| "it autocompletes" | the ZLE widget bound to TAB |

## .evaluation

### against the goals

| goal | verdict |
|------|---------|
| tab autocomplete inline | ✅ the core; ZLE widget splices into `LBUFFER` |
| custom aliases, no rebuild | ➖ deferred — CLDR already covers the named set 6/6 |
| keyword search ("happy") | ✅ CLDR — **verified**, 😀 carries `happy` |
| fast | ✅ **measured at 8.8 ms/lookup**, ~11x under the 30 ms budget |
| kitty + tmux + zsh | ✅ pure zsh + coreutils; kitty/tmux irrelevant to the inline path |
| repo as source of truth | ✅ `install_emoji` in a `pt*.sh`, TSV generated on install |

### pros

- **no runtime dependency in the hot path** — the widget is zsh builtins plus
  one `grep`. no python, no node, no daemon.
- **degrades to plain fzf** — if the widget breaks, `emoji` still works
- **the index is a flat file** — inspectable, greppable, diffable, hand-fixable
- **no curation debt** — CLDR ships the slang, so there is no personal list to
  maintain, sync, or lose

### cons

- **zsh only.** the widget does not exist in bash. `emoji` the command works
  everywhere, but the marquee feature is shell-specific. acceptable — vlad
  lives in zsh.
- ~~**`:` collides.**~~ measured at **0 false triggers in 20,499 real commands**
  under the word-start anchor. `scp host:path` and `arn:aws:s3` keep their colon
  mid-word, so they never fire. fall-through covers the residual.
- **a TAB rebind is invasive.** tab is sacred. must chain to the prior widget
  exactly, not merely to the default.
- **one more generated artifact** to keep fresh (CLDR ships new emoji yearly)

### edgecases → pit of success

| edgecase | behavior |
|----------|----------|
| `:` with zero matches | fall through to normal completion — tab still works |
| `:` mid-word (`scp h:/x`, `test:unit`, `arn:aws:s3`) | never triggers — the word does not *begin* with `:`. measured 0/20,499 |
| index absent / not yet built | widget silently falls through; `emoji` prints a build hint |
| ambiguous prefix | fzf picker, best match preselected |
| ambiguity ordered badly | **design decision:** prefix hits rank ahead of partial hits; ties by CLDR order. falsifiable in use, revisit if it feels wrong |
| **trigger char is in the index** | `:colon` would insert a literal `:` — resolved by the emoji-only filter (see groundwork) |
| **invisible combiner insert** | the 5 skin-tone modifiers render as an empty cell alone, reads as silent failure — resolved by the same filter |
| terminal cannot render the glyph | out of scope — kitty renders emoji |
| non-zsh shell | widget absent; `emoji` command still available |
| tab pressed with empty buffer | no `:` → falls through |

the through-line: **a false trigger costs exactly one normal tab.** that is
what makes a TAB rebind tolerable.

## .groundwork

### external research

**CLDR annotations — VERIFIED, live-fetched this session.**

```sh
curl -s https://raw.githubusercontent.com/unicode-org/cldr-json/main/\
cldr-json/cldr-annotations-full/annotations/en/annotations.json \
  | jq '{count: (.annotations.annotations|length), grin: ...}'
```

```json
{ "count": 1965,
  "grin":   { "default": ["cheerful","cheery","face","grin","grinning",
                          "happy","laugh","nice","smile","smiling","teeth"],
              "tts": ["grinning face"] },
  "rocket": { "default": ["launch","rocket","rockets","space","travel"],
              "tts": ["rocket"] } }
```

- HTTP 200, shape is
  `.annotations.annotations["<char>"] = { default: [...], tts: [...] }`
- **`happy` → 😀 confirmed.** the central premise of the wish holds.
- **`launch` → 🚀 confirmed.** the kitty gap is real and this closes it.

**⚠️ CLDR annotates *characters*, not emoji.** the raw TSV was built and its
head read, rather than trusted from a `jq length`:

```
{	open curly bracket	brace bracket curly open
🏻	light skin tone	1–2 light skin tone type
,	comma	comma
:	colon	colon
!	exclamation mark	bang exclamation mark point
```

| class | count |
|-------|-------|
| annotated entries | 1,965 |
| **actual emoji** | **1,536** |
| not emoji | ~429 |
| — ascii punctuation | 29 |
| — invisible skin-tone modifiers | 5 |

two of those are real defects, not trivia: **`:` is in the index** (the tool's
own trigger, so `:colon`+TAB inserts a colon that looks like what you typed),
and the **skin-tone modifiers are invisible alone** (an empty cell reads as a
silent failure — `rule.forbid.surprises`).

**required generator step:** intersect CLDR keys against the authoritative
emoji list at `unicode.org/Public/emoji/latest/emoji-test.txt`, fully-qualified
rows only. that file *defines* "is an emoji", so the filter is principled rather
than a hand-rolled codepoint range.

that URL was **checked, not assumed** — `curl -sI` returns HTTP 200,
`last-modified: 2025-08-16`, `content-type: text/plain`. the `/latest/` alias
resolves, so the generator needs no version pin.

**stale figure:** the "~438 KB" JSON size predates this filter and is unmeasured
here anyway. immaterial — we ship the derived, filtered TSV.

**kitty's picker — SECONDHAND, not confirmed by me.** a research subagent read
`gen/wcwidth.py`, `tools/unicode_names/query.go` and
`kitty/options/definition.py` via the GitHub API and reported: a names-only
index built from `UnicodeData.txt`, zero `cldr` hits in the tree, and
`EMOTICONS_SET` hardcoded to `0x1f600..0x1f64f`. **I have not opened these
files.**

this claim is the entire premise — if kitty already did keyword search, the
wish mostly evaporates. it must be confirmed firsthand before execution, and
the cheap confirmation is empirical rather than source archaeology:

```sh
kitten unicode-input     # search 'happy' — does 😀 appear?
```

if 😀 appears, stop and rethink the wish.

**not yet verified:** the ~438 KB figure is from the research agent, unmeasured
here. immaterial — we ship the derived TSV, not the JSON.

## .assumptions & open questions

### assumptions we made

1. **`:` is the right trigger.** borrowed from slack/github. unvalidated.
2. ~~**one grep per tab is fast enough.**~~ — **measured, holds.** 8.8 ms/lookup
   (see below).
3. ~~**the dataset is 1,966 emoji.**~~ — **false, corrected.** 1,536 emoji among
   1,965 annotated characters; the filter is now a required generator step.
4. **english CLDR only.**

*(prefix-before-partial ordering was listed here as an assumption. it is not —
it is a stated design decision with a rationale, and it now lives in the
edgecase table where it belongs.)*

### open questions, triaged

each is tagged `[answered]` (resolved now), `[research]` (a command to run), or
`[wisher]` (only vlad knows). **only one is on vlad's desk.**

1. **[research] does kitty already do this?** — the load-critical one. the whole
   project rests on kitty's picker without keyword search, and that claim is
   secondhand (see §groundwork). settle it before we build:

   ```sh
   kitten unicode-input     # search 'happy' — does 😀 appear?
   ```

   **if 😀 appears, stop** — the wish mostly evaporates and we reconsider.
   gates stone 5. `[research]` rather than `[answered]` only because the picker
   is an interactive TUI and wants a real terminal.

2. **[answered] trigger char — `:` holds, measured against vlad's own history.**
   the fear was `scp host:path`, `arn:aws:s3`, `npm run test:unit`. so I counted,
   over 20,499 commands in `~/.zsh_history`:

   | probe | matches |
   |-------|---------|
   | `:` then a letter, anywhere in the line | 66 (0.32%) |
   | **words that *begin* with a bare `:`** | **0** |
   | bare `:` at word-start, any next char | **0** |

   the same regex with the colon removed returns 19,806 matches, so the pattern
   is live and the zero is real. and all 66 are colons **mid-word**:

   ```
   npm run provision:integration-test-db     # ~30 of the 66
   git@github.com:ehmpathy/sdk-config.git
   "arn:aws:s3:::'$BUCKET_NAME'"
   \:qa!                                     # 8 — vim muscle memory, already a typo
   ```

   **so the anchor is the whole answer.** the word under the cursor must
   **match** `^:[a-z0-9_+-]+$` — *begin* with the colon, not merely contain one.
   under that rule, 0 of 20,499 real commands false-trigger, `scp host:path`
   included. ⚠️ this anchor carries the load: relax `match` to `contains` and the
   66 become live collisions.

3. **[answered] the wish's own alias question.** you asked: shell aliases
   (`e`, `em`) vs emoji aliases. the CLDR check says **neither is
   load-critical** — your whole vibe set resolves from the index, 6/6. so shell
   aliases yes (one line, free), emoji alias file deferred until a real miss.
   object if you want it in v1 anyway.

4. **[answered] on a unique match: silent insert.** the action is reversible by
   one backspace, and a confirm prompt is precisely the detour this tool exists
   to remove. worst case for a wrong default is one keystroke.

5. **[answered] english CLDR only.** CLDR ships per-locale files at the same URL
   shape, so another locale is a generator path change, not a redesign. no
   decision foreclosed.

6. **[wisher] nvim too?** the wish named
   kitty+tmux+zsh, so I scoped to a zsh ZLE widget. but this repo carries a
   large nvim config and several nvim briefs; you live there too, and much of
   the text that wants emoji (commit bodies, briefs, markdown) gets typed in
   nvim, not at the prompt. the cheap answer: `emoji <query>` already prints to
   stdout, so an nvim mapping that prompts and inserts is a handful of lines
   against the same index — no new subsystem, same reuse logic that cut the
   alias file. say the word and it goes in; otherwise v1 is shell-only and the
   data path stays well-known so it can be added later.

   this is the **only** question that needs you. the rest are settled above.

### measured, no longer assumed

**lookup latency — 8.8 ms.** on the full *unfiltered* TSV, including a `wc`
fork the real widget never pays:

```sh
$ time (for i in {1..50}; do grep -m1 -i 'happy' emoji.tsv | wc -c; done)
0.09s user 0.31s system 91% cpu 0.441 total     # = 8.8 ms / lookup
```

budget was 30 ms; perceptual threshold ~100 ms. ~11x under, and the filtered
index is smaller still.

**what this deletes:** the fallback to preload the index into a zsh associative
array at shell start. it would trade shell-startup time and per-shell memory to
avoid a fork that costs 8.8 ms. struck from the design.

### still to measure

- widget latency end-to-end in the live shell (grep is the dominant term, but
  the ZLE redraw is untimed)
- whether a 1,536-line fzf feels instant (should, but confirm)

## .what is awkward

**1. TAB is sacred, and we are rebinding it.**
the honest discomfort. tab is the most reflexively-used key in a shell, and a
subtly wrong chain-through will feel like the shell is broken with no obvious
culprit. mitigated by fall-through, but the risk is real and the
implementation must chain to *whatever was bound before*, not to a guessed
default.

**the fallback, held in reserve:** bind a free key (alt+e / ^G) to a widget
that opens fzf and inserts at the cursor. that drops the TAB rebind *and* the
`:` collisions, keeps the inline insert, and costs only the type-then-complete
flow. the index and lookup are identical, so the swap is cheap.

trigger to take it: if the chain-through proves fragile in execution. (the
second trigger — `:` false-positives — is retired; measured at 0/20,499.) vlad
asked for tab explicitly and twice, so tab is the default, but this option stays
on the table rather than a late rediscovery.

**2. ~~`:` is a genuinely poor trigger in a shell.~~ — measured, resolved.**
this entry called `:` "the design's weakest joint" and asked for a second
opinion. it needed a grep, not an opinion. over 20,499 commands of real history:
66 contain a colon, **0 begin a word with one**. `scp host:path` and friends are
safe under the word-start anchor because their colon is mid-word. the joint was
not weak; I had simply never looked. see §open questions for the numbers.

consequence: the alt+e / ^G fallback below now has **one** trigger condition (a
fragile TAB chain-through) rather than two.

**3. ~~two sources of truth for one lookup.~~ — resolved by scope cut.**
this was the alias-file precedence problem. the 6/6 CLDR check removed the
alias file from v1, and the awkwardness left with it. it returns only if the
escape hatch ships, and then precedence must be crisp (custom wins).

**4. the wish says "wherever my cursor already is" — we deliver "wherever your
cursor is *in zsh*."**
that is narrower than the words. in nvim, in a browser textarea, in slack
itself, this does no work. i think shell-first is right, and the wish's own
constraints say kitty+tmux+zsh — but the gap between the aspiration and the
delivery should be named now, not discovered later.

**5. ~~"fast" is asserted, not measured.~~ — resolved.**
timed at 8.8 ms/lookup against the real data, ~11x under budget. the preload
fallback this entry worried about is deleted, since it would pay shell-startup
cost to save a fork that is already cheap. residual: the ZLE redraw itself is
untimed, but grep dominates and grep is not the problem.

**6. the head of the data file was read only after the vision was written.**
the count in this document was wrong for its first two drafts because I read a
`jq length` and not the rows. the correction (1,536 not 1,966, plus a required
emoji-only filter) is in place — but the discomfort worth naming is that a
derived number passed for comprehension, and the same class of lapse produced
the secondhand kitty claim in §groundwork. print the thing before you cite it.
