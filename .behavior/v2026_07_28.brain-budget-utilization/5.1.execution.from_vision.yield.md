# 5.1 execution — brain-budget-utilization

three `brains.auth.*` commands in `src/brains.auth.sh`, plus a snapshot suite that runs as
`rhx brains.auth.test`.

## what shipped

| command | what it does |
|---------|--------------|
| `brains.auth.set [--reach <email>]` | signs in, asks the token who it is, files it under that name |
| `brains.auth.usage [--reach <email>\|@all] [--json]` | reads budget per account, renders one block each |
| `brains.auth.use [--reach <email>]` | swaps the global claude login; no args reports who is signed in |

an account is named by its **reach** — the email the oauth token reports. no handle is invented,
so no handle can disagree with the token or be typed wrong (the vision carries the amendment
that retired the earlier `--sub <slug>` scheme).

### the shape of a read

```
🧠 claude budget
   ├─ casey@ahction.com: ✋ refresh token dead (run: brains.auth.set)
   ├─ vlad@ahbode.com  ← signed in
   │  ├─ session  ██░░░░░░░░  24% used  ·  resets at mon 13:20, in 2h41m
   │  └─ week     ████░░░░░░  48% used  ·  resets at tue 12:00, in 25h21m
   └─
```

exit codes, for a cron or statusline that reads only `$?`: `0` at least one account read,
`1` all failed and at least one failure is ours, `2` all failed and every failure is the
caller's to fix.

## the invariants this code exists to hold

these are the reasons the implementation is shaped the way it is. each has a hazard brief and a
clamp in the suite.

| invariant | why | where |
|-----------|-----|-------|
| **one holder per token** | an oauth refresh rotates server-side, so two holders of one token means whichever reads next kills the other. the ACTIVE account is read from `~/.claude` with zero refreshes; parked accounts live in the keyrack | `hazard.claude-oauth-one-holder-per-token.md` |
| **install-then-park** | park-then-install leaves the same token in both places between the steps — the two-holder state, which persists indefinitely if the install fails | `_brains_auth_park_file` |
| **a rotated token is always filed** | the refresh rotates before the install runs, so an install failure that returns without a write-back drops the only live value and strands the account | `hazard.claude-oauth-refresh-rotation.md` |
| **identity is derived, never remembered** | a swap made behind our back (a plain `/login`) is picked up correctly because the live token is re-asked on every call | `_brains_auth_active_reach` |
| **an unproven identity may label, never authorize** | `~/.claude.json` can lag the live token; a stale name would misfile one account and orphan another | `_brains_auth_identity_is_actionable` |
| **no secret in argv** | `/proc/<pid>/cmdline` is world-readable; tokens ride stdin or a scoped env assignment | `hazard.secrets-in-argv.md` |
| **the pinned UA matters** | an unrecognized `User-Agent` buckets the request into a rate-limited path that 429s persistently | `hazard.claude-oauth-user-agent-429.md` |

## where it lives

`src/brains.auth.sh` — its own file, on the paved `src/X.sh` → `~/.bash_aliases.X.sh` pattern
that `src/ductwork.sh` and `src/termwork.sh` already use: sourced from the head of
`bash_aliases.sh`, copied by `sync.devenv.bashaliases`.

it was inline until this round, and the argument that finally moved it was **hermeticity**,
not hygiene. the suite and both skill proxies `source` this namespace under `set -uo pipefail`.
while it sat inline, that meant a source of the whole 4,300-line monolith — so an unset
variable or a parse defect in ANY unrelated alias would hard-abort the clamp on the riskiest
credential code in the repo, for a cause with no relation to brains.auth. the surface is now
1,768 self-contained lines. the same move is what let the CI job below run a bare `bash`.

⚠️ **`teesafe` strips every newline at the tail of what it is handed** — write and append
alike, and a newline-only payload becomes empty. the extraction hit that twice, and it is the
exact shape of `hazard.bash-aliases-parse-silently.md`: a file whose last line glues to
whatever follows. both files were repaired with an `# eof-guard` sentinel that `Edit` then
removed, and both were verified byte-wise (`tail -c | cat -A`). anyone who rebuilds a
`src/*.sh` file with `teesafe` owes the same check.

### the clamps were proven to bite

per `rule.require.clamp-edge-cases`, a clamp never seen red is a guess. three deliberate
regressions, each reverted after:

| regression | what went red |
|------------|---------------|
| neutered the `.bak` copy | `install.bak-holds-prior` — got empty |
| dropped one value guard | `guard.usage.reach-without-value` — **exit 124**, `timeout` killed the real infinite spin |
| mis-filed one severity | **4 cases at once** — hint, tree, severity table, and the exit code moved together |
| trapped `INT` alone again | **4 cases at once** — the three signals plus the arm/disarm agreement |
| classified keyrack by its stderr prose | `gettoken.exit2-is-absent` (2→1) + `gettoken.absent-stays-quiet` |
| dropped the bootstrap value guard | **both** proxy guards — **exit 124** twice, two real spins |
| made the `--sub` notice unconditional | **9 cases** — `deprecation.reach-is-quiet` plus every help/render snapshot it leaked into |
| removed the `--sub` notice entirely | `deprecation.sub-says-so` — the silent-alias variant |
| flipped the reach precedence (`[[ -z "$reach" ]]`) | `set.token-identity-outranks-flag` — filed under `wrong@example.com` |
| removed the `@all` union | `union.active-joins-all` — the live account **silently vanished**, no error |
| removed the compare-and-swap | **5 cases** — chiefly `cas.changed-refuses-install`: *INSTALLED ANYWAY — a token was destroyed* |
| dropped the value guard from the shared bootstrap | **3 × exit 124** — both proxies **and the suite itself** spun forever |
| removed `no_subscriptions` from the severity table | `coldstart.no-subscriptions.exit` — a documented **exit 2 became a 1** |
| flipped the keyrack owner constant | `hints.every-error-code` — proving all five call sites read one source |
| restored `use`'s drifted unknown-arg line | `unknownarg.use-matches-set` — the exact 19-round drift, named |
| added a region banner with no map entry | `sectionmap.matches-the-banners` — named the orphan `§` |
| appended one line after curl in the call leaf | `callleaf.usage-passes-curl-rc` — **a dead network read as `0`** |
| routed the bearer through curl's argv | `callleaf.usage-keeps-token-off-argv` — *LEAKED to argv* |
| removed the strand guard | **3 cases** — chiefly *INSTALLED ANYWAY — a token was destroyed* |
| widened the strand guard to any `.bak` | `strand.redundant-bak-still-installs` — the guard bricked the command |
| restored `use`'s hand-rolled shape verdict | **3 cases** — an api key sent the human to re-auth a subscription |

four of these deserve a word.

the **strand** pair is the sharpest lesson of the round, because the two regressions fail in
opposite directions and only both clamps together hold the guard in its narrow lane: drop it
and a swap silently destroys an account's last token; widen it and every later swap refuses
behind a `.bak` that guards no token at all. the defect it fixes was worse than its nitpick
grade suggested — the park-failure message said "rerun to file it", and that rerun reached the
`cp` first, parked the wrong account, and clobbered the stranded one. **the advertised cure was
the disease.**

the **call-leaf** pair earns its place for the same reason at a smaller scale: an extraction
made to satisfy a decompose-for-recompose nitpick could have quietly broken two guarantees no
other case watched — that curl's exit code survives the split (a dead network would then read
as a 200 with an empty body) and that the bearer stays out of `/proc/<pid>/cmdline`.

two more deserve a word. the union regression is the shape that worries me most in this
whole feature — it does not error, it just renders one fewer row, so the human reads "that
account has no budget stored" and re-auths a token that was fine. and the bootstrap one is
the leverage argument made concrete: **one** edit, **three** hung commands, one of them the
suite whose whole job is to report the hang.

### ⚠️ the test suite clobbered the human's live claude config — fixed 2026-08-31

the worst defect this feature shipped was in the **test file**, and it survived all 14 review
rounds. `brains.auth.test.sh` writes fixtures through two path variables that
`bash_aliases.sh` defaults to real dotfiles. the two redirects sat 270 lines apart, and a
profile-sync section added between them wrote its fixtures to `$HOME`:

```sh
:436   printf 'not json at all' > "$_BRAINS_AUTH_LIVE_PROFILE"   # ⚠️ the human's real ~/.claude.json
```

**every `rhx brains.auth.test` run overwrote a 400 KB live config**, first with a ~90-byte
fixture and then with that literal string. it hid because claude code rewrites that file from
memory on its next change, so a live session repaired it within seconds — and because each case
asserted on the fixture it had just written, so the suite passed either way.

the human found it, and asked whether some defect wrote `not a json` into their settings.

**the fix:** both redirects co-located above every case, then **verified** by a loop that halts
the run if either path escapes the temp dir. a comment had claimed this invariant since the
first draft; a comment cannot fail a run, and this can.

**proven:** point the profile back at `$HOME` → the run halts before the first write. real files
byte-identical either side of a full run (401679 / 471). lesson externalized to
`hazard.test-fixtures-leak-to-real-dotfiles.md`.

**the transferable lesson:** both this and the `bash_aliases` parse defect were invisible in a
diff and obvious in a run. a suite that writes through a variable with a production default
needs its redirect **verified**, and one line — `wc -c` the real file either side of the suite —
is a complete leak detector that needs no knowledge of what the cases do.

### the later rounds (96 cases)

| added | what it clamps |
|-------|----------------|
| swap sequence | mint → install → park-file → sync, hermetic via a mint seam; both recovery narratives |
| `.bak` lifecycle | shredded on a park success, KEPT on a park failure — a secret at rest either way it breaks |
| `use` exit codes | a dead token exits `2` (constraint), a network failure `1` — a caller can branch on `$?` |
| error-node writer | eleven emit sites through one `jq --arg` leaf; a quote can no longer make a failure render as healthy |
| leak guard | the redirect verified, not merely written |
| sign-in state read | three causes that once flattened into one "empty" — no file, unparseable, parsed-but-bare — each with its own exit code and its own hint |
| hint provenance | the swap's remediation must come FROM the shared table; a second copy cannot satisfy the clamp |
| keyrack split | a keyrack that is LOCKED is ours to fix (exit 1, "unlock it"); a key never STORED is the caller's (exit 2, "sign in"). one node once served both, with the sign-in hint |
| `set` vs `use` agreement | both derive the mint-failure exit code from the shared table, so two commands can no longer give opposite answers about one fault |
| the rotation race | three narratives — a raced token recovers, a dead one stays dead, a retry that also fails still surfaces. catches BOTH an absent retry and an unconditional one |

## ⚠️ one blocker remains, and only the human can clear it

the 82 snapshot baselines and the test harness are **untracked** — not `.gitignore`d, just never
added to the index. so a fresh checkout cannot pass the suite (every `_snap` finds no baseline
and fails), and a reviewer cannot see the pinned output in the diff. two reviewers graded this a
blocker; both were right.

the add is gated on a permission a mechanic does not hold:

```sh
git.commit.uses allow --global
rhx git.stage.add 'src/brains.auth.sh' \
                  '.agent/repo=.this/role=any/skills/brains.auth.bootstrap.sh' \
                  '.agent/repo=.this/role=any/skills/brains.auth.use.sh' \
                  '.agent/repo=.this/role=any/skills/brains.auth.test.sh' \
                  '.agent/repo=.this/role=any/skills/brains.auth.test.snap' \
                  '.github/workflows/test.brains.auth.yml'
```

⚠️ **and one file to take back OUT of the index**: `.temp/ba.trace` is a scratch capture of
suite output, staged at some point before `.temp/` was gitignored — and an ignore rule does not
reach a path already in the index, so it would ship. it holds no secret (the suite is hermetic
and prints no token), but it is noise in a credential-code diff, which is the worst place for a
reviewer's attention to be spent:

```sh
git rm --cached .temp/ba.trace   # leaves the file on disk; only drops it from the index
```

  rotated token back only AFTER its own mint returns, so that single read can land in the gap,
  see the old value, conclude "no one raced me", and condemn a live account to a browser
  re-auth. the re-read is now polled, bounded, so the loser outlasts the write-back. still NO
  lock, and for the unchanged reason: a stale lockfile wedges every later read of that account,
  which trades a rare wrong message for a permanently dead command. the poll cannot wedge — it
  is bounded by construction and runs only on a path already about to fail, so a healthy read
  pays none of it. the clamp reproduces the exact four-step timeline.

## ⚠️ the one endpoint everything rests on

the whole read path is one undocumented endpoint, and the vision's promised TUI-snapshot
fallback was never built. that was true before this round and went unlisted here, which was
the gap — an accepted risk that is not written down is indistinguishable from an overlooked
one. it is now `hazard.claude-usage-endpoint-is-undocumented.md`: the failure signature, the
one thing to rule out first (a UA drift 429s and *looks* like a retirement), and the three
moves open if it dies. the risk is unchanged; only its findability is.
