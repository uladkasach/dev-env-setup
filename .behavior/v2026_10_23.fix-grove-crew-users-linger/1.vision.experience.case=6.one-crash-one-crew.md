# case=6 — one crash costs one crew, and leaves a core

## .narrative

a storm of crew-verb clients hits crew A's server, the trigger load the wish measured, and it
segfaults. the crew owner at the laptop sees crew A go quiet while B works on, revives A, and
A's new server runs the pinned build. the diagnoser opens A's core with `coredumpctl`, rather
than a lone kernel log line.

## .timeline

```
[t0] given crews A and B, each on its own `-L` server (nheuron crewwork)
[t1] when  a storm of clients hits crew A's server and it segfaults
[t2] then  crew B's seats still answer `duct.read`
[t3] then  `coredumpctl list tmux` shows A's core
[t4] when  the crew owner revives crew A
[t5] then  A's new server answers, on its own socket, at 3.5a
[t6] when  the diagnoser runs `coredumpctl info <pid>`
[t7] then  the stack names the fault site (symbols permit)
```

fail-safe: contained (one crew of N), loud (a core, not a silent loss), and the fix is the revive
the crew owner already knows.
