# case=13 — a conf that does not parse installs no plugin

## .narrative

tpm learns its plugin list from a tmux server that has loaded the conf. the apply starts an
isolated server (`-L grove_tpm`) for that read. when `~/.tmux.conf` does not parse, the server
still STARTS: tmux drops the whole file, so the server holds no option and no `@plugin`. tpm,
handed that server, reads an empty list and reports success with no plugin fetched. that silent
under-install is the trap: the box looks converged and runs on tmux defaults.

a started server therefore proves no parse. the apply asks `source-file -n`, which parses without
a run, before it trusts tpm, and ✋s with tmux's own parse error as the cause.

```
[t4] then  • <plugin> already at the declared commit, per pinned plugin
```

fail-safe: tpm's success is never read as an install; the bundle stays red until the conf parses.
`prove.tmux-configure-refuses-an-unpinned-plugin` holds it twice: arm B asks a real tmux build,
on a fixture socket, whether it starts on a bad conf (it does, with no `@plugin`) and whether
`source-file -n` refuses it (it does); arm C8 snaps [t2] and asserts tpm never ran.
`prove.tmux-plugins-converge-past-a-whole-tpm` asserts the [t4] phrase for tmux-resurrect.
