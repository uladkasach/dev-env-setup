# case=8 — ground meets a failed build

## .narrative

ground runs the apply. the sha matches, but a build dep fails to install, or `make` fails. ground
sees a ✋ that names the step and the log path; the prior tmux is still on PATH, so every duct to
the box still works while ground reads the log.

## .timeline

```
[t0] given any box, with a prior tmux on PATH
[t1] when  ground applies 2.8.tmux and the build fails
[t2] then  ground reads:
           ✋ tmux 3.5a did not build (configure | make)
              ⇒ the prior tmux is untouched; a duct still reaches this box
              read why: <the build log path>
[t3] then  no file under /usr/local/bin changed
```

the install writes a temp path and renames only on success, so a failure cannot leave a
partial binary.
