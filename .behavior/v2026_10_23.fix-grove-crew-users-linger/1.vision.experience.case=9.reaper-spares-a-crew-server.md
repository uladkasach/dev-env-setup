# case=9 — a crew owner's two-day-old crew survives the reaper

## .narrative

the crew owner booted crew A two days ago and has worked with it since. each hour the box's
abandoned-process reaper ticks; she never sees it. crew A's server was born in a scope of its
own, so to the reaper it is that scope's oldest process and it is spared — her crew answers as
it did yesterday.

the counter-hazard she must never meet: a crew whose server was born from inside another crew's
pane. that server sits under an older process in a borrowed cgroup, so the reaper's rules all
match, and a day after its boot she would find the crew gone with no crash and no core — only a
reaper log line. the nheuron dispatch closes it: each crew's server is born in its own scope.
this repo's clamp proves both halves, so the hazard is caught before she can meet it.

## .timeline

```
[t0] given the crew owner's crew A, its server born in its own scope, 2 days old
[t1] when  the reaper ticks, hourly
[t2] then  the crew owner's `duct.read` on crew A answers as before — no gap
[t3] given (clamp) a crew server born inside another crew's pane, > 24h old
[t4] when  the reaper runs in plan mode
[t5] then  it names that server as one it would reap — the hazard is real, and the birth rule
           in the nheuron dispatch is owed
[t6] then  any real reap names the pid and command in the reaper log, so a reaped crew is never
           mistaken for a crash
```

fail-safe: the spare is by construction (own scope), and a kill is loud (the reaper log names it).
