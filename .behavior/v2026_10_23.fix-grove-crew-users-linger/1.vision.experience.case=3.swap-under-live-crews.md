# case=3 — the binary swaps under live crews (the densest walk)

## .narrative

a grove still on 3.2a hosts three crews. ground applies; the crew owner watches from the laptop.
the new binary lands by rename, so each live 3.2a server keeps its inode and no crew drops —
the crew owner sees no gap in any crew. new servers from then on run 3.5a.

what happens if one of the old servers later crashes is case 6; what a new client meets on an
old server is case 10.

## .timeline

```
[t0] given a grove on apt 3.2a, crews A, B, C up; the crew owner reads each crew
[t1] when  ground applies 2.8.tmux
[t2] then  3.5a is built, written to a temp path, and renamed over /usr/local/bin/tmux
[t3] then  crews A, B, C still answer `duct.read` — no server was killed
[t4] when  a new crew D is booted
[t5] then  crew D's server reports 3.5a
```

⚠️ [t2]–[t3] rest on install-by-rename (the yield's relayed block).
