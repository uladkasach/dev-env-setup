# case=12 — a pane keeps its spawn-time TERM

## .narrative

a live tmux server started before the conf reached it. it holds a `default-terminal` the conf
does not declare (`screen`, an 8-colour entry), and every pane it spawned inherited that TERM.
the app inside each pane reads TERM once, concludes 8 colours, and emits only 8-colour codes —
a clamp at the source, which no client feature can undo. a read of the conf alone sees a correct
file and reports ✔, so the verify reads the server and each pane instead. an apply sets the
server right, yet a pane that already exists keeps its old copy until it exits — so the fix names
the act that reaches a pane: a new pane where a human sits, `rhx duct.reboot` for a grove's duct.

## .timeline

```
[t0] given a live server whose default-terminal is `screen`, and the conf declares `tmux-256color`
[t1] when  any seat runs `rhx grove.provision --what 2.8.tmux --mode plan`
[t2] then  ✋ ConstraintError: 1 live server(s) hold a default-terminal the conf does NOT declare
             fix: rhx grove.provision --what 2.8.tmux --mode apply
             ⚠️ a pane that ALREADY exists keeps its spawn-time TERM
[t3] given the server is right, and 1 of 2 panes spawned before the conf reached it
[t4] then  ✋ ConstraintError: 1 of 2 live pane(s) hold a TERM the conf does NOT declare
             ⇒ no re-apply repairs a pane
             fix, per affected pane: a new pane (prefix c / prefix %), or
               rhx duct.reboot --on 'duct://<grove>/<tree>/<role>'
[t5] when  the pane is replaced
[t6] then  • all N live pane(s) spawned with TERM=tmux-256color ✔
```

fail-safe: the verify grades the server and each pane, never the conf alone, so a clamped pane
is red even on a box whose conf is current. A and E of
`prove.tmux-verify-names-a-server-behind-the-pin` snap [t2] and [t4]; C of the same play snaps
the [t6] row (`• all 1 live pane(s) spawned with TERM=tmux-256color ✔`).
