# case=11 — a reboot keeps the crash collector

## .narrative

a box ships apport with `enabled=1`. the ground seat applies the bundle: systemd-coredump lands,
and `sysctl --system` points `core_pattern` at it. a plan right then reads ✔. but apport's init
runs at every boot after `systemd-sysctl`, and it writes its own pipe into `core_pattern` with no
condition. so the first crash after a reboot goes to apport, which skips an unpackaged
`/usr/local/bin/tmux` — no core, the wish's own pain back again. the apply therefore turns
apport's boot claim off (`enabled=0`, in place) and reads the switch back. it never stops the
service: apport's stop resets the live pattern to `core`. the verify reads both facts — the pipe
now, and whether apport will take it back at boot — so a box that would lose its collector at the
next boot is red today, not after the crash it was meant to catch.

## .timeline

```
[t0] given a box with apport installed and `enabled=1` in /etc/default/apport
[t1] when  the ground seat runs `sudo -v && rhx grove.provision --what 1.6.8.coredump --mode apply`
[t2] then  • apport's boot claim on core_pattern is off (enabled=0)
           • systemd-coredump collects each core, across a boot; read them with coredumpctl
[t3] when  the box reboots, then a tmux server segfaults
[t4] then  `coredumpctl list tmux` names the crash
[t5] given instead a seat with no root that only plans, on the same box before the apply
[t6] then  ✋ ConstraintError: the kernel pipes each core to systemd-coredump now, and apport
             takes it back at the next boot
           fix: sudo -v && rhx grove.provision --what 1.6.8.coredump --mode apply
                (on a grove: run it on the ground seat, which holds sudo)
```

fail-safe: a switch that cannot be written is a ✋ that names the next boot (U9), never a ✔ on a
pattern that holds only until the box restarts. [t3]–[t4] are unexercised on a real reboot; the
clamp is the boot claim itself, read from the init's own switch (V6, V7, U7–U9).
