# case 3 — a decline is visible, never folded into a pass

## narrative

the mechanic runs `--all` on a laptop where one play's subject is absent. they watch the tree print
`🌙 prove.b-declines — declined or timed out`, then the tally, then a `🌙` line on stderr that tells
them the decline proved no claim. the exit is 2, so their shell prompt shows the run did not pass.
later the director reads the tree's newest log. its last line is
`└─ 1 passed · 1 declined · 0 failed`: three counts, never two, so the director can see a decline
sat in the run rather than meet a bare "passed". how a `0 failed` with a decline grades is the
reader's own rule; the file withholds no count it needs.
