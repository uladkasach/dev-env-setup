# experience dimensions — play.run --all leaves its verdict in the tree

## actors

each cell has ONE actor. a run and a read are two experiences, so they are two actors.

| actor | encounter |
|---|---|
| mechanic | runs `rhx play.run --all`, reads the terminal |
| director | reads the tree's newest `what=all/*.stdout.log` (by mtime), never the terminal |
| clamp | `prove.play-run-all-reads-three-verdicts` drives the runner in temp fixture repos |
| ci | `test.play.run.yml` runs the clamp on a fresh runner, per pr that touches the runner or its clamp |

## the run matrix (mechanic + director)

five axes, each a closed set of exclusive values:

| axis | values | n |
|---|---|---|
| O · suite outcome | `empty` (no tracked play) · `all-pass` · `decline-no-fail` · `fail-no-decline` · `decline-and-fail` | 5 |
| L · `what=all/` dir state | `absent` · `present-writable` · `present-unwritable` | 3 |
| S · stamp claim | `free` · `taken-then-free` (a same-second collision, cleared within the try bound) · `taken-past-bound` (every try collides) | 3 |
| H · history in the dir | `none` · `prior-flat` (an older `*.stdout.log`) · `prior-legacy` (an older `*/summary.log`) | 3 |
| R · when the director reads | `after-run` · `mid-run` | 2 |

product: 5 × 3 × 3 × 3 × 2 = **270 cells**. `case=_.md` verdicts every one, by slice.

### why the axes are orthogonal, and where they are not

each axis is an independent fact a box can hold: what the index tracks (O), the state of the log
dir (L), what other runs claimed (S), what older runs left (H), when a reader looks (R). no value of
one is defined by another. but the runner walks them as an **ordered pipeline** — O gates the run,
L gates the claim, S gates the log — so a value upstream can make a downstream value unreachable:

- H and S are meaningful only on `L = present-*`. the latent "log dir present" fact is exactly the
  complement of `L = absent`; it is folded into L rather than walked as its own axis
- an upstream halt leaves no in-flight window, so R = `mid-run` is reachable only where the runner
  reaches the log dir

those correlations are recorded as impossible cells (I1–I4), each with its reason, so the product
stays a closed decomposition: every cell has a coordinate, and the unreachable ones are named.

### the precondition upstream of the product

`.play/permanent/` absent (a checkout mid-move) halts at `play.run.sh:112-116` before O is read:
`✋ ConstraintError: no tracked play dir at …`, exit 2, no log. that is extant behavior, and the same
contract case 4 adds for a present-but-empty index. verdict: itemized, as `s0` in `case=_.md`.

- S counts the collisions a run meets, so "three or more runs in one second" is `taken-then-free`
  (cleared within the bound) or `taken-past-bound` (not cleared). the set is closed over any count
- O names a mixed run `decline-and-fail`, so case 2's suite has one coordinate

### the fault axes — each halts, so each value is one slice

execution found four more facts a box can hold. each has ONE healthy value; every other value
halts the run at a fixed point with one verdict, whatever the five axes above hold. so a fault
value does not multiply the product — it is one slice, upstream of the product (X, Y) or cut from
its log path (Z, W). the 270 cells are the `ok` row of all four.

| axis | values | halts | where |
|---|---|---|---|
| X · the index | `ok` · `untracked-on-disk` · `nested-tracked` · `nonascii-tracked` · `unreadable` | before O | upstream |
| V · `--within` | `ok` (whole seconds ≥ 1) · `invalid` (`0`, a word, a suffix) | before X | upstream |
| Y · the log root path | `ok` · `squatted` (a file holds the name) | before L | upstream |
| Z · the stamp claim, beyond a held name | `ok` · `dir-refused` (a dir it may write, not search) · `create-refused` (the dir won, the log name is too long) · `orphan-held` (a log with no dir holds each name) | at S | claim |
| W · a write mid-run | `ok` · `verdict-log-lost` · `play-dir-lost` · `killed` (a signal ends the run) | after the claim | log path |

- `nested-tracked` and `nonascii-tracked` are the non-halt values: a play one dir below the suite
  is outside it, and a tracked play with a non-ascii name is in it. found in execution, where a
  bare pathspec `*` listed the first, and git's quoted names read the second as untracked
- `orphan-held` is a collision, not a fault: each orphan reads as taken, so it folds into S =
  `taken-past-bound` when every try meets one
- concurrent peers (real runs at once, no seed) are S = `taken-then-free` reached by a live race
  rather than a seed; one coordinate, two ways to reach it

### the mode axis — the runner's other doors

the 270 cells are all M = `all`. the runner has four other doors, and none writes a verdict log,
so none multiplies the run matrix: each is one slice, its own row in `case=_` (f14–f17).

| axis | values | writes a verdict log | shares |
|---|---|---|---|
| M · the mode | `all` · `list` · `help` · `play` · `bad-args` (an unknown flag, or `--all` with `--play`) | `all` alone | `list` shares X (the index read); `play` shares V (`--within`) |

## the clamp matrix

| axis | values | n |
|---|---|---|
| C · play.run.sh under test | `changed` · `reverted-to-main` · `claim-check-then-write` · a guard off (create-fault arm · `rmdir` · append · per-play log · index) | 3 + guards |
| F · fixture repo | `mixed` · `declined` · `unproven` · `green` (a prior flat log and a legacy `summary.log`) · `empty` · `redafter` · `nested` · `untracked` · `stamps` · `shift` · `race` · `orphans` · `locked` · `unsearch` · `deep` · `truncated` · `killed` · `squat` · `playlock` · `badindex` · `unicode` | 21 |

the C × F product is not walked whole: a variant of C exists to redden ONE fault, so each is
verdicted on the fixtures it targets. `case=_.md` holds one row per fixture, with the C that
reddens it.

## feel is derived, not an axis

feel is a function of the coordinates, so it is not walked as a sixth axis:
happy ⟺ a stdout log is written AND O = `all-pass` AND R = `after-run`. every other reachable
run-matrix cell is sharp. for the clamp, happy ⟺ C = `changed` (the clamp is green).

## barred cells

the runner checks in a fixed order — empty index, then dir write, then stamp claim — so a cell past
an earlier halt cannot reach a later axis.

| # | cell | kind | why |
|---|---|---|---|
| I1 | L = `absent` × H ≠ `none` | impossible (nature) | a prior file needs the dir |
| I2 | L = `absent` × S ≠ `free` | impossible (nature) | a collision needs a file in the dir |
| I3 | L = `present-unwritable` × (S ≠ `free` or R = `mid-run`) | impossible (nature) | the write check fails before any claim, so no run is in flight to read |
| I4 | O = `empty` × (S ≠ `free` or R = `mid-run`) | impossible (nature) | the empty-index halt precedes any claim, so no run is in flight to read |
| N1 | O = `empty` × a reader meets a `0 · 0 · 0` log | forbidden (nurture) | the runner halts before any log (F4) |
| N2 | any written log whose last line is not the tally | forbidden (nurture) | the reader's one contract; the clamp asserts the literal last line |
| N3 | a same-second run overwrites a prior log | forbidden (nurture) | the noclobber claim refuses an extant name (F3) |

the same-second pair itself is NOT barred: it occurs, and the runner allocates around it
(S = `taken-then-free`, case 8). only the overwrite is barred.

the rows overlap (a cell can be both I1 and I2), so they are not summed. the impossible set is
their union, I1 ∪ I2 ∪ I3 ∪ I4 = 270 − 99 = **171 cells**; reachable: **99** (derivation in
`case=_.md`).
