# 1.vision — play.run --all leaves its verdict in the tree

## .the outcome world

a director reads one cell per tree: is its full suite green? for a dev-env-setup tree the suite is
`rhx play.run --all`. after the run, the tree holds one flat file per run:

```
.log/role=mechanic/skill=play.run/what=all/
  2026-11-05T15-00-00Z.stdout.log        ← the run's verdict tree; last line = the summary
  2026-11-05T15-00-00Z/                  ← one log per play, as today; same stamp as the file (F6)
    prove.a-passes.log
    prove.c-fails.log
```

the last line of the newest `*.stdout.log`:

```
      └─ 41 passed · 2 declined · 0 failed
```

`failed 0` reads green. the reader needs no dir walk, no pid, no file name but the stamp.

### before / after

| | before (main at 3f8b899) | after |
|---|---|---|
| verdict file | `what=all/<stamp>.pid<N>/summary.log` | `what=all/<stamp>.stdout.log` |
| shape | one dir per run, verdict nested inside | one flat file per run, beside its dir |
| matches `git.repo.test` layout (`what=<what>/<ts>.stdout.log`) | no | yes |
| per-play logs | `<stamp>.pid<N>/<slug>.log` | `<stamp>/<slug>.log` — the dir is the stamp's claim (F6) |
| empty index | `0 · 0 · 0`, exit 0 — reads green | `✋ ConstraintError`, exit 2, no log |
| in git | no (`.log/` ignored, `.gitignore:4`) | no |

### the aha

a ship report reads every repo the same way: `what=<x>/<ts>.stdout.log`, last summary line.
dev-env-setup is no longer the one tree with a bespoke layout.

## .the contract

- path: `$ROOT/.log/role=mechanic/skill=play.run/what=all/<YYYY-MM-DDTHH-MM-SSZ>.stdout.log`
- content: the `--all` verdict tree exactly as printed to stdout, header to summary
- last line: `      └─ N passed · N declined · N failed`
- the final blank + `🌲 every play passed` coda stays stdout-only, so the summary stays last (F2)
- `summary.log` retires: one writer per artifact (F1)
- the stamp is claimed atomically by `mkdir <stamp>/` (q9), then its log by noclobber create, with
  bounded tries, then `💥 MalfunctionError` exit 1 (F3). a name another run holds is a collision;
  any other refusal is a fault, named at once
- the per-play logs sit at `<stamp>/<slug>.log` — the claimed dir, so it carries no pid (F6):
  inside a dir, never named `*.stdout.log`, so `what=all/*.stdout.log` matches exactly one file per
  run and a newest-file reader never picks a dir
- an empty index halts: `✋ ConstraintError`, exit 2, no log written (F4)
- the header names both artifacts, one line each: `├─ verdict:` and `├─ plays:`

## .mental model

*"play.run leaves a receipt in the tree, the same kind every other suite leaves."* we say
`stdout.log`; a reader says "the test log".

## .evaluation

pros: one layout across repos; no dir walk; an empty suite can no longer read green; the clamp
play already exists and is hermetic.
cons: two artifacts per run (file + dir); `stdout.log` holds the verdict tree but not the coda.
while a run is in flight, and for good after a kill, the newest log holds no tally, so the cell
reads `fail` over the prior green — the safe direction, at the cost of a red that names no defect.
`what=all/` grows by one log and one dir per run, with no prune.

## .what is awkward

- the wish's premise was stale; the change is a conform, not a rescue
- `stdout.log` is a slight misnomer: it holds the verdict tree, not the coda. the alternative —
  last line the coda — breaks the wish's one hard rule (last line = summary)
