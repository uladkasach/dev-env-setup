# case=4 — a fresh grove enrolls itself

critipath · happy · cells e1, e2, e3 · sketch, not proof

## .narrative

infra stands up `grove-2`. the commander runs the one command he already runs on every new grove,
`rhx git.grove.provision boot grove-2 --mode apply`. its `ground` apply converges the whole tree, and
the backup bundle is one of its bundles: it lays the agent, its `.service` and `.timer`, enables
the timer, and verifies. no userdata, no second command, no flag. the same bundle on his laptop
declines in one line, since a laptop holds no grove role.

## .timeline

```
given a fresh grove `grove-2` (ec2 or hetzner), infra's declarations in /etc/grove/
when [t0] `rhx git.grove.provision boot grove-2 --mode apply`
  then the ground seat's apply installs the root-owned agent + grove-backup.service + grove-backup.timer
  and the timer is enabled (OnCalendar=hourly, Persistent=true)
  and the verify prints ✓ grove backup · enrolled · next run in <N>m
when [t1] a second apply
  then each unit file matches, and naught is rewritten (idempotent)
when [t2] the camper seat's apply (no sudo)
  then the bundle reads the root-owned state and does not decline: verify only
when [t3] `rhx grove.provision --mode apply` on a laptop (`local@unix`)
  then the bundle declines inline: 🌙 a laptop holds no grove role; grove backup is for groves
```
