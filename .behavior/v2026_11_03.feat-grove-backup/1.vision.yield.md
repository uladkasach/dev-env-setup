# 1.vision — grove backup and restore

## .the outcome world

### before

a grove holds the only copy of every unpushed commit and every clone conversation. a hetzner box
holds them on one unmirrored ssd. when it dies, they die. the one backup path is a laptop alias
(`git backup`) a human must remember to run, on a box he must first reach, with an s3 uri he must
recall.

### after

every grove backs itself up each hour. no human runs it, no clone sees it. the commander's usual
read, `rhx git.grove.stats`, carries one more line — `backup: ✓ 20m ago` — or a loud `✗` that names
its cause and who fixes it. when a grove dies, the commander stands up a fresh one, lists what the
dead one held, and restores it with one command. the unpushed commits are there; the conversations
resume.

### the aha

the commander never has to remember what was on the dead grove. `--list` tells him, dated to the
last hour it lived.

## .the contract we propose

| surface | shape |
|---------|-------|
| bundle | a root-owned agent + `grove-backup.service` + `grove-backup.timer` (`OnCalendar=hourly`, `Persistent=true`), modeled on `1.system/1.8.tmpfiles`. declines on `local@*`: a laptop holds no grove role |
| enroll | `grove.provision`, the ground seat's apply. a fresh grove gets it from `git.grove.provision boot`, with no extra step |
| scope source | the dirs and the plaintext excludes have ONE source: `GROVE_BACKUP_SCOPE` in infra (`provision/aws.infra/account=camp/grove/groveBackupScope.ts`, on infra#64's branch). the agent's lists are clamped to it by a test that reads it via `rhx git.repo.get`, never to a copy |
| walk | `/home/*/git/<org>/<repo>`, `/home/*/git/<org>/_worktrees/<dir>`, `/home/*/.claude`, `/home/*/.rhachet` |
| unit | one tar per clone (with `.git`), per worktree, per home dir |
| exclude | `node_modules` at any depth; `dist` `build` `coverage` `.next` only where git ignores them (a tracked dir named `build` is source, and its uncommitted edits are kept); `~/.claude/.credentials.json`; `~/.rhachet/keyrack/vault/os.direct/` |
| key | `grove=<slug>/user=<os user>/org=<org>/repo=<repo>/tree=<dir>/date=<YYYY-MM-DD UTC>.tar.gz` · `grove=<slug>/user=<os user>/home=<.claude\|.rhachet>/date=<…>.tar.gz` |
| skip | sha256 of the uncompressed tar vs the metadata of that unit's LATEST object, of any date; equal → no put. so `date=` marks the day a unit last changed, and an untouched clone is put once, ever — never once a day (F8) |
| mid-write | tar exits 1 when a file changes as it reads. an append to a `~/.claude/projects/**/*.jsonl` is the normal state of a live conversation, so that unit lands as read (a torn last line accepted) and counts ok; any other changed file means retry the unit once, then fail it loud while the rest still land |
| run-time fault | a put that errors (s3 5xx, throttle) or a temp tar that cannot be written (disk full) takes the same rule: retry the unit once, then name it; the rest still land, and the run is ✗ |
| lock | one backup lock per box; one restore lock per seat |
| reach order | grove name, then bucket name, then credential, then the verb's grant (`access denied: s3:<verb>`); the first that fails is the cause reported, and it fails the whole run, since a retry cures none of them |
| credential | the default aws chain. ec2: the instance profile. hetzner: roles anywhere, via its credential helper on loopback |
| bucket + grove name | read from infra's declarations on the box, never typed here (F1, F4) |
| status | journal + world-readable `/var/lib/grove-backup/status.json` |
| observe | one line, `✓ <age>` · `✗ FAILED` · `✗ STALE` (>2h) · `✗ NOT ENROLLED`, rendered from `status.json` by the bundle verify and `rhx grove.backup.get` here, and by infra's `rhx git.grove.stats --box <grove>` (owed by infra; F5) |
| restore a home dir | a fresh grove's provision already laid `~/.claude` and `~/.rhachet`, so a home restore lays each absent file and keeps each present one, named; `keyrack/` is never laid, since it is sealed to the dead grove's own key (F7) |
| restore onto a live clone | a fresh grove already holds a clean clone of each org repo (`5.10.repos`), so a clone restore **grafts**: it fetches the dead clone's local branches, `refs/stash` (as `<grove>/stash`), and each worktree's HEAD (as `<grove>/wt/<dir>`, so a commit on a detached HEAD survives) in fast-forward only, keeps a diverged one as `<grove>/<branch>` and names it, and never overwrites a file. the checked-out branch cannot take a fetch, so it fast-forwards by `git merge --ff-only` on a clean tree only; on a dirty tree it lands as `<grove>/<branch>` with the merge command named (F7) |
| human surface | `rhx grove.backup.get [--list] [--from <grove>]` (no `--from` lists every grove prefix) · `rhx grove.backup.restore --from <grove> (--all \| --repo <org/repo> --tree <dir> \| --home <.claude\|.rhachet>) [--into <dir>]`, run on the box (F2). `--all` restores every unit of the caller's seat in dependency order: clones, then worktrees, then home dirs |

this adopts #169's proposed design, with three changes forced by what a fresh grove holds: the
grove name and bucket name arrive as infra declarations on the box (F1, F4); a restore grafts into
the clones and home dirs a fresh grove's own provision already laid, rather than refuse them (F7);
the agent walks the two real seats, `ground` and `camper`, under `/home/*`. the "grove stats" line
#169 names lands in infra's `git.grove.stats`, read from the status file this repo writes (F5).

## .mental model

- to a friend: "time machine for the dev box, except it lives in s3 and the box can die"
- the commander says **backup** and **restore**; we say the same (F6). he says "my trees"; we say
  `unit` only inside the agent
- the shape is a **third topology**: push and pull move bytes through the laptop; backup moves them
  grove → s3 and restore s3 → grove, never through here

## .evaluation

| goal (from the wish) | met by |
|---|---|
| a backup runs on a schedule on every grove, no hand step | the bundle, via `grove.provision` (case=1, case=4) |
| it says when it last succeeded | status.json + the verify line (case=1 [t3], case=3) |
| a restore onto a fresh grove is proven end to end | case=2, proven at 5.3 on a real fresh grove |
| bucket names from their one source | infra declares them on the box from `CAMP_GROVE_BUCKET_NAME` (F1) |
| the dir list from its one source (#169 .coverage) | the agent's dirs + excludes clamped by test to `GROVE_BACKUP_SCOPE` |
| owed items from #63 named in the pr body | listed below |

**pros** — one door (`grove.provision`), no userdata, one agent for both kinds via the default
chain, loud on every failure, no plaintext credential leaves the box.

**cons** — hourly granularity: up to an hour of work can still die with the box. a full tar per
changed unit, never an incremental diff; a large clone re-puts whole on each change. any grove can
write any grove's prefix (one shared role, accepted by infra F8).

**pit of success** — a guessed name is never used (two groves would overwrite each other); a restore
never overwrites a present target, and grafts into a fresh grove's own clone rather than fight it;
a worktree restore with its clone absent names the clone restore first; a `DEEP_ARCHIVE` object thaws and prints the resume command rather than fail raw.

## .owed from ahbode/infrastructure#63 (for the pr body)

   `CAMP_GROVE_BUCKET_NAME` (F1)

   **camper's** `[default]` at the loopback endpoint (`genGroveCamperAwsConfigDefault.ts`); the agent
   runs as root, so root's endpoint is owed too — a declaration the agent's unit reads, never a
   port typed here
4. **`GROVE_BACKUP_SCOPE` on infra main** — it lives on infra#64's branch; the clamp test needs it
   on main to read a merged source
5. **the backup line in grove stats** — `git.grove.stats` (ec2, over ssm) and `hetzner.grove.probe`
   (hetzner, infra#64) render one line from `/var/lib/grove-backup/status.json` (F5)
6. **a fresh grove of each kind** to prove the restore against (`rule.forbid.deferred-provision-defects`:
   the one legitimate halt)

**assumptions**: an ec2 grove's instance profile already carries the `grove-s3` grant.
📌 relayed from the wish ("merged and applied; camp plan in sync"), unverified here: #63 is merged,
but no live put was run from this repo; 5.3 proves it with a real put. the skip needs the hash
before the put, so a unit cannot stream straight to s3: it tars once into a root-only temp file,
hashes as it writes, and puts only on change. that assumes disk headroom for the largest unit,
unmeasured (q7). `ProtectHome=yes` from the 1.8 template is NOT copied, since the agent must read
homes. a worktree restore takes its admin dir (`.git/worktrees/<dir>`) from the clone's latest
object; that object is never older than the worktree's last commit, since a commit there writes the
clone's `.git`, which re-puts the clone.

## .what is awkward?

- **five of the six owed items sit in another repo.** the agent can be written now, but it fails
  loud on every grove until infra declares the bucket and grove names (F1, F4), and on hetzner
  until infra#64 applies; its line in grove stats is infra's to render (F5). the urgency is
  hetzner, and hetzner waits longest
- **hourly is a window, not a guarantee.** the wish says "every unpushed commit"; the truth is
  "every unpushed commit older than the last hour"
- **a full re-put per changed unit** is cheap to build and wasteful at scale; a busy clone of a big
  repo re-uploads whole each hour it changes
- **`restore` is not a get/set/gen/del verb.** kept as the domain's own word, since `set` reads as
  overwrite, which a restore must never do (F2)
