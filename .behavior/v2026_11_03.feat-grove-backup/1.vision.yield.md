# 1.vision — grove backup and restore

## .the outcome world

### before

a grove holds the only copy of every unpushed commit and every clone conversation. a hetzner box
holds them on one unmirrored ssd. when it dies, they die. the one backup path is a laptop alias
(`git backup`) a human must remember to run, on a box he must first reach, with an s3 uri he must
recall.

### after

every grove backs itself up every 3 hours. no human runs it, no clone sees it. each tree lands
as one atomic, self-contained object: its own git, its changed files, and the transcripts of every
clone that worked in it. the commander's usual read, `rhx git.grove.stats`, carries one more line —
`backup: ✓ 20m ago` — or a loud `✗` that names its cause and who fixes it. when a grove dies, the
commander lists what it held and restores any one tree, or all of them, on any grove. the unpushed
commits are there; the conversations resume; the transcripts the crews learn from survive.

### the aha

one tree is one object, and it needs no other. a dead grove's tree comes back whole from its own
unit, onto a box that holds naught of that repo but origin.

## .the transcripts weigh as much as the code

a tree's brain transcripts are the record each crew learns from, and that loop is how the crews
improve. so a transcript gets every guarantee a commit gets: it rides in its tree's own unit, it
restores from that unit alone, and a test clamps that it comes back byte for byte.

## .the three objectives, each pushed to its limit

| objective | means |
|---|---|
| **atomic** | one tree is one object, put in one write. a restore reads the old unit or the new one, never half. a unit is one point in time: git read once from refs that cannot change under it, files packed then rechecked |
| **efficient** | a unit carries only what origin and its own HEAD cannot rebuild. a quiet unit costs a metadata read, never a pack. a run takes the stalest unit first, so a run that stops partway hands its tail to the next |
| **self-contained per tree** | a tree's unit holds its own git, its checkout state, its changed files, and its transcripts. it restores with no other unit of that repo |

## .the contract we propose

| surface | shape |
|---------|-------|
| bundle | `5.devtools/5.27.backup`: an agent + `grove-backup.service` (`User=camper`) + `grove-backup.timer` (`OnCalendar=0/3:00`, `Persistent=true`). declines on `local@*`: a laptop holds no grove role |
| enroll | ground's apply. a fresh grove gets it from `git.grove.provision boot`; one bundle alone from `boot --what 5.27.backup` |
| priority | `Nice=10`, `CPUWeight=10`, `IOWeight=10`, `IOSchedulingClass=idle`: a clone's own build or test always outranks the backup. no run-time limit cuts a healthy pass short; one run at a time, by lock and by systemd |
| scope source | the dirs and the plaintext excludes have ONE source: `GROVE_BACKUP_SCOPE` on infra main. the agent's lists are clamped to it by a test that reads it via `rhx git.repo.get`, never a copy |
| walk | camper's `~/git/<org>/<repo>`, `~/git/<org>/_worktrees/<dir>`, `~/.claude`, `~/.rhachet` |
| unit | one per tree (clone or worktree), one per tree with no git of its own (an orphan: a `_worktrees/<dir>` with no `.git`; a set-aside: a tree under `<clone>/.git/tree-del-setaside/`), plus two global units: `home=.claude` and `home=.rhachet`. every transcript under `~/git` sits inside some unit |
| key | `grove=<slug>/user=camper/org=<org>/repo=<repo>/tree=<dir>/date=<YYYY-MM-DD UTC>.tar.gz` · `…/org=<org>/orphan=<dir>/…` · `…/org=<org>/repo=<repo>/setaside=<name>/…`, where a set-aside's hour is cut from its name and a box-salted hash stands in · `grove=<slug>/user=camper/home=<.claude\|.rhachet>/date=<…>.tar.gz`. `date=` marks the day a unit last changed |
| a tree's git | `.grove-backup/objects.pack`: a plain git pack of what its refs and reflogs reach, minus every sha `git ls-remote origin` answers; `refs.txt` names each ref. so commits, branches, the stash, and reflog tips origin lacks ride; what origin holds never does. no origin → every commit rides; origin silent → this box's view of origin stands in, and the unit packs again next pass |
| a tree's checkout | `.grove-backup/checkout/`: HEAD, the index, its reflogs, any rebase or merge mid-flight. `.grove-backup/staged/`: the index's blob of each staged file. `.grove-backup/repo/`: branch + remote config (urls cleaned), `info/exclude`, edited hooks |
| a tree's files | only what differs from HEAD: modified, staged, renamed, untracked, and the git-ignored files worth a keep. a delete is a row in `.grove-backup/meta.json`. a file flagged `assume-unchanged` or `skip-worktree` packs whole |
| a tree's transcripts | `.agent/.actors/*/brain/.claude/` lives IN the tree, so it rides in the tree's unit; a test clamps that it comes back byte for byte from that unit alone |
| exclude | `node_modules` at any depth; `dist` `build` `coverage` `.next` only where git ignores them; `~/.claude/.credentials.json`; `~/.rhachet/keyrack/vault/os.direct/` |
| no dox | a unit carries no host name, address, or account id; the manifest records shas and paths relative to the tree, never a box fact |
| change | each unit records its own mark the moment its put lands. a unit whose refs, HEADs, and index did not move, and in which no file's ctime moved since its mark, is skipped with no pack. a changed unit packs, hashes, and puts only when the hash differs from its latest object |
| order | stalest mark first, a never-put unit before all. a run that stops partway resumes at the first tree not yet synced |
| point in time | a pack that saw a file's ctime move under it packs again, twice at most, then lands with the flag in its manifest. a `.jsonl` a brain still appends to lands as a whole prefix of itself |
| run-time fault | a put that errors or a pack that cannot be written: retry the unit once, then name it; the rest still land, and the run is ✗ |
| reach order | grove name, then bucket name, then credential, then the verb's grant (`access denied: s3:<verb>`); the first that fails is the cause, and it fails the whole run |
| credential | camper's own aws config: the instance role on ec2, roles anywhere on hetzner |
| bucket + grove name | read from infra's declarations on the box (`/etc/grove/backup.bucket`, `/etc/grove/name`), never typed here |
| status | journal + world-readable `/var/lib/grove-backup/status.json` |
| observe | one line, `✓ <age>` · `⏳ the first run is at work` · `✗ FAILED` · `✗ STALE` (>2h) · `✗ NOT ENROLLED`, from `status.json`, by the verify, `rhx grove.backup.get`, and infra's `git.grove.stats` |
| restore a tree | clone origin, or reuse the clone here; index the unit's commits; check out its HEAD with its index; lay its files and apply its deletes. a present clone takes the unit's branches fast-forward only; a present worktree is kept; a branch that diverged lands as `<grove>/<branch>`, named, never overwritten |
| restore a global unit | lays each absent file and keeps each present one, named; `keyrack/` is never laid, since it is sealed to the dead grove's own key |
| human surface | `rhx grove.backup.get [--list] [--from <grove>]` · `rhx grove.backup.restore --from <grove> (--all \| --of <org/repo> --tree <dir> \| --home <.claude\|.rhachet>) [--into <dir>]`, on the box. `--all` skips each tree already restored here, so a cut-off restore resumes |

## .mental model

- to a friend: "time machine for the dev box, one capsule per project, and the box can die"
- the commander says **backup** and **restore**; we say the same (F6). he says "my trees"; the
  agent says `unit`
- the shape is a **third topology**: push and pull move bytes through the laptop; backup moves them
  grove → s3 and restore s3 → grove, never through here

## .evaluation

| goal (from the wish) | met by |
|---|---|
| a backup runs on a schedule on every grove, no hand step | the bundle, via `grove.provision` (case=1, case=4) |
| it says when it last succeeded | status.json + the verify line (case=1, case=3) |
| a tree with an unpushed commit and a clone conversation is whole on a new grove | a tree's self-contained unit: its commits and its transcripts (case=2) |
| bucket names from their one source | infra declares them on the box from `CAMP_GROVE_BUCKET_NAME` (F1) |
| the dir list from its one source | the agent's dirs + excludes clamped by test to `GROVE_BACKUP_SCOPE` |
| owed items from #63 named in the pr body | listed below |

**pros** — one door (`grove.provision`), one object per tree, a restore that needs no other unit,
a quiet pass that costs a metadata read, a stopped pass that resumes, loud on every failure, no
plaintext credential leaves the box.

**cons** — a 15-minute window: work since a unit's last put can still die with the box. a unit
leans on origin for every commit origin holds, checked by `ls-remote` each time its refs move. any
grove can write any grove's prefix (one shared role, accepted by infra F8).

**pit of success** — a guessed name is never used (two groves would overwrite each other); a restore
never overwrites a present target; a commit origin dropped since the last fetch still rides, since
"pushed" means on origin now; a `DEEP_ARCHIVE` object thaws and prints the resume command rather
than fail raw.

only what differs from origin and HEAD, so the headroom it needs is small.

## .groundwork

### external research

- `ahbode/infrastructure#63` — merged. buckets, lifecycle, and the `grove-s3` grant (put, get,
  restore, list; no delete)
- the bucket name is computed: `asOrgBucketName({ purpose: 'grove-backup', env: 'camp' })`
  (`rule.require.bucket-namespace` in infra)
- the lifecycle keeps the 24 newest noncurrent versions of a key, for 7 days
- s3 `DEEP_ARCHIVE` reads need `RestoreObject` and a 12–48h thaw
- `git pack-objects --revs` with `--not <sha>…` writes only the objects the named shas lack, and
  `git index-pack` proves a pack reads before it is trusted. a `git bundle` refuses to exist when
  every ref tip is already on origin, so it cannot carry a commit only a reflog reaches

### internal research

- server tags: `local@unix`, `cloud@aws.ec2`, `cloud@hetzner.hetzbot` (`src/grove.env.sh`)
- root timer template: `src/grove.provision/1.system/1.8.tmpfiles/`
- seats: `ground` (sudo) and `camper` (no sudo)
- a fresh grove clones every org repo (`5.10.repos`), so a tree restore usually reuses a clone
- rhachet points each clone's brain config into its tree (`.agent/.actors/<actor>/brain/.claude/`),
  so a tree's transcripts live inside it
- a worktree's `.git` is a link to `<clone>/.git/worktrees/<dir>`; its commits, branches, and stash
  live in the clone, so a self-contained worktree unit bundles them
- extant laptop alias `git backup`: kept as is (F3)

## .what is awkward?

- **a 15-minute window is a window, not a guarantee.** the truth is "every unpushed commit older
  than that unit's last put"
- **"pushed" must mean on origin now.** a unit trusts origin for every sha `ls-remote` answers; a
  repo with no reachable origin pays for its whole `.git`
- **`restore` is not a get/set/gen/del verb.** kept as the domain's own word, since `set` reads as
  overwrite, which a restore must never do (F2)
