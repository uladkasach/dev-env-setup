# case=2 — a dead grove's work comes back, one self-contained tree at a time

critipath · happy, with sharp edges inside · cells l1, l2, r1–r7, r9, r10, r11, r12, r20, r21, r23 · the densest walk · sketch, not proof

## .narrative

`grove-1` was a hetzner box, and its ssd died. it held `ahbode/svc-quotes`, and a worktree
`_worktrees/svc-quotes.feat-x` with two commits nobody pushed, an edited file, and the
conversation that wrote them — inside the tree, at `.agent/.actors/<actor>/brain/.claude/`.

the commander asks infra for a fresh grove. `grove-2` comes up — ec2, as it happens; a restore
reads any grove's prefix, so the kind does not matter. its `grove.provision` enrolls the agent
(case=4) and, as every fresh grove does, clones each org repo (`5.10.repos`).

he lists what `grove-1` left behind, then restores the worktree. its unit needs no other: it
carries its own pack of the commits origin lacks, its HEAD, its index, its changed files, and its
transcripts. the restore indexes those commits into the clone already here, adds the worktree at
its HEAD, lays its index and its files. `git log` in the worktree shows the two unpushed commits; the
conversation is there byte for byte, and `claude --resume` lists it. on a box with no clone of that
repo at all, the restore clones origin first — still from that one unit.

last, the two global units: `.claude` and `.rhachet`. the one hand step left is the one the backup
refuses to carry: he logs the brain in again (`rhx brains.auth.set`), since `.credentials.json`
never left `grove-1`.

the aha: **one tree, one object, and it needs no other. he never had to remember what was on
`grove-1`, and the fresh box's own clone did not stand in his way.**

## .timeline

```
given a dead grove `grove-1` (hetzner), backed up on its last pass
  and a fresh grove `grove-2` (ec2), enrolled, whose provision cloned `ahbode/svc-quotes` clean
when [t-1] `rhx grove.backup.get --list`
  then it lists each grove prefix in the bucket with its latest date
    ├─ grove-1   <date>
    └─ grove-2   (none yet)
when [t0] `rhx grove.backup.get --from grove-1 --list`
  then it lists each unit with its latest date and class
    grove-1
    ├─ user=camper
    │  ├─ org=ahbode/repo=svc-quotes/tree=svc-quotes            <date> STANDARD
    │  ├─ org=ahbode/repo=svc-quotes/tree=svc-quotes.feat-x     <date> STANDARD
    │  ├─ home=.claude                                          <date> STANDARD
    │  └─ home=.rhachet                                         <date> STANDARD
    └─ 4 units
when [t1] `rhx grove.backup.restore --from grove-1 --of ahbode/svc-quotes --tree svc-quotes`
  then the clone's commits are indexed into the live clone, its branches fast-forward only
    ├─ feat-x          + 2 commits (new branch)
    ├─ main            = (already equal)
    ├─ + stash · 1 entry
  and each changed file lands where the live copy still matches HEAD; a live file that differs
    is kept and named                                                         # r7
when [t1.head] grove-1's `main` is 1 commit ahead, and `main` is the branch checked out here
  then git refuses a fetch into a checked-out branch, so the restore does not try one
  and if the live tree is clean, it fast-forwards `main` with `git merge --ff-only`      # r4
  and if the live tree is dirty, it leaves the tree and `main` alone, lands the commit as
    `grove-1/main`, and names the one command to run once the tree is clean            # r5
      └─ git merge --ff-only grove-1/main
when [t1.sharp] a branch on grove-1 diverged from the live clone's same-name branch
  then that branch is not moved; the restore names it and the two shas, and lands it as
    `grove-1/feat-y` beside the live one — never a force, never a silent skip
when [t2] `rhx grove.backup.restore --from grove-1 --of ahbode/svc-quotes --tree svc-quotes.feat-x`
  then the worktree's own commits are indexed into the clone here                # r9
  and ~/git/ahbode/_worktrees/svc-quotes.feat-x is added at its HEAD, its index and reflog laid
  and `git log origin/feat-x..HEAD` in it shows the 2 unpushed commits
  and its edited file is present as it stood at the last pass
  and each conversation under `.agent/.actors/*/brain/.claude/` matches grove-1's byte for byte  # r23
when [t2.alone] the same restore on a box with no clone of `ahbode/svc-quotes`   # r10
  then it clones origin first, then does [t2] — from that one unit, no other owed
when [t3] `rhx grove.backup.restore --from grove-1 --home .claude`
  given grove-2's provision already laid ~/.claude (settings, hooks)
  then each file absent on grove-2 lands; each file present is kept as grove-2 has it, and named
    └─ = settings.json   (kept: grove-2's provisioned copy)
  and ~/.claude/.credentials.json is ABSENT
  and the output names the login: `rhx brains.auth.set`
when [t3.rhachet] `rhx grove.backup.restore --from grove-1 --home .rhachet`
  then role storage lands the same way (absent lands, present kept)
  and `keyrack/` is not laid: it is sealed to grove-1's own key, which died with grove-1;
    the output says so and names `rhx git.grove.auth.keys.set` for grove-2's own keys
when [t4.sharp] the worktree restore is run again, by name
  then it refuses: the worktree dir is present; it names the path and `--into <dir>`
  and under `--all` the same tree reads `= already here; kept as it stands`, exit 0
when [t5] on another fresh grove: `rhx grove.backup.restore --from grove-1 --all`
  then it restores every unit of the caller's seat: clones, worktrees, orphans and
    set-asides, then the two global units
  and an orphan lands at `_worktrees/<dir>`, a set-aside at `_setaside/<repo>/<name>`, each
    transcript byte for byte                                                       # r24
  and a tree already restored here is skipped, so a cut-off `--all` resumes        # r20
  and one unit that fails does not stop the rest; the exit is non-zero and the unit is named
```
