# case=2 — a dead grove's work comes back on a fresh one

critipath · happy, with sharp edges inside · cells l1, l2, r1–r6, r9, r11, r12, r20, r21 · the densest walk · sketch, not proof

## .narrative

`grove-1` was a hetzner box. its ssd died at 03:10. it held `ahbode/svc-quotes`, and a worktree
`_worktrees/svc-quotes.feat-x` with two commits nobody pushed, plus the conversation that wrote
them.

the commander asks infra for a fresh grove. `grove-2` comes up — ec2, as it happens; a restore
reads any grove's prefix, so the kind does not matter. its `grove.provision` enrolls the agent
(case=4) and, as every fresh grove does, clones each org repo (`5.10.repos`). so when he arrives,
`~/git/ahbode/svc-quotes` is already there: a clean clone of `origin`, with none of `grove-1`'s
local branches.

he lists what `grove-1` left behind, then restores the clone. the restore does not overwrite the
fresh clone and does not refuse it either: it grafts. it opens the backed-up clone aside, fetches
its local branches into the live clone fast-forward-only, and reports each branch it moved. then
he restores the worktree: its admin dir lands in the live clone's `.git/worktrees/`, its files
land, `git worktree repair` links the two. `git log` in the worktree shows the two unpushed
commits. last, `.claude`: `claude --resume` lists the conversation. the one hand step left is the
one the backup refuses to carry: he re-logs the brain (`rhx brains.auth.set`), since
`.credentials.json` never left `grove-1`.

the aha: **he never had to remember what was on `grove-1`, and the fresh box's own clone did not
stand in his way.**

## .timeline

```
given a dead grove `grove-1` (hetzner), whose last backup ran at 03:00 UTC
  and a fresh grove `grove-2` (ec2), enrolled, whose provision cloned `ahbode/svc-quotes` clean
when [t-1] `rhx grove.backup.get --list`
  then it lists each grove prefix in the bucket with its latest date
    ├─ grove-1   2026-11-03T03:00Z
    └─ grove-2   (none yet)
when [t0] `rhx grove.backup.get --from grove-1 --list`
  then it lists each unit with its latest date and class
    grove-1
    ├─ user=camper
    │  ├─ org=ahbode/repo=svc-quotes/tree=svc-quotes            2026-11-03 STANDARD
    │  ├─ org=ahbode/repo=svc-quotes/tree=svc-quotes.feat-x     2026-11-03 STANDARD
    │  ├─ home=.claude                                          2026-11-03 STANDARD
    │  └─ home=.rhachet                                         2026-11-03 STANDARD
    └─ 4 units
when [t1] `rhx grove.backup.restore --from grove-1 --repo ahbode/svc-quotes --tree svc-quotes`
  then the live clone's files are untouched
  and each local branch of grove-1's clone is fetched in, fast-forward only
    ├─ feat-x          + 2 commits (new branch)
    ├─ main            = (already equal)
    ├─ grove-1/stash   + 1 stash entry (refs/stash, kept aside)
    └─ grove-1/wt/svc-quotes.spike   + detached HEAD of worktree `svc-quotes.spike` (kept aside)
when [t1.head] grove-1's `main` is 1 commit ahead, and `main` is the branch checked out here
  then git refuses a fetch into a checked-out branch, so the graft does not try one
  and if the live tree is clean, it fast-forwards `main` with `git merge --ff-only`      # r4
  and if the live tree is dirty, it leaves the tree and `main` alone, lands the commit as
    `grove-1/main`, and names the one command to run once the tree is clean            # r5
      └─ git merge --ff-only grove-1/main
when [t1.sharp] a branch on grove-1 diverged from the live clone's same-name branch
  then that branch is not moved; the restore names it and the two shas, and lands it as
    `grove-1/feat-y` beside the live one — never a force, never a silent skip
when [t2] `rhx grove.backup.restore --from grove-1 --repo ahbode/svc-quotes --tree svc-quotes.feat-x`
  then ~/git/ahbode/_worktrees/svc-quotes.feat-x exists, linked by `git worktree repair`
  and `git log origin/feat-x..HEAD` in it shows the 2 unpushed commits
  and its uncommitted edits are present as they stood at 03:00
when [t3] `rhx grove.backup.restore --from grove-1 --home .claude`
  given grove-2's provision already laid ~/.claude (settings, hooks)
  then each file absent on grove-2 lands; each file present is kept as grove-2 has it, and named
    ├─ + projects/…/<session>.jsonl   (12 files)
    └─ = settings.json                (kept: grove-2's provisioned copy)
  and ~/.claude/projects/ holds the conversation's session files
  and ~/.claude/.credentials.json is ABSENT
  and the output names the re-fill: `rhx brains.auth.set`
when [t3.rhachet] `rhx grove.backup.restore --from grove-1 --home .rhachet`
  then role storage lands the same way (absent lands, present kept)
  and `keyrack/` is not laid: it is sealed to grove-1's own key, which died with grove-1;
    the output says so and names `rhx git.grove.auth.keys.set` for grove-2's own keys
when [t4.sharp] the worktree restore is run again
  then it refuses: the worktree dir is present; it names the path and `--into <dir>`
when [t5] on another fresh grove, in place of [t1]–[t3.rhachet] one by one: `rhx grove.backup.restore --from grove-1 --all`
  then it restores every unit of the caller's seat, clones first, then worktrees, then home dirs
  and prints one tree of what landed, what grafted, what was kept, and what was set aside
  and one unit that fails does not stop the rest; the exit is non-zero and the unit is named
```
