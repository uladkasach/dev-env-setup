# case 9 — the shipped declaration: an apply under `off` strips, and keeps the write bit

## .narrative

the commander's home holds role hooks, and the lock is declared `off` until repos pinned below
the shielded rhachet move their pins. he runs the apply. the hooks leave; his own keys stay; the
file keeps its owner's write bit at 0600. the plan after it ✔s the strip and marks the write bit
with a 🌙 — never a ✋, since writable is what was declared, and never a ✔, since the lock the wish
asked for is still owed. the plan exits 0, and the debt stays on its page.

a sprout pinned below the shield then installs. its init writes its hooks through the tree's
arrow, and the write lands — its install does not fail. the next apply strips them again.

## .bdd

```
given a home settings file with 3 role hooks, mode 0400 from an earlier lock
  and _GROVE_PROVISION_5_3_BRAINS_SETTINGS_LOCK=off
when [t0] rhx grove.provision --what 5.3.brains --mode apply
  then 0 role hooks remain; every key outside the patch holds its value
  then the file mode is 0600
  then the transcript reads "(mode 600, swapped in by rename)"
when [t1] rhx grove.provision --what 5.3.brains   (plan)
  then ✔ no role-authored hook
  then 🌙 "keeps its write bit (mode 600), as declared off — the lock is owed, and waits for the pre-shield pins"
  then the plan exits 0
when [t2] the apply runs again
  then [KEEP]; byte-equal; no backup
```
