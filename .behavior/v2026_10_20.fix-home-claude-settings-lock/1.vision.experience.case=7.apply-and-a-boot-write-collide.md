# case 7 — an apply and a boot write collide

measured: one sprout boot wrote home from four pids within fourteen seconds. so the commander's
apply can land while a director's sprout boots. he should never have to think about that.

he does not. at no instant is the home file writable: the apply locks its tmp before the rename,
and the rename swaps the whole file in one step. a boot writer that opens home before the rename
gets `EACCES` on the old file; after, on the new one. there is no window to land in, so the order
of the two never changes the outcome.

```
given [c7] home settings locked; a sprout boot writer that opens the arrow in a loop
  when [t0] apply runs while the loop is live
    then every open by the writer fails with EACCES, before and after the rename
    then the result is byte-equal to an apply run alone
    then mode 0400 at every observed instant
```

the clamp holds this: its green arm runs the writer's open against the file through the arrow,
and asserts the mode, before and after an apply.
