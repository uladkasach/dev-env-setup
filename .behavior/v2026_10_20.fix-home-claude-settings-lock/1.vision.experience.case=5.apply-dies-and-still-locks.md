# case 5 — the commander's apply dies, and his file is still locked

the commander starts the provision, then hits ctrl-c halfway, or his disk fills. he reads a ✋ and
the fix line. he runs plan: ✔ — the file holds exactly what it held before, and it is still
read-only. he lost a run, not his lock.

what made that true: the apply never made the live file writable. it built the new content in a
tmp beside the file, locked the tmp, then renamed it over — one atomic step. an interrupt before
the rename leaves the original as it was; the tmp is cleaned by the trap.

```
given [c5] home settings locked + clean
  when [t0] apply, interrupted before the rename (signal, jq error, full disk)
    then the commander sees ✋ with the fix line
    then ~/.claude/settings.json is byte-equal to the before, mode 0400
    then no tmp is left beside it
  when [t1] rhx grove.provision --what 5.3.brains --mode plan
    then verify ✔
```
