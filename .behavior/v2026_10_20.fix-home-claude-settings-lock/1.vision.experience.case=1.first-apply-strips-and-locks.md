# case 1 — first apply strips and locks

the commander runs one command. the bundle copies the file aside, drops the 22 role hooks, merges
its patch, and turns off the write bit. he reads the four lines it prints and his file is his again:
`env`, `model`, `permissions` exactly as before, any hook he wrote himself still there, no hook a
role wrote.

if the copy aside fails — a full disk, a read-only dir — the apply halts before it builds a tmp or
writes aught, and says why. no backup, no write.

```
given [c1] home settings writable, 22 role hooks + 1 unauthored hook + env + model + permissions,
          and one key the 5.3.brains patch declares holds a stale value
  when [t0] rhx grove.provision --what 5.3.brains --mode plan
    then verify ✋ names 22 role hooks by author, the write bit, and the stale key, with the apply command
    then the file is byte-equal to the before
  when [t1] rhx grove.provision --what 5.3.brains --mode apply
    then a backup beside the file is byte-equal to the before
    then zero hooks with author repo=* remain; empty matcher blocks and events are gone
    then the unauthored hook remains, byte-equal
    then the stale key reads its declared value
    then every key the patch does not declare reads its before value
    then the file mode is 0400
  when [t2] rhx grove.provision --what 5.3.brains --mode plan
    then verify ✔ — zero role hooks, no write bit

given [c1.b] the backup cannot be written
  when [t0] apply
    then the half exits ✋ "could not back up ~/.claude/settings.json", with the path it tried
    then the file is byte-equal and its mode unchanged
```
