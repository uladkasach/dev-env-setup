# case 6 — apply recovers any state short of clean

three states look half-done, and each would slip past an apply that keyed its skip on one fact:

- **writable, no hooks, patch current** — the commander's file after a hand edit. no strip owed, but
  the write bit is on. an apply that skipped "because no hooks" would leave the door open
- **locked, hooks present** — the commander unlocked by hand to tweak a key, and a sprout landed
  hooks before he re-ran the bundle. the lock is on, so a skip keyed on the write bit would miss it
- **locked, no hooks, patch stale** — the repo moved a key's declared value. the file is locked and
  clean of hooks, but wrong

in each, the commander runs apply and reads the same short report: a backup, what changed, locked.
plan then shows ✔. the skip fires only on the one state that is clean on all three axes.

```
given [c6.a] home settings writable, no role hooks, patch current
  when [t0] apply
    then a backup lands beside it
    then content is byte-equal to the before; mode 0444

given [c6.b] home settings locked, 3 role hooks present, patch current
  when [t0] apply
    then a backup lands beside it
    then zero role hooks remain; every other key unchanged; mode 0444

given [c6.c] home settings locked, no role hooks, one declared key stale
  when [t0] apply
    then a backup lands beside it
    then the key reads its declared value; every other key unchanged; mode 0444

  when [t1] (any of the three) rhx grove.provision --what 5.3.brains --mode plan
    then verify ✔
```
