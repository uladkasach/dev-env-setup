# case 4 — the commander reads a clean journal at any trace volume

critipath · sharp — the second defect, and the fix's own trace rows multiply it.

## .narrative

the commander opens the grove's idle-hibernate journal to learn why crews died. today every tick
carries a line that looks like a fault:

```
sort: write failed: 'standard output': Broken pipe
```

it is noise — the verdict beside it was computed right — but the commander cannot tell that from the
page, and a line that looks like a failure on every tick teaches a reader to skip the page. the
grove holds thousands of traces (2,589 under one home here, plus 128 actor dirs), and the fix adds
more rows to read, so the noise would only grow.

after the fix, the same journal holds one line per tick — a hold with its reason, or a sleep — and
no error at any volume.

**the mechanism, for the clamp:** today's check takes the max with `sort -rn | head -1`. head exits
after one line; systemd runs the unit with SIGPIPE ignored (recalled default, A1), so sort's next
write fails with EPIPE and complains. the fix reads every mtime in one `awk` pass and keeps the max,
so no reader closes early.
