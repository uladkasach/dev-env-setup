# case 5 — 0901 retires its stopgap in one apply

critipath · happy — the hand-held box returns to a declared state.

## .narrative

0901 today: the timer stopped by hand, a drop-in `stopgap-crews.conf` that runs
`idle-hibernate-holds.sh` as an `ExecCondition=`, and infra's old check. the ground seat — reached
as `<grove>.ground`, the transport `prove.ground-seat-converges` names — runs one command:

```sh
rhx grove.provision --what 1.15.hibernate --mode apply
```

the upsert writes the checkout's check to a temp file beside `/usr/local/bin/idle-hibernate.sh` and
renames it into place, so a tick that fires mid-apply runs the old check or the new one, whole —
never a torn file. it writes the service and timer units the same way, removes the stopgap drop-in
and its holds file, reloads systemd, and arms the timer. the verify reads each fact back. a second
apply changes naught.

## .timeline

```
[t0] given 0901: timer stopped, stopgap drop-in + holds file present, old check
[t1] when the ground seat applies 1.15.hibernate
[t2] then each file lands by rename, so a concurrent tick never reads a partial check
[t3] then the check and both units match the checkout
[t4] then `idle-hibernate.service.d/` holds no foreign drop-in, and the holds file is gone
[t5] then the timer is enabled and active
[t6] when the ground seat applies again
[t7] then each upsert reports `•` (already held), and the verify passes
```
