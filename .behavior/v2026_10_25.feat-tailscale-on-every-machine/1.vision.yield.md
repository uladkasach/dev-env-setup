# 1.vision — tailscale on every machine

## .the outcome world

### before

the commander types `ssh camper@<host>`. it hangs, then times out. his laptop has no
tailscale client, so no route to any `100.x` address exists. hetzner waits.

### after

on his laptop:

```sh
sudo -v && rhx grove.provision --what 5.23.tailscale --mode apply
```

```
   ├─ 5.23.tailscale
   │  ├─ provision.upsert
   │  │  • tailscale's release key verified against its pinned fingerprint ✔
   │  │  • apt source: pkgs.tailscale.com/stable/ubuntu noble (UBUNTU_CODENAME, not ID=pop)
   │  │  • tailscale installed (1.x.y)
   │  │  • tailscaled enabled at boot, active
   │  ├─ provision.verify ✔
   │  ├─ configure.upsert
   │  │  🙋 sign in — open this url in your browser, as yourself:
   │  │     https://login.tailscale.com/a/<code>
   │  │     then rerun: sudo -v && rhx grove.provision --what 5.23.tailscale --mode apply
   │  └─ configure.verify ✋ not joined — the daemon reads 'NeedsLogin'
   │        ⇒ the sign-in is owed; the url is printed by:
   │        fix: sudo -v && rhx grove.provision --what 5.23.tailscale --mode apply
```

he opens the url and signs in. he reruns the same line:

```
   ├─ 5.23.tailscale
   │  ├─ provision.upsert  • tailscale already installed — no work
   │  ├─ configure.upsert  • this node already joined the tailnet — no work
   │  └─ configure.verify  ✔ joined as a member · no tags · a camp grove is a peer
```

then `ssh camper@<host>` connects. every later rerun prints the same two `no work` lines
and asks naught.

### the aha

one package, two joins. the client is the same on every machine. **what differs is who the
machine joins as**: a laptop as its human, under his login; a grove as `tag:camp`, with a key. the
bundle reads that from the tier it already knows — never from a flag a human must remember. and a
hetzner box whose bootstrap left its fact now reads as the cloud grove it is; one whose fact is
absent is refused by name before any bundle runs.

## .the contract

two changes.

### 1. a third platform in `src/grove.env.sh`: `hetzner.hetzbot`

today a hetzner box answers no platform probe, so a headless one is refused, and one whose session
forwards a display reads `local@unix` — a laptop with a human.
a new probe, from a free fact the hetzner bootstrap leaves on disk (#172's shape of the fix, step 1),
gives it `cloud@hetzner.hetzbot` (the platform half names the box lifecycle, beside `aws.ec2`).
tier `cloud`, so every gate that reads "no human here" (`!= local@unix`) answers right on a hetzner
box whose bootstrap left its fact. a fresh box whose fact is absent answers no rung, so
`grove.env.sh` refuses it by name (exit 2) before any bundle runs: it never reads `local@unix`, and
no second guard is owed (F011, dropped at 5.1).

### 2. one new bundle, `5.23.tailscale`, in `5.devtools` after `5.12.rack`

every write below runs by a seat with root. a seat with no root (an agent shell, a grove's
`camper`) declines each write with the `sudo -v &&` line, mints no url, and makes no `up` call
(case 3).

| phase | every machine | `local@unix` (the human's laptop) | `cloud@*` (ec2, hetzner) |
|---|---|---|---|
| `provision.upsert` | signed apt repo, `tailscale` package, `systemctl enable --now tailscaled` | same | same |
| `provision.verify` | binary present, unit enabled + active | same | same |
| `configure.upsert` | joined → no work | not joined → **member join**: `sudo tailscale up` (no `--auth-key`, no `--advertise-tags`), print the url, **exit** | not joined → **tagged join**: `tailscale up --auth-key=file:<key file> --advertise-tags=tag:camp`, no url; key absent → ✋ names the handoff |
| `configure.verify` | — | ✔ joined · no tags · a user login · a camp grove is a peer; ✋ otherwise | ✔ joined · tags = `tag:camp` · no user login; ✋ otherwise |

**the tagged key** — a pre-approved, tagged tailscale auth key minted by `ahbode/infrastructure`
for `tag:camp`. the bundle reads it from the rack, and never from argv
(`hazard.secrets-in-argv`):

| box | vault | how it lands there |
|---|---|---|
| `cloud@aws.ec2` | `aws.params`, at `<org>.camp.TAILSCALE_AUTH_KEY` — the ec2 instance role reads it (`rule.forbid.aws-params-off-ec2` permits it here only); per-org, revised at 5.1 (F012) | infra writes it once per org, for that org's camp groves |
| `cloud@hetzner.hetzbot` | `os.secure` on the box | the human runs `rhx git.grove.auth.keys.set <grove> --mode apply` from the laptop; the key is a `5.16.keys` row |

the rest of #172 — the port-22 firewall on `tailscale0`, the sshd bind, the platform lifecycle
split, the break-glass drills — stays #172's.

the invariants from #174, and where each is held:

| invariant | held by |
|---|---|
| a laptop never takes `tag:camp` | the member path passes no `--advertise-tags` and no key; the tagged path runs on `cloud@*` only; verify ✋s on any tag under `local@unix` |
| a remote grove never joins as a member | the member path runs on `local@unix` only, fails closed; hetzner reads `cloud@hetzner.hetzbot` where its fact is present, and a box the probe cannot name is refused before any bundle runs. cloud verify ✋s an untagged join |
| one join per machine | the join guard reads the daemon (`BackendState`) before any `up` |
| ubuntu only | `pkg_assert_apt`; the repo path keys on `UBUNTU_CODENAME` |
| the sign-in is the human's act | on a laptop the bundle prints the url and exits; it never mints, pastes, or fakes a login. a grove's tagged key is infra's to mint and the human's to place; the bundle only reads it |

## .mental model

- **to a friend:** "the dev-env setup now puts tailscale on every box. on my laptop it gives me a
  login link once; on the cloud boxes it's preinstalled and joins with a key."
- **analogy:** one badge reader on every door; the laptop gets a personal badge (my login), a
  grove gets a service badge (`tag:camp`). a personal badge never opens a service door, and a
  service badge never opens mine.
- **their words vs ours:** the commander says *ground* for his laptop. this repo already spends
  `ground` on the sudo seat of a grove box (`term=ground`). so the contract speaks in tiers —
  `local@unix` / `cloud@*` — and in *member join* / *tagged join*, never *ground*.

## .evaluation

**goals:** the commander's laptop gains a `100.x` route (case 1); reruns are silent (case 2); the
sign-in stays the human's act (cases 1, 4); remote groves join as `tag:camp` and never as a
member (cases 5, 6, 8).

**pros**
- one bundle, every machine; the signed repo puts tailscale on the `apt upgrade` path
- the join kind is derived from the tier; no flag to forget, no way to tag a laptop through it
- no run ever waits on a browser: an apply finishes, and the next one confirms
- the hetzner probe fixes the tier for every bundle, not only this one — and #172 inherits it

**cons**
- a grove's join waits on a key the bundle cannot make: infra mints it, and on hetzner the human
  places it. until then verify ✋s on every apply (case 8)
- the sign-in takes two runs: one prints the url, a rerun confirms
- the probe touches `grove.env.sh`, which every bundle reads; each `cloud@*` / `!= local@unix`
  gate in the tree must be audited for what it asks of a hetzner box (#172 step 4)

**pit of success**
- an agent shell can never sign in on a human's behalf: it declines with the `sudo -v &&` line
- an unopened url costs naught: verify ✋s with the rerun line, and no run hangs
- plan mode never prints a url and never calls `up`

**assumptions** — each **[research]**
- the hetzner probe's fact. #172 names candidates: `/etc/ssh/sshd_config.d/00-grove.conf` plus
  the `ground`/`camper` pair, or a declared `/etc/grove` identity file. `grove.env.sh` demands a
  probe measured on the box it names AND on one it must stay silent on. the laptop half is free.
  the hetzner half needs reach to the box — which this very bundle gives, once the laptop joins.
  if an ec2 grove's bootstrap writes the same file, the hetzner rung must sit after the ec2 rungs
- the audit of every tier gate: each bundle that reads `local@unix`, `!= local@unix`, `cloud@*`,
  or `*@aws.ec2` is sorted by what it asks (#172 step 4): no screen / no human → key on tier;
  needs aws (imds, ssm, hibernate) → key on `aws.ec2`
- "a known camp grove is a peer" needs a grove name to look for, read from somewhere not tracked
  here (the grove registry `git.grove.*` already keeps, or the ssh alias); which one is a blueprint call
- `tailscale up` with no auth key prints the login url; the exit-after-print shape needs a way to
  get the url and return — `tailscale up --timeout`, a backgrounded `up`, or the `AuthURL` field of
  `tailscale status --json`. which one works is a probe
- a rerun of `tailscale up` that omits a prior flag warns and prints a copyable command (kb), so
  the daemon read must precede every `up`
- `tailscale status --json` answers for a non-root user; if not, the camper seat reads
  `systemctl is-active` and declines the join read
- the tagged join: `tailscale up --auth-key=file:<path>` reads the key from a file, so it never
  enters argv; a tagged key carries its tags, so `--advertise-tags=tag:camp` must match them or the
  `up` refuses. both from tailscale's kb, owed a check before execution
- the key's name in the rack, and that `@all.camp` in `aws.params` is readable by every camp ec2
  grove's instance role — infra's to confirm (`handoff.infra.grove-account-reach`)
- the hetzner box already sits on the tailnet (#172 measured it); whether it joined as `tag:camp`
  decides if its first apply reads "joined → no work" or ✋s a wrong join
- the bundle needs `2.1.toolkit` (`curl`, `gnupg`, `jq` — `2.1.toolkit/provision.upsert.sh:23`)
  first, and the tagged join needs `5.12.rack`. as `5.23` in `5.devtools`, dispatched after
  `5.12.rack`, it has both (the slot moved from `2.4` at 5.1)
- measured 2026-10-25: this laptop has no `/usr/bin/tailscale`, and no
  `/etc/apt/apt.conf.d/50unattended-upgrades`
- acceptance 1, 3, 5 of #174 need `rhx tailscale.reach.probe` and the camp acl, both in
  `ahbode/infrastructure`

## .what is awkward?

1. **the wish's word and the repo's word disagree.** *ground* means the human's machine to the
   commander and the sudo seat to this repo. the contract uses neither sense of it.
2. **a laptop wish now edits the platform ladder.** the probe is the right fix for the invariant,
   and it reaches every bundle that reads the tier. its proof needs a measurement on the hetzner box,
   which needs the tailnet this wish delivers — so the laptop half lands first, and the hetzner rung
   is measured over the new route before it ships.
3. **the wish says "as #172 already does", and #172 is unbuilt.** so this wish builds the tagged
   join itself, and takes on a key it cannot mint. the bundle owns the join; infra owns the key;
   the human owns its placement on hetzner. three owners for one green verify.
4. **"a camp grove is a peer" needs a grove name.** the repo may not track the tailnet's name, so
   verify must look for a known grove from a source outside the tracked tree.
