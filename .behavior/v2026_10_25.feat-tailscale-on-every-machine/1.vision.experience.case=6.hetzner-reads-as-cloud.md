# case 6 — the ground seat on a hetzner box (sharp, fails safe)

## .narrative

a crew member sshes into the hetzner grove's `ground` seat and runs the full tree apply, as they do
on every grove. the run's header names the box `cloud@hetzner.hetzbot`. the tailscale bundle finds
the client in place and the box already on the tailnet as `tag:camp`, and says so in one
`no join owed` line. on a second, fresher box that its bootstrap never finished, the run stops before
any bundle: no probe could name the box, and the error names the one line the bootstrap owes in
`/etc/grove/platform`. on a third box the file is there but mode 000: the run halts, says the file
cannot be read, and names `sudo chmod 644`. neither box ever reads as a laptop.

## .timeline

```
given the hetzner grove, its bootstrap fact on disk, joined as tag:camp
  when [t0] the crew runs `rhx grove.provision --mode apply` as `ground`
    then they see the header read `cloud@hetzner.hetzbot`                                   # B11
     and configure.upsert `this node already joined the tailnet — no join owed`               # B5 (C6)
     and configure.verify ✔ joined · tags = tag:camp                                        # B16

given a fresh hetzner box with no bootstrap fact
  when [t1] the crew runs `rhx grove.provision --mode apply` as `ground`
    then they see ✋ ConstraintError: cannot tell which machine this is — no platform probe answered   # B13 (C3)
     and it names the platform declaration, its path, the bootstrap that owes it, and
         `GROVE_ENV_SERVER=cloud@hetzner.hetzbot` for one run
     and no bundle runs: no install, no `up`

given a hetzner box whose /etc/grove/platform is mode 000, and a forwarded display
  when [t2] the crew runs the same apply
    then they see ✋ ConstraintError: cannot tell which machine this is — /etc/grove/platform exists but cannot be read   # B18 (C4)
     and `fix: sudo chmod 644 /etc/grove/platform`
     and no bundle runs — the display beside it never answers `local@unix`

given the commander's laptop
  when [t3] he runs the same apply
    then the probe answers no; the header reads `local@unix`; the member path runs          # B11 (silent rung)
```

## .fail-safe

fast (refused before any bundle), loud (a ✋ the crew member reads at once), teaches the fix (the
probe fact the bootstrap owes, or the chmod). the derivation has no fallback, so an unnamed or
unreadable box never reads as a laptop. an ssh session that forwards X no longer reaches the
desktop rung either: that rung declines any ssh seat.
