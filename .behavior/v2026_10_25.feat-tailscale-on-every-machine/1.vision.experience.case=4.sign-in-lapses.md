# case 4 — the url is left unopened (sharp, fails safe)

## .narrative

the url prints and the run ends. the commander does not open it — he gets pulled into a call. no
run hangs, no duct is held. every later apply ✋s in verify with the rerun line, so the owed step is
loud wherever he next looks. when he does rerun, the bundle sees the node still waits for a login
and prints a url again.

## .timeline

```
given tailscale installed and enabled, not joined, a human run on `local@unix`
  when [t0] he runs `sudo -v && rhx grove.provision --what 5.23.tailscale --mode apply`
    then provision.upsert prints `tailscale already installed — no work`
     and he sees a login url and the rerun line, and the run returns him to his prompt     # B6 (C17)
     and configure.verify ✋ not joined — the daemon reads NeedsLogin; the sign-in is owed, and it shows the url
  when [t1] he leaves the url unopened
    then the node stays in a login wait; no process holds his terminal or a duct
  when [t2] he next runs an apply — the bundle alone, or the full tree
    then configure.verify ✋ not joined — the sign-in is owed
     and it shows the url the daemon still holds; or, where it holds none, says no url is
         minted yet and that the fix below mints one
     and it prints: sudo -v && rhx grove.provision --what 5.23.tailscale --mode apply
  when [t3] he runs that line
    then configure.upsert reads the node as not joined, and prints a login url again
```

## .fail-safe

no wait at all (the run exits after the url), loud (a ✋ on every apply until joined), teaches the
fix (the rerun line). verify reads the url from the daemon itself, so both branches are proven
(`prove.tailscale-caselist`: "url held", "no url yet"); which one a real daemon takes after a long
wait is tailscaled's choice, and either serves the human. no partial join is left: the node waits
for a login, which the next run reads as "not joined".
