# case 3 — the agent shell declines, before install and after it (sharp, fails safe)

## .narrative

the crew runs the bundle with no root. on a laptop with no tailscale, it cannot install, and it says
so at once with the one command the human owes. later, after the commander has installed tailscale
but before he has signed in, the crew runs the bundle again. provision is done, so the run reaches
the join — and the crew's seat must not sign in for him. it declines again, with the same line,
and mints no url for the crew to see.

## .timeline

```
given a laptop with no tailscale, an agent shell with no cached sudo credential
  when [t0] the agent runs `rhx grove.provision --what 5.23.tailscale --mode apply`
    then provision.upsert 🌙 declines within a second — no apt call, no key fetch           # B1 (P4)
     and it prints: sudo -v && rhx grove.provision --what 5.23.tailscale --mode apply
     and provision.verify ✋ tailscale absent, with the same fix-text
     and configure.upsert makes no `up` call                                                # (C2)

given the same laptop, tailscale installed by the human, not joined
  when [t1] the agent runs the same command
    then provision.upsert prints `tailscale already installed — no work`                              # B14 (P3)
     and configure.upsert 🌙 declines the join: no root, and the sign-in is the human's    # B1 (C13)
     and it prints the same `sudo -v &&` line, and mints no url
     and configure.verify ✋ not joined — the sign-in is owed
```

## .fail-safe

fast (no network at [t0], no `up` at [t1]), loud (a ✋ from verify each time), teaches the fix (the
exact `sudo -v &&` line — the form `gotcha.rhx-runs-a-skill-with-no-tty` proves a human can pass).
