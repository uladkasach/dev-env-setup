# case=7 — a crew works through a week, unattended: nights, a reboot, a lid close, a cert lifetime

covers inventory rows 35, 36, 37, 39. the reboot binds this stone; the lid close, idle, and
wifi idle in `[t4]` bind naught here — they are remote-laptop constraints (ruled, seed S1),
shown so the collocated case is on record. feel: 😊 happy, one 🗡️ edge. care: 🔴 critipath — the wish
grounds the whole effort in autonomy: a box that needs a human to re-auth on a schedule is a
workstation, not a grove.

## .narrative

a crew starts on `house-1` at 22:00 and runs past dawn. at 10:00 the next day its sts session
— 12h at most — has long since lapsed. it never noticed: `credential_process` is called by the
sdk whenever a session nears its end, and each call signs a fresh one from the cert on disk. no
daemon, no timer, no keyrack unlock (whose ~9h expiry would otherwise put a human on a 9-hour
cycle × every grove).

saturday the laptop reboots for a kernel update. the house sshd unit returns with the box; the
cert is a file; there is no credential process to restart. the first send after boot works.

sunday the human closes the lid mid-crew. the whole box sleeps — the supervisor, the house
seats, and the crew freeze together, so no reach goes dark while a sender waits on it: the
sender is asleep too. on wake the crew resumes where it froze. its next aws call finds its
session lapsed and re-signs from the cert. the wifi came back on its own, by the host's
`1.11.wifi` watchdog; loopback never left. an idle suspend is the same walk.

a house grove on this box inherits the laptop's sleep, never its own. what a sleep costs the
crew is wall-clock time; a grove that must work while the lid is shut is the remote-laptop
stone's, out of scope here.

the cert itself is short-lived — 7 days in AWS Private CA's short-lived mode. so the camper
holds a user timer that renews it a day before its end, with its own live badge: the old cert
signs the request for the new one. the renewal is the one live part, so it is also the one
that reports loud — a failed renewal fails the next converge's verify with the hours left, days
before the badge dies, not at 3am when it does.

## .timeline (sketch)

```ts
given('[case7] house-1 converged with a cert valid 7 days', () => {
  when('[t0] 13h pass mid-crew', () => {
    then('aws calls keep answers — credential_process signs a new session; no human, no daemon');
  });
  when('[t1] the box reboots', () => {
    then('the house sshd unit is enabled and returns; the first reply after boot works');
    then('the badge needs no restart — the cert is a file');
  });
  when('[t2] day 6 of 7: the renewal timer fires', () => {
    then('a new cert lands at the same path, mode 0600; the helper picks it up on its next call');
  });
  when('[t3] the renewal failed (e.g. the CA refused)', () => {
    then('the next converge\'s 5.6.aws verify fails ✋ with hours-left and the renewal log path');
    then('the failure surfaces days before the badge dies');
  });
  when('[t4] the lid closes mid-crew (or idle suspend), then the box wakes — binds naught here; a remote-laptop constraint', () => {
    then('the crew process resumes; it is never killed by the sleep');
    then('the first aws call after wake re-signs a session from the cert; no human');
    then('the first `git.grove.send house-1 --reply` after wake answers; the unit never stopped');
    then('a wifi idle or stall breaks no reach — the reach is loopback; aws calls retry once the host watchdog reconnects');
  });
});
```

⚠️ the renewal's AWS-side grant (the role may issue its own next cert) is
`ahbode/infrastructure#36`'s to decide. this case shows the box half it would drive.
