## .what

a box we already own — a laptop on a home network — becomes a **grove** the fleet can dispatch
crews onto. two properties, and both are the outcome:

1. **reachable** from a supervisor that is not on its LAN
2. able to obtain its **AWS identity with no human in the refresh loop**

## .why

**cost.** a 64 GB cloud grove runs ~$385/mo on-demand. a laptop we already own runs ~$5–10/mo of
power. researched 2026-09-11; the flat-rate alternatives (rented dedicated hardware) land ~€40/mo.

**capacity and blast radius.** the extant grove is 31 G and carries 13–17 crews at zero `full`
stall — a proven size, not a compromise. three 32 G laptops hold ~3x the fleet RAM and divide the
single-box failure domain by three.

⚠️ **but the reason this merits the work is autonomy, never the money.** the fleet exists so crews
work overnight with nobody awake. a box that needs a human to re-auth on a schedule is not a
grove; it is a workstation.

## 🔴 .the gap, stated from this repo's own brief

`.agent/repo=.this/role=any/briefs/creds/howdoes.a-box-reach-an-aws-account.md` documents exactly
**two** identity paths. **a laptop grove can use neither:**

| path | mechanism | why it fails here |
|---|---|---|
| laptop | `sso_session` → a cached sso token | needs a **human at a browser**, periodically |
| grove | `credential_source = Ec2InstanceMetadata` | needs **IMDS**, which exists only on EC2 |

⇒ a third mechanism is required, and **that gap is the whole ask.** we did not pick one — see
`.advisory` below.

## 🔴 .START HERE — the collocated grove, `house://localhost`

> *"a separate user on the same local machine as a touch grove … its not the visible open local
> grove, its the underhood collocated grove, with their own camper and ground users. that way even
> on the same machine there can be a sandbox. and, it enables rapid tests."*
> — the wisher, 2026-09-13 🟡 *(said before the word settled on `house`)*

a **second unix user on the machine the supervisor already runs on**, provisioned with the extant
`camper` / `ground` split and reached over **loopback**.

🟢 **this is the cheapest first grove there is, and it is the natural first stone.** it needs **no
tailnet and no Roles Anywhere** — a second unix user and loopback ssh are enough.

### .why it is yours, and why it comes first

| | |
|---|---|

### 🔴 the sandbox is STRONGER here than on EC2 — and the reason is surprising

`ahbode/infrastructure`'s own `term=camper` carries a warn that must be read before this is built:

> *"a camper bounds what the crew may do to the BOX. it bounds no part of what they may do in AWS.
> the grove's IMDS endpoint (169.254.169.254) answers ANY uid on the box, with no privilege of any
> kind — so every camper already holds the grove's full badge … a camper with zero sudo reaches all
> of it with one unprivileged `curl`."*

⚠️ **on an EC2 grove the OS boundary buys no AWS boundary at all.** ⇒ 🟢 **but a house grove has no
IMDS** — that absence is the whole reason `ahbode/infrastructure#36` exists. its AWS identity
arrives from a **credential the user holds** (a cert on disk, a `credential_process`), and a file
carries unix permissions where a link-local endpoint does not.

| | EC2 grove | 🟢 `house://localhost` |
|---|---|---|
| where the AWS badge comes from | IMDS — a network endpoint | a file the user owns |
| does a second unix user get it | 🔴 **yes, unavoidably** | 🟢 **only if you grant it** |
| so the OS boundary buys… | OS integrity only | **OS integrity AND an AWS boundary** |

🔴 **so a collocated house grove can hold a real per-user AWS boundary that an EC2 grove cannot.**
that is a reason to build it, not merely a caveat.

⚠️ **and it is an unverified inference, drawn from two repos' briefs by an author outside both.**
**check it against whichever identity mechanism you and `#36` settle on** before any guarantee rests
on it — if the credential lands somewhere world-readable, the boundary evaporates and the claim
above is wrong.

### ⚠️ what is genuinely unsettled

- **the authority form.** `house://localhost` is what symmetry suggests and it reads well. whether the

- **loopback ssh still needs a key.** the camper/ground `authorized_keys` split applies unchanged,

### 🟢 AMENDED 2026-09-13 — two leads costed, and a SECOND candidate this wish never named

🔴 **the first dispatch of this wish named only Roles Anywhere.** the peer seed
(`ahbode/infrastructure#36`) named a second candidate and this one did not — an omission, corrected
here. **both are yours to weigh**, and the identity mechanism is a joint decision with that repo
rather than a choice either makes alone.

**candidate A — IAM Roles Anywhere + a CA.** cost was re-checked and it is far lower than feared:

| mode | per CA / month | per cert | max validity |
|---|---|---|---|
| general-purpose | **$400** | $0.75 → $0.001 tiered | years |
| 🟢 **short-lived** | **$50** | **$0.058** | **7 days** |

AWS names Roles Anywhere as the case short-lived mode was built for, so it is **8x cheaper AND the
better posture** — a 7-day cert makes revocation a non-problem. the trust anchor takes an AWS
Private CA reference directly, and **one CA serves the whole fleet** rather than one per grove.

⇒ the tradeoff that matters is **not** the dollars; it is who operates the CA:

| | self-hosted (step-ca) | 🟢 AWS Private CA, short-lived |
|---|---|---|
| $ / month | $0 | $50, fleet-wide |
| renewal, revocation, responder liveness | 🔴 **yours** | vendor's |
| a cert that expires mid-converge at 3am | 🔴 **yours to diagnose** | vendor's to keep alive |
| operational surface | 🔴 permanent; it never completes | none |

**candidate B — OIDC + `AssumeRoleWithWebIdentity`.** no CA at all. ⚠️ **and it is not the free
lunch it first appeared:**

| what was hoped | what is true |
|---|---|
| Tailscale vends an OIDC token for a node, which AWS STS accepts | 🔴 **backwards.** Tailscale's "workload identity federation" (GA, all plans) is **inbound only** — it lets cloud workloads authenticate **to** Tailscale. Tailscale is the **consumer** of OIDC tokens, never an issuer AWS would trust |
| no service to operate | 🔴 needs an issuer that (a) attests the box and (b) is **reachable from the public internet** so AWS can fetch its JWKS |

🟡 a third-party OSS project (`tsiam`) issues JWTs on behalf of a tailnet node for exactly this
exchange, so the shape is **possible** — but it is a service exposed to the public internet that
you operate, with less maturity and no vendor behind it.

⇒ **the honest order flipped.** B is not dismissed; it is no longer the cheap one.

⚠️ vendor sources, checked 2026-09-13 — the AWS Private CA price page, the AWS announcement of
short-lived certificate mode (2022-10), the AWS Security Blog post *"IAM Roles Anywhere with an
external certificate authority"*, and the Tailscale blog post *"Workload identity federation GA"*.

🔴 **if a shape we never imagined satisfies the acceptance above, that is the better outcome.**

### 🟢 AMENDED 2026-09-13 — the REACH half, costed properly

⚠️ **the line above first read *"a free tier that covers a few devices"*. that is FALSE**, and it
understates the free tier badly enough to eliminate an option that in fact fits:

| tier | price | the caps that bind |
|---|---|---|
| 🟢 **Free (Personal)** | **$0** | 6 users · **unlimited devices** · **50 tagged resources** |
| Starter | ~$6/user/mo | 3-user minimum |
| Premium | $18/user/mo | SCIM, audit-log export, SLA |

⇒ **a grove fleet fits the free tier with room.** groves would be *tagged* devices (`tag:grove`), so
the one cap that binds is **50 tagged resources** — at 3 laptops that is 6% of it.

**Tailscale is both OSS and proprietary, and the split is what matters:**

| layer | what it is | license |
|---|---|---|
| data plane | WireGuard — the actual encrypted tunnels | 🟢 OSS, GPLv2, in-kernel since 5.6 |
| the client | `tailscaled`, the CLI | 🟢 OSS, BSD-3 |
| 🔴 **control plane** | key exchange, ACLs, device registry, DERP relays | ⛔ **proprietary SaaS** |

🟡 **what a control-plane outage actually costs is narrower than it sounds.** the data plane is
peer-to-peer, so extant tunnels **stay up**; what stalls is *new* connections and key rotation. for
a grove fleet: live crews survive, a fresh `crew.boot` onto a grove you had not already reached does
not.

**Headscale** is a third-party OSS reimplementation of the control plane, and the official client
speaks to it unmodified:

| | Tailscale SaaS | Headscale |
|---|---|---|
| control plane | theirs, closed | yours, OSS |
| cost | $0 at this scale | a box to run it on |
| when it breaks at 3am | 🟢 their pager | 🔴 **yours** |

⇒ **the same tradeoff as the CA question, and it points the same way** — $0 with zero operational
surface beats $0 with a service to keep alive
(`rule.always.grade-infra-on-unattended-operation`).

🟢 **and the exit is real:** the client is OSS and Headscale is a drop-in, so a terms or price change
does not capture us. that is a materially better position than a proprietary client would leave.

⚠️ **one consequence for the supervisor side, noted so it is not a surprise:** a tailnet node is
reachable with no start call, which **largely retires `git.grove.wake`**. that is `nheuron`'s to
handle (`uladkasach/nheuron#18`), not yours — flagged only so the reach choice is made with its
downstream in view.

## .constraints that bind, and why

- **no human in the credential refresh loop** — stated above; it is the point of the ask
- **a laptop is not a server** — lid close, idle suspend, wifi powersave, and thermal limits each
  take a grove dark mid-crew. a grove that goes dark mid-converge loses the crew work
- **a swap cushion carries real weight here.** on an EC2 grove the hibernate agent reserves swap
  and then disables it, so memory pressure kills rather than pages — measured on the extant grove
  as an `earlyoom` SIGTERM of a 17-hour clone. a laptop has no such constraint, so this is an
  opportunity rather than a risk, and it merits care to not reproduce the EC2 behavior by accident
- ⚠️ **this repo is PUBLIC.** no account ids, internal hostnames, or credential values in
  artifacts
