# case=3 — select and copy lines in a grove duct, over ssh

holder `tmux.remote` · far conf `converged` · intent `copy` · happy · critipath

## .narrative

the human works in a duct on a grove: kitty on the laptop, ssh, tmux on the far box. a provision run printed a failure they want to paste into a task.

super+v behaves exactly as in case=1. kitty cannot see past ssh, so it does not try: it sees the `in_tmux` mark the far tmux wrote back through the pty, and sends tmux's key. the far tmux enters copy-mode; enter, right-alt+j/k, and ctrl+c select and copy. the copy reaches the laptop clipboard through tmux's clipboard relay, the same path an nvim yank takes there.

## .timeline

```
given a duct on a grove whose tmux.conf matches this repo
  when [t0] super+v
    then the far tmux enters copy-mode
  when [t1] enter, right-alt+k ×4
    then a 5-line selection on the far screen
  when [t2] ctrl+c
    then the 5 lines are on the laptop clipboard
  when [t3] ctrl+x
    then copy-mode ends on the far tmux
```

## .the sharp neighbour

a grove whose tmux.conf predates this behavior has no bind for super+v's key: demoed in `case=5.stale-grove-types-a-tilde`.
