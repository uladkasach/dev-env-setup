# case=1 — select and copy lines in a local duct

holder `tmux.local` · intent `copy` · happy · critipath

## .narrative

a test failed in a duct. the stack trace sits twenty lines up, mixed with prompt noise. the human wants exactly the six trace lines in a message, without a mouse drag that overshoots.

they press super+v. tmux enters copy-mode; the cursor sits on the prompt line. right-alt+k six times walks up to the last trace line. enter: that line lights up. right-alt+k five more times: the selection grows upward, one line per press. one too far? right-alt+j takes it back. ctrl+c: the six lines are on the clipboard, and the highlight stays, in case they want one more. enter ends the selection; super+v returns them to the prompt.

## .timeline

```
given a duct (kitty → tmux) with output on screen
  when [t0] super+v
    then copy-mode is on; the cursor is on the bottom line
  when [t1] right-alt+k ×6
    then the cursor moved up 6 lines; no selection yet
  when [t2] enter
    then a line selection begins at the cursor
  when [t3] right-alt+k ×5, right-alt+j ×1
    then the selection spans the lines the cursor crossed, and shrinks on the way back
  when [t4] ctrl+c
    then the selected lines are on the clipboard
    then copy-mode and the selection both stay
  when [t5] enter
    then the selection ends; copy-mode stays
  when [t6] super+v
    then copy-mode ends; the prompt takes keys again
```
