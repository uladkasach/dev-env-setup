# 1.vision — a keyboard line selector in the terminal

## .the contract

one gesture, the same in every terminal window this human uses:

| key | does |
|---|---|
| super+v | open the selector over what the window shows; again, close it |
| right-alt+j / k | move one line down / up |
| enter | begin a line selection at the cursor; enter again ends it |
| ctrl+c | copy the selection, and keep it |
| ctrl+x, super+v, q | leave, with no copy |

the selector belongs to whoever owns the history, so the human never has to know which:

| the window holds | the selector is |
|---|---|
| a tmux duct, local or on a grove | tmux copy-mode |
| no tmux | kitty's scrollback, in a read-only nvim overlay |

## .the outcome world

**before:** to copy six lines of a stack trace, the human drags the mouse, overshoots into the prompt, trims the paste by hand. in a duct, a mouse drag fights tmux for the scroll; on a long trace it must scroll mid-drag.

**after:** super+v, walk to the line, enter, walk to the other end, ctrl+c. the hands never leave the home row; right-alt+j/k are the same arrows they use all day. the selection grows and shrinks one line at a time, so it is exactly the lines meant.

**the aha:** it is the same five keys whether the window is a local duct, a duct on a grove three hops away, or a bare kitty shell.

## .evaluation

**fit to the wish:** every key the wish names does what the wish says, in both holders ("both with and without tmux"). the selector is literal in both: tmux's own copy-mode, nvim's own visual mode.

**pros**
- one gesture across three holders; the human never asks "am I in tmux?"
- the arrows are the ones keyd already maps (`1.1.keybinds`): no new layer
- copy rides the extant paths: tmux's clipboard relay, nvim's `"+y` and its toast
- leave never copies, so an exit cannot overwrite the clipboard

**cons**
- copy-mode keys change for every entry into copy-mode, not only via super+v: enter no longer copies-and-exits, ctrl+c no longer exits (fulcrums F3, F5)
- without tmux, the selector is a separate overlay window, not a mode in place (F1)

**pit of success**
- super+v toggles, so the key that opened the view always closes it
- ctrl+c with no selection leaves copy-mode, so the copy key never strands the human
- the overlay is read-only with no swap file: no edit and no save prompt can happen

## .groundwork

### external research
- kitty 0.47.4: the kitten calls `Boss.call_remote_control`, `Boss.mark_window_for_close`, `Window.user_vars`, `kitty.constants.config_dir`. each one's EXISTENCE is read off the installed kitty via `rhx kitty.api.get`
  - 📌 unverified: that `call_remote_control` runs a `launch` under `allow_remote_control no`. kitty's docs present it as the kitten's path to remote commands; the installed build ships no source to confirm. the first real super+v outside tmux settles it, and a refusal shows kitty's error window (`Boss.show_error`), never a dead key
- kitty's default `clipboard_control` includes `write-clipboard`, read via `rhx kitty.api.get`; kitty.conf sets no override
- COSMIC: `/usr/share/cosmic/com.system76.CosmicSettings.Shortcuts/v1/defaults` binds no super+v; the live `custom` file holds only the binds 3.3.desktop declares, none on super+v
- tmux: the full gesture is proven on the laptop's tmux 3.4 (`prove.visual-select-keys`)
  - 📌 unverified: the version floors (`user-keys`, `copy-selection-no-clear`) are recalled, not checked
  - 📌 inherited: a grove ran tmux 3.2a when measured 2026-09-03 (a dated comment in tmux.conf), not re-measured. the play run on a grove settles both

### internal research
- right-alt+j/k → plain Down/Up: `src/grove.provision/1.system/1.1.keybinds/_.sh` (`[vimarrows]`)
- tmux has no super, so super must be rewritten in kitty: `kitty.conf` (ctrl+super+r block), `gotcha.tmux-carries-no-super-modifier`
- kitty's ctrl+c arrives in tmux as `C-S-c`; ctrl+x arrives as a bare `C-c`: `kitty.conf`, `copy_notify.py`
- the `in_tmux` user var, set by tmux on attach, also over ssh: `tmux.conf` (the in_tmux hooks)
- nvim's visual `<C-S-c>` → `"+y`, with a copy toast: `src/grove.provision/4.terminal/4.5.nvim/init.lua`

## .what is awkward

- **the overlay reads kitty's screen buffer**, so with an app such as nvim on the alternate screen it shows that app's screen, not the shell history behind it. rare: daily windows are ducts
- **a non-kitty terminal** loses ctrl+c-to-copy in copy-mode (it leaves instead); `y` still copies (F4)
