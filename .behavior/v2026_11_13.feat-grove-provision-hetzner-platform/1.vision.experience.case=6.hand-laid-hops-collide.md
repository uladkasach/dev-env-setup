# case=6 — hand-laid hop profiles meet the bundle's fence

feel: sharp · care: critipath

## .narrative

a hetzner grove whose `~/.aws/config` holds a hand-written `[profile ahbode.prep.ehmpath]`, outside any fence — the state a human leaves when they unblock a suite by hand before this route lands. the new tree arrives and `5.13.reach` drives `aws.reach.set`. today that skill copies every line outside its fence through byte for byte (`aws.reach.set.sh:445`), then appends its own fenced `[profile ahbode.prep.ehmpath]` — two sections of one name, the last silently wins, and no apply ever sees the pair.

with this route, the skill checks for an UNFENCED section of the profile it is about to write. it finds one, writes no byte for that row, and stops it with a ✋ that quotes the line numbers and names the one-time fix. the other rows proceed. after the human deletes the hand block, one apply lays the fenced hop.

## .timeline

```
given a hetzner grove, identity live
  and ~/.aws/config holds an unfenced [profile ahbode.prep.ehmpath]
  and no fenced test or prod hop yet
when [t0] rhx grove.provision --mode apply
  then 5.13.reach's prep row prints `✋ [profile ahbode.prep.ehmpath] is already declared outside the grove fence`
  then the text names the file and its line range
  then the fix-text says: delete that block by hand, then re-run — the bundle will own it
  then the hand-laid prep block is byte-equal to its pre-run bytes
  then no fenced prep block was written
  then the test and prod rows lay their fenced hops
  then the run exits non-zero, so the defect is never read as ✔
when [t1] the human deletes the hand block; rhx grove.provision --mode apply
  then the prep hop is laid inside its fence, sts proved
  then the test and prod hops report current, no write
```
