# case=7 — `1.14.updates` from a seat with no root

feel: sharp · care: critipath

## .narrative

`1.14.updates` is box-wide: it installs a package and writes `/etc/apt/apt.conf.d/`. on a grove the camper seat holds no sudo — the ground/camper split puts root on ground alone. camper's apply reaches the bundle; `pkg_can_sudo` answers no. the bundle declines through the extant `bundle.root.declines` (`src/bundle.upgrade.sh:360`), which names the seat that can act. the verify still runs, and it judges the bundle's own drop-in, never the package alone: a box whose bootstrap installed `unattended-upgrades` but not this repo's policy reads ✋ owed, with the root run as its fix. only a box the root seat has applied reads ✔.

the laptop meets the same seat question (F2: the bundle reaches every box). an `rhx` shell has no tty for sudo to ask on, so the decline's fix reads `sudo -v && rhx grove.provision --what 1.14.updates --mode apply`, which a human runs once at a terminal.

## .timeline

```
given a hetzner grove, camper seat, no sudo
  and unattended-upgrades installed by infra's bootstrap
when [t0] rhx grove.provision --what 1.14.updates --mode apply
  then the upsert prints the root decline, with the seat that can run it
  then the verify reports ✋ the owned drop-in differs from the declared policy (or is absent),
    and names the root run as the fix — the package alone is never read as fine
given the same seat on a box that lacks the package
when [t1] rhx grove.provision --what 1.14.updates --mode apply
  then the upsert declines as at [t0]
  then the verify reports ✋ as at [t0], and names the root run as the fix
when [t2] the root seat runs rhx grove.provision --what 1.14.updates --mode apply
  then the package is installed, the drop-in written, the timers enabled ✔
when [t2b] camper's apply runs again
  then the upsert declines, and the verify reads every claim ✔
given a laptop, an rhx shell with no sudo cached
when [t3] rhx grove.provision --what 1.14.updates --mode apply
  then the upsert declines, and its fix reads sudo -v && rhx grove.provision --what 1.14.updates --mode apply
when [t4] the human runs that line at a terminal
  then the drop-in is written and the timer enabled ✔; a second apply writes no byte
```
