# case=1 — hetzner, first plan and apply, identity live

feel: happy · care: critipath

## .narrative

the commander ssh's into the hetzner grove as camper. infra's bootstrap has written `/etc/grove/platform`, and its identity skill has wired `[default]` to the served session on loopback. first he plans: the header names `cloud@hetzner.hetzbot`, the aws lines list the `ambient` profile and three hops as owed, and the file is untouched. then he applies. `5.6.aws` reads `[default]`, leaves it alone, mirrors its endpoint into a fenced `ambient`, and findserts the empty credentials file. `5.13.reach` sees `ambient` answer, then lays one hop per declared env, each `role_arn` + `credential_source = Ec2InstanceMetadata` + the endpoint line `[default]` names, each proved by a live sts call. he runs `svc-chat`'s suite; it reaches prep. a second apply writes no byte.

## .timeline

```
given a hetzner grove, /etc/grove/platform = hetzner.hetzbot
  and camper's ~/.aws/config holds infra's [default] (region + ec2_metadata_service_endpoint)
  and no hop profile yet
when [t0] rhx grove.provision --mode plan
  then the header reads `server cloud@hetzner.hetzbot`
  then 5.6.aws and 5.13.reach report `ambient` and each hop as owed
  then ~/.aws/config is byte-equal to its pre-run bytes
when [t1] rhx grove.provision --mode apply
  then 5.6.aws reports [default] read, never written
  then ~/.aws/config holds a fenced [profile ambient] with the same endpoint
  then ~/.aws/credentials exists, empty
  then 5.13.reach lays ahbode.{test,prep,prod}.ehmpath, each with the endpoint [default] names
  then each hop's sts answer names its target account
  then the [default] section is byte-equal to its pre-run bytes
when [t2] rhx grove.provision --mode apply   # again
  then every aws line reports current, no write
  then the [default] section is still byte-equal
when [t3] AWS_PROFILE=ahbode.prep.ehmpath aws sts get-caller-identity
  then the arn names the prep role
```
