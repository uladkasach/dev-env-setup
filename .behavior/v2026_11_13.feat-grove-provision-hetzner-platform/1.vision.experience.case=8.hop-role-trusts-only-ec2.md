# case=8 — a hop's target role trusts the ec2 grove, not the hetzner one

feel: sharp · care: alterpath (chosen for demo: densest walk, and its fix crosses into another repo)

## .narrative

infra reuses the camp grove role on hetzner (Q8), so most targets trust both groves at once. this case is the exception: a target whose trust policy pins the ec2 service or an ec2 session tag rather than the role itself, so the hetzner session — same role, different path in — is refused. so on the first hetzner apply, `aws.reach.set` writes a correct hop body and then its live proof (`aws.reach.set.sh:651-664`) gets `AccessDenied` on `sts:AssumeRole`. the skill already says this is "an infra ask, not a box defect". the route keeps that loud failure, and adds to it the one fact the hetzner case needs: WHICH principal must be trusted — the arn `[default]` answers as.

## .timeline

```
given a hetzner grove, identity live
  and the prep role's trust policy admits the camp grove role only via its ec2 path
when [t0] rhx grove.provision --what 5.13.reach --mode apply
  then the prep row writes its fenced body
  then the prove step prints `💥 the profile is declared and does NOT answer`
  then the text quotes aws's AccessDenied
  then the text names the principal to trust: the arn `aws sts get-caller-identity --profile default` returns
  then the text names the infra repo to ask
  then the run exits non-zero; no ✔ is printed for prep
when [t1] infra adds the hetzner grove role to the trust policy; rhx grove.provision --mode apply
  then the prep row proves ✔ in the prep account
```
