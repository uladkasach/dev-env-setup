# wish — dev-env-setup — a hetzner box provisions as a grove, not as a laptop

## .what

`grove.provision` knows two platforms, `aws.ec2` and `unix`. a hetzner dedicated box (ubuntu 24.04, reached by its ssh alias, then the tailnet) reads as `unix`, i.e. a laptop. it should provision as any other grove: the same bundles, with the box-specific parts keyed off a third platform.

## .why

ahbode/infrastructure moved the camp grove to a hetzner box (route `v2026_10_20.feat-hetzner-cloud-grove`, pr ahbode/infrastructure#64). its bootstrap does auth only: hostname, the ground/camper user split, the host nftables wall, sshd lockdown, the tailnet join. all else a grove carries is owed by the bundles, run on the box exactly as on an ec2 grove. the commander drives the hetzner grove closed himself, and asked for this tree to exist beside it.

## .what differs from aws.ec2

- no instance metadata, no ssm agent, no hibernate: the box is always on
- aws identity comes from iam roles anywhere through a root-owned signer helper on `127.0.0.1:9911`; camper's `[default]` profile points at it. a bundle must not overwrite that profile
- the cross-account hop profiles (`role_arn` into `<prep-role>` and its peers, with `[default]` as their source) are the bundles' to lay, as on ec2; infrastructure lays none. a hop profile edit must keep `[default]`, and the identity skill keeps every non-default profile
- reach is the ssh alias, then the tailnet; no ssm session
- the `aws.params` vault is gated on `GROVE_ENV_SERVER == *@aws.ec2` and fails closed (`rule.forbid.aws-params-off-ec2.md`); a hetzner box needs its own platform tag there, or its keys move to `os.secure`
- `unattended-upgrades` is installed by the bootstrap today; it belongs in a bundle (host updates), and moves there once the bundle exists

## .the ask

1. a third platform value (e.g. `hetzner` or a generic `offsite`) that `grove.provision` detects or takes as a flag
2. the bundles run on it as on `aws.ec2`, minus the ec2-only steps above
3. a test that a provision on the third platform leaves camper's `[default]` aws profile intact
