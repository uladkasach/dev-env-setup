# 1.vision — a hetzner box provisions as a grove, not as a laptop

## .the correction this vision starts from

the wish says a hetzner box "reads as `unix`". this repo already moved past that:

- `src/grove.env.sh:326` probes `cloud@hetzner.hetzbot` from one declared file, `/etc/grove/platform`
- `GROVE_ENV_SERVER=cloud@hetzner.hetzbot` is the documented override (`src/grove.env.sh:524`)
- a box with no declaration, reached over ssh, is **refused by name** — never called a laptop (`src/grove.env.sh:505-537`)

so ask 1 (a third platform) is met. what is NOT met:

| gap | where | effect on the hetzner grove today |
|---|---|---|
| infra's bootstrap never writes `/etc/grove/platform` | ahbode/infrastructure, `genHetznerGroveBootstrapShell.ts` (0 hits for `grove/platform`) | every unattended run refuses; a human must type the override |
| "is this a grove?" is answered by **IMDS**, not by the platform | `5.6.aws/configure.upsert.sh:45`, `aws.reach.set.sh:278`, and through `ambient` (laid only where IMDS answered) `5.13.reach/configure.upsert.sh:25` | `5.6.aws` declines, `aws.reach.set` calls the box a **laptop**, `5.13.reach` declines ⇒ zero hop profiles ⇒ every suite runs as camp or dies `AccessDenied` |
| the hop body hardcodes `credential_source = Ec2InstanceMetadata` | `aws.reach.set.sh:390,406` | even if forced, a hetzner hop would source from a `169.254.169.254` that does not exist |
| the empty `~/.aws/credentials` findsert sits behind the IMDS decline | `5.6.aws/configure.upsert.sh:51` returns before the findsert at `:146` | aws-sdk v2 under `AWS_SDK_LOAD_CONFIG=1` throws `ENOENT` (the grove-1 measurement, m8) |
| no clamp protects camper's `[default]` | — | infra owns it; no check proves we never write it |
| `unattended-upgrades` has no bundle | bootstrap installs it | host updates live outside the inventory (`rule.require.repo-as-source-of-truth`) |

⇒ the work is not "add a platform". it is **"judge the platform, not IMDS, wherever a bundle asks who this box is — and read each platform's identity endpoint from the platform."**

## .the outcome world

### before

the commander ssh's into the hetzner grove as camper and runs `rhx grove.provision --mode apply`.

```
✋ ConstraintError: cannot tell which machine this is — no platform probe answered
```

he types the override. the tree runs green — every tier gate already treats `cloud@*` right. then a suite in `svc-chat` dies:

```
AccessDenied: arn:aws:sts::<camp-acct>:assumed-role/<camp-grove-role>/… is not authorized
```

`5.13.reach` printed `declined — no ambient identity here` and no one read it. the only way forward is a hand-written `[profile ahbode.*.ehmpath]` block per env — a procedure no repo records. (illustrative: whether the commander has laid such blocks on the live box is unknown; case=6 covers the state if he has.)

```
...
```

a second apply prints the same with no writes. `[default]` is byte-identical before and after both.

### the aha

the grove-1 lesson was "a box must say who it is". hetzner adds the second half: **"…and each platform says it differently."** ec2 says it through IMDS at `169.254.169.254`; hetzner says it through the same protocol at infra's loopback signer, named in `[default]`. once one transformer maps platform → identity endpoint, no aws bundle asks `169.254.169.254` a question only ec2 can answer.

## .the contract we propose

### one transformer: the box's own aws identity endpoint

both grove platforms serve their identity through the SAME protocol — an IMDSv2 endpoint. ec2's sits at `169.254.169.254`; hetzner's is infra's signer on loopback, named in `[default]`. so the one platform delta is **which endpoint**, never which credential shape:

```sh
# .what = the IMDS endpoint that serves this box's own aws identity
grove_env_aws_identity_endpoint
#   aws.ec2          → (empty — the sdk default, 169.254.169.254)
#   hetzner.hetzbot  → read from [default]'s ec2_metadata_service_endpoint, never typed
#   unix             → none; a laptop's identity is a human's sso login — callers decline
```

every body this repo writes keeps `credential_source = Ec2InstanceMetadata`, and on hetzner adds one line, `ec2_metadata_service_endpoint = <that endpoint>`. every caller that today curls `169.254.169.254` to decide "grove or laptop" reads the platform instead:

| caller | ec2 (unchanged) | hetzner (new) | laptop (unchanged) |
|---|---|---|---|
| `5.6.aws` configure | writes fenced `ambient` + `[default]` | writes fenced `ambient` (+ endpoint line) only; **never** `[default]` | declines |
| `5.6.aws` credentials findsert | empty file | empty file | untouched |
| `aws.reach.set` hop body | `role_arn` + `credential_source = Ec2InstanceMetadata` | same + endpoint line | confirm sso profile only |
| `aws.reach.set --env camp` | `credential_source = Ec2InstanceMetadata` | same + endpoint line | — |
| `5.13.reach` gate | `ambient` answers | `ambient` answers | declines |

⚠️ **this departs from the wish's shape on purpose.** the wish names hops "with `[default]` as their source" (`source_profile = default`). 📌 from recall of botocore, unverified: a `source_profile` must yield credentials through the profile providers (static, process, sso, web identity), which exclude instance metadata — so a `[default]` that holds only an endpoint would fail `The source profile "default" must have credentials`. the endpoint shape sidesteps that whatever the answer, and matches ec2's body line for line. the first execution step measures both shapes on the box (F5); if `source_profile = default` works, it remains a clean swap.

⚠️ IMDS stays the right question in ONE place: `5.6.aws` on ec2 still asks it whether a role is **attached** (a cloud box can lack one). the platform answers "which source"; the source answers "does it work".

### `[default]` on hetzner has one writer

infra's identity skill. every bundle and skill here **reads** it and never writes it (`rule.forbid.two-writers-on-one-artifact`). infra's writer keeps every non-default profile (its awk skips only `[default]`), so the two orders converge:

- bundles first, identity skill second → hops kept, `[default]` laid
- identity skill first, bundles second → `[default]` kept, hops laid

the two writers still share one FILE, so a run at the same moment could lose an update: our read-modify-write would put back the `[default]` bytes it read. so each writer here swaps the file atomically (tmp + `mv`, as infra's does), and just before the swap re-reads `[default]`; a change since the read aborts that write with a ✋ and a re-run (c16).

### the clamp (ask 3)

`.play/permanent/prove.hetzner-default-profile-survives.play.sh`:

- a fixture `$HOME` whose `~/.aws/config` holds infra's exact `[default]` shape plus a human profile
- `GROVE_ENV_SERVER=cloud@hetzner.hetzbot`
- drives `5.6.aws configure.upsert`, `aws.reach.set` (body half), `aws.reach.del`, twice each
- asserts the `[default]` section is byte-equal, the human profile byte-equal, and each hop names the endpoint `[default]` names
- proves it bites: a fixture that writes `[default]` on hetzner goes red

plus the live proof `rule.require.prove-changes-on-a-grove` owes: plan · apply · apply on the hetzner grove, and the same on an ec2 grove for regression.

### `1.14.updates` — host updates as a bundle

- provision: `unattended-upgrades` installed
- configure: enabled, security origin only, no auto-reboot (a duct dies on reboot)
- applies on every box, the laptop included (F2): no physical fact keeps a laptop from security updates, and the policy never reboots, so a human still chooses when to restart
- infra drops the install from its bootstrap once this lands (a radio to infra)

- to a friend: *"the hetzner box is a grove like the ec2 one; it just gets its aws badge from a local signer instead of from amazon's metadata service."*
- analogy: two buildings, two badge readers. the doors inside (the hop roles) are the same; only the reader at the front differs. we stopped asking every door "is there an amazon reader here?"

## .evaluation

**goals:**

| ask | met by |
|---|---|
| 1. a third platform | already present; infra's file write closes the unattended gap |
| 2. bundles run as on ec2, minus ec2-only steps | the identity-endpoint transformer; every tier gate already reads `cloud@*` |
| 3. `[default]` survives | the play clamp + live plan/apply/apply |
| (implied) `unattended-upgrades` into a bundle | `1.14.updates` |

**pros:**
- one fact (platform → identity endpoint) in one place. `aws.reach.set`'s host-kind curl retires; `5.6.aws` asks the platform first and keeps IMDS only for its ec2 role-attached check; `5.13.reach` keeps its `ambient` gate, which now answers on hetzner too
- one body shape on both grove platforms (`credential_source = Ec2InstanceMetadata`); hetzner adds one derived line, so no second branch of hop logic
- ec2 behavior is byte-identical; the change is additive per platform
- the house grove, when it comes, adds one row, not three edits

**cons:**
- `aws.reach.set` must source `grove.env.sh` to read the platform; today it is self-contained
- `ambient` on hetzner relies on the sdk to honor `ec2_metadata_service_endpoint` (F1, owed a live measure)

**edgecases and their pit of success:**

| edge | contract keeps it safe by |
|---|---|
| serve not wired yet (`[default]` absent or no endpoint) | `5.6.aws` and `5.13.reach` decline loudly, name infra's identity skill; no file written |
| `/etc/grove/platform` absent | extant refusal, names both fixes |
| a human runs `--for local` on hetzner apply | extant lens halt (`grove.provision._.sh:406`) |
| `aws.params` on hetzner | the gate reads the TIER, `cloud@*`, so a hetzner camp grove reads `aws.params` as an ec2 one does; a local or house grove fails closed to `os.secure` (`rule.require.aws-params-on-camp-groves-only`, T16) |
| a stale hop with `credential_source = Ec2InstanceMetadata` on hetzner | `aws.reach.set` compares the body, rewrites it in its fence |
| a hand-laid, unfenced `[profile X]` of the name a hop would write | `aws.reach.set` refuses that row (✋, line range, one-time fix), writes no byte — today it would append a silent twin (`aws.reach.set.sh:445`) (F4) |
| `1.14.updates` from camper, no sudo | extant `bundle.root.declines`; the verify still reports present or owed |
| `aws.reach.set` run by hand on a laptop over ssh | it reads `GROVE_ENV_SERVER` when a provision exported it, else derives once; the derivation refuses an ssh seat with no platform, so a laptop-over-ssh hand run now needs `GROVE_ENV_SERVER=local@unix` — where today IMDS silence called it a laptop. a regression in reach for one rare seat, traded for one parser |
| a hop's target role trusts only the ec2 grove's role | extant live sts proof fails loud (`aws.reach.set.sh:651-664`); this route adds the principal to trust — the arn `[default]` answers as |
| `[default]` edited by hand on hetzner | not ours; read as is, never repaired |

## .what is awkward

- **every hetzner body this repo writes — `ambient` and each hop — copies `[default]`'s endpoint.** the copy is read at apply time, never typed, yet it is still a copy: if infra moves the port, every copy goes stale until the next apply. each verify compares its copy to `[default]` and names the drift. the alternative that holds no copy, `source_profile = default`, fails on the box (F5, measured: `The source profile "default" must have credentials.`) — so the copy is the price of a shape that works
- **`aws.reach.set` gains a dependency on `grove.env.sh`.** right by `rule.require.conform-to-sdk-environment` (one derivation), but the skill ran standalone before
- **the platform file is a second writer's seat.** the boot lays `/etc/grove/platform` over ground from the registry (`git.grove.set --platform`, S8 · T10), as a findsert: a line infra laid first is kept when it agrees and refused by name when it differs, never overwritten
- **`1.14.updates` reaches the laptop too (F2).** no physical fact splits it from a grove; the cost is one `sudo -v && rhx grove.provision --what 1.14.updates --mode apply` at a terminal
