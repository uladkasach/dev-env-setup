# 🌙 dream: the codediff resize probe reads red under load, judged by a timer

kind: fix · owner: dev-env-setup · caught 2026-11-07

## .the cue that fired

the full suite on a shared box read `prove.codediff-resize-renders-once` red: its control arm
saw 3-4 renders per burst where it wants 1. five lone runs read 1. the fix rode in #189's branch
for a round, and a peer review held it as a change of a locked criterion outside that wish, so it
was taken back out to land on its own.

## .the gap, precisely

- the control arm runs the shipped 80ms debounce against five resize steps 20ms apart. on a
  loaded box a step gap stretches past 80ms, the timer fires mid-burst, and the arm reads 2+.
  the mechanism works; the clock judged it
- the old-per-step arm asserts exactly 5. a slow event loop once added a 6th render, so it can
  go red for the same clock reason

## .the shape of the fix

measured on a grove-free laptop seat, each arm green on five runs, two of them concurrent:

- **probe**: read the shipped window first (`local shipped_ms = _G.codediff_resize_debounce_ms`),
  then set the control window to 1000ms. after the burst, wait on the render itself
  (`vim.wait(5 * window_ms, function() return renders > 0 end, 10)`), then one full window more
  (`vim.wait(window_ms + 200, …)`). emit `debounce_shipped_ms=` on the world row
- **play**: the control arm asserts the shipped window ≥ 50ms (`MIN_SHIPPED_MS=50`) — a held
  key's repeat gap is ~30-40ms, so a shorter window renders per step. the old arm asserts
  `n >= STEPS` (5), one render per step as a floor
- bite: init.lua's window set to 10ms → the shipped assert red; restored to 80 → green
- the `arm` call gains `< /dev/null`

the open question a reviewer raised, owed an answer in that pr: this trades a live proof at
exactly 80ms under load (the flake) for a proof of the mechanism plus a read of the shipped
value. if the live 80ms proof must stay, the alternative is a burst whose step gaps are driven
by the probe's own clock rather than `vim.wait`, so load cannot stretch them.

## .why it is not done in this round

#189's verification stone judged it a change of a locked criterion, outside the wish. it is
clean on its own: two files, no caller.
