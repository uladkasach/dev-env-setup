dream = a laptop that locks itself when it is truly idle, and never when it is
        merely quiet

## .what

today `3.3.desktop` section 5 declares all three idle timers `None`, so the laptop
never locks on its own. that is a deliberate choice with a stated reason, and it is
also the only reason a walk-away leaves the rack unlocked.

the dream is to turn idle-lock back ON — and to have it distinguish **idle** from
**quiet**, so it never fires on the case it was disabled for.

## .why it is off today

`configure.upsert.sh:89-91` states the reason, and the reason is sound:

> a long build or a detached grove run is not idleness
> a screen that sleeps mid-run costs the session it was meant to show

so the timer was not disabled out of dislike for locking. it was disabled because
**COSMIC's idle clock reads the keyboard, and the work this box does most often
touches no keyboard for an hour at a stretch.** a `git.grove.provision boot` is ~10
idle-looking minutes; a nvim treesitter build, a docker pull, a watched CI run — each
is indistinguishable from an empty chair.

⚠️ and one of those is worse than an interrupted build: **a lock mid-`--reply` send
puts a password prompt where the duct expects a pane.** that is `term=eat` at the
compositor layer.

## .why it should come back

the box holds `@all.camp.GITHUB_TOKEN`'s reader, a yubikey-backed `SSH_AUTH_SOCK`,
and every grove's reach. redteam round 24 graded the laptop the more-trusted side of
every boundary it examined. an unattended unlocked session is the one ingress that
needs no CVE, no MITM, and no supply chain — just a walk past.

⇒ the current state is an **accepted risk with no expiry date**, which is the shape
this repo distrusts most.

## .the shape a safe version takes

the split the whole dream turns on:

| the box is… | keyboard | should it lock? |
|---|---|---|
| **idle** — no human, no job | quiet | **yes** |
| **quiet** — a build, a duct run, a watched CI | quiet | **no** |
| busy | active | no (already handled) |

so the timer is not the mechanism. the **inhibitor** is.

### the primitive that already exists

`systemd-inhibit --what=idle` holds an idle inhibitor for the life of a command.
logind exposes the held locks via `loginctl show-session -p IdleHint`, and COSMIC's
idle daemon is an ordinary consumer of that signal.

⇒ so the wiring is: **the things that make the box quiet should say so**, and the
timer can then be honest.

### the candidate seams, ranked by how much quiet each explains

1. **`git.grove.send --reply` / `--detach`** — the duct. wrap the wait in an idle
   inhibitor, so a grove run cannot be interrupted by a lock and cannot have its
   pane eaten by a password prompt
2. **`grove.provision` itself** — an apply is minutes of no keyboard, on the box
   being converged
3. **`git.repo.test --what integration|acceptance`** — a long suite
4. **a watched release** — `git.release --watch` polls for up to 15 minutes

⚠️ **do not reach for a blanket "inhibit while any terminal is open."** that is the
disable, spelled longer, and it would re-arrive at today's state through a door
nobody could see.

## 🛑 .what this must not become

- **a repair play.** the timer is machine state, so it is a bundle
  (`rule.forbid.repair-plays`). `3.3.desktop` already owns it — section 5 is the
  site, and the inhibitor wiring belongs beside each long-running caller
- **a second declaration of the timeout.** one holder. if the value lands in both
  `3.3.desktop` and a brief, that is m.9 and it will drift
- **an unproven claim that it works.** the clamp must go red with the property
  absent (`gotcha.a-check-that-cries-wolf-gets-silenced`). a verify that reads
  `screen_off_time` and stops has proven the *declaration*, never the *behaviour*

## .the measurements owed before it is turned on

1. **does COSMIC honour `systemd-inhibit --what=idle`?** unproven. cosmic-idle may
   read logind's `IdleHint`, or it may keep its own clock. this is the load-bearing
   unknown and everything else waits on it
2. **is there a lock timer distinct from `screen_off_time`?** the bundle declares
   three keys; if COSMIC has a fourth (`lock_after` or similar) then today's "idle
   screen-off and suspend disabled" is a partial claim wearing a whole one's ✔
3. **what does a lock do to a live duct pane?** measure it once, on purpose, before
   it happens by accident

## .the shape of "done"

```
• idle screen-off and suspend disabled            ← today
• screen locks after N idle minutes; a duct run,
  an apply, and a long suite each hold it off ✔   ← the dream
```

plus a play that runs a bounded fake-long-job, confirms the inhibitor is held, drops
it, and confirms the lock arms again — seen red before it is trusted green.
