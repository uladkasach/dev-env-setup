# 🌙 dream: keynav's login autostart reaches headless groves

- kind: fix (this repo)
- owner: `1.1.keybinds`
- caught 2026-11-17

## .the cue that fired

a duct reborn by the boot (`boot_seat_duct_reborn`) starts a LOGIN shell, and the hetzner
camper pane then printed, on every prompt:

```
Error: DISPLAY environment variable not set
[1]+  Done                    ( keynav && echo "keynav started" || echo "keynav already up" )
```

## .the gap, precisely

- `1.1.keybinds/configure.upsert.sh` (`grove_provision_1_1_keybinds_keynav_autostart`) appends
  `(keynav && …) &` to `~/.profile` on every seat it runs on
- neither the bundle nor `1.system/_.sh` gates it by tier, so a cloud grove (ec2 or hetzner)
  carries it too — and a cloud grove has no display
- the same holds for the keyd remap itself: a cloud grove has no keyboard (it declines for
  want of root on camper, then ground writes it)
- harmless to a verdict (`--reply` redirects its own payload), but it is noise in every
  login shell and a desktop tool asked on a box with no desktop

## .the shape of the fix

1. gate `1.1.keybinds` on the tier that has a keyboard and a display: `local@unix`, with a
   decline line beside its reason (`repo.overview`, `.$server`)
2. on a seat that is not `local@unix`, remove the bundle's own block from `~/.profile` (the
   `# grove: keynav autostart at login` marker, and the legacy unmarked line) — idempotent
3. a play arm: a cloud seat with the block → the apply removes it; a laptop keeps it
4. prove plan / apply / apply on a grove

## .why it is not done in this round

the fix touches a bundle outside this route's diff and owes a cleanup write on every extant
grove, a clamp, and a grove proof of its own. it blocks no step: no human acts on it, and no
verdict reads it. so it fails the CLEAN test for a fix pulled into this stone.
