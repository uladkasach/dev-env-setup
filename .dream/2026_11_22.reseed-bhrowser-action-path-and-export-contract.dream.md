## .the gap, precisely
1. `--play .temp/x.play.ts` is read as a PACKAGE name; `--play ./.temp/x.play.ts` is looked up
   against the skill's own dir inside node_modules. only an absolute path works
2. `howto.browser-action-playbooks` documents `export default async (page, ctx)`; the skill refuses
   that and demands `export const action = async ({ page, browser })`
3. `browser.start` refuses with "chromium not found" and hints a raw `npx playwright install
   chromium`; this repo paved `rhx browser.chromium.set` for it, upstream has no skill

## .the shape of the fix
- anchor `--play` at the caller's cwd (`path.join(process.cwd(), play)` when not absolute) before import
- keep the loader's `export const action` contract and fix the brief to match; no `export default` fallback
- ship a `browser.chromium.set`-shaped skill upstream, and name it in the start refusal
