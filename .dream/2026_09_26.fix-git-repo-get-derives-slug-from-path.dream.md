## .the gap, precisely

`git.repo.get` holds the org↔dir correspondence **twice**, in opposite directions, and
each half assumes the path spells the slug:

| # | site | shape |
|---|---|---|
| 1 | `lookup_repo` → `local local_path="$git_root/$slug"` | FORWARD — joins a slug into a path |
| 2 | `get_all_local_repos` → `local rel_path="${repo_path#$git_root/}"` | BACKWARD — derives a slug from a path |

⇒ measured against the alias, each half fails in its own direction:

```sh
# 1. the TRUE github slug finds no local clone, and falls through to cloud
rhx git.repo.get lines --in aether-auctions/svc-x --paths 'readme.md'
#   → reads ~/git/aether-auctions/svc-x, absent
#   → "cloud <url>", so it works, SLOWER, and over the wire
#   → and `--tree` fails outright: `fail_tree_not_local`, since worktrees are local-only

# 2. the repo list reports a slug GITHUB DOES NOT HAVE
rhx git.repo.get repos --repos 'aether/*'
#   → reads ~/git/aether/svc-x, emits slug `aether/svc-x`
#   → a cloud query on that slug 404s; a human who copies it gets a dead name
```

🛑 **neither half errors.** #1 quietly takes the slow path and loses `--tree`; #2 prints a
well-formed slug that does not exist. that is `rule.forbid.failhide`'s shape — an honest
report about the wrong subject.

## .the shape of the fix

> **the clone's own remote is the authority on its slug. its path never was.**

both halves already have the clone in hand, so the remote is one command away:

```sh
git -C "$repo_path" remote get-url origin
#   → https://github.com/aether-auctions/svc-x.git  |  git@github.com:aether-auctions/svc-x.git
#   → strip the host and the .git → aether-auctions/svc-x
```

- **`get_all_local_repos`** — emit the slug the REMOTE names, not `${repo_path#$git_root/}`.
  the path becomes what it should have been all along: where the clone sits, not what it is.
- **`lookup_repo`** — try the direct join first (it is right for every un-aliased org, which
  is nearly all of them), and on a miss, ask the clones. a dir-name index built once per
  invocation from `get_all_local_repos` answers it with no extra `git` calls.

⚠️ **a `GIT_REPO_DIR_ALIASES` env var is the wrong fix**, and worth a name so it is not
reached for: it would be a SECOND holder of a fact the clone already carries, free to drift,
and it would need a declaration on every box
(`gotcha.a-check-that-cries-wolf-gets-silenced`, m.9). the remote is the one holder and it
travels with the clone.

⚠️ **a `.git`-less checkout has no remote to read** — a grove's pushed `src/` is exactly
that shape. `get_all_local_repos` already keys on `.git`, so such a dir is out of scope
today; keep it so, and fall back to the path when the remote read returns empty. name it
as a fallback, never as the primary.

## .why it is not done in this round

**SAFE**: ✋ no. it is another repo's skill, on its own release train, with its own
snapshots and acceptance tests. an edit from here reaches no consumer.

**CLEAN**: ✋ no. `get_all_local_repos` feeds four subcommands (`repos`, `files`, `lines`,
and the `--repos` fan-out); a change to what it emits ripples through every one of their
snapshots.

⇒ so it is a reseed, per `rule.always.scope-onetime-lessons-to-the-behavior`: the fix's
home is `ehmpathy/rhachet-roles-ehmpathy`, and a tree adopts only what is scoped to itself.

## .what holds meanwhile

- `--in aether/svc-x` (the DIR slug) works fully, local, with `--tree`
- `--in aether-auctions/svc-x` (the TRUE slug) works over the cloud path, and loses `--tree`
- no data is at risk either way; the cost is one slow path and one wrong slug
