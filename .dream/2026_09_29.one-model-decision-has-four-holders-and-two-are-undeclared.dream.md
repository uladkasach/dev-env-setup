## 🔴 .the gap — one DECISION, FOUR holders, and no reader compares them

🛑 **the src grep above finds two. the LIVE FILE holds two more.** measured 2026-09-30, a read of
`~/.claude/settings.json` on this laptop:

| # | holder | mechanism | declared by a bundle? |
|---|---|---|---|
| 1 | `2.7.aliases` | `ANTHROPIC_MODEL`, a shell export | ✔ `bash_aliases.sh:61` |
| 2 | `5.3.brains` | `.model` in `~/.claude/settings.json` | ✔ via `GROVE_BRAIN_CLAUDE_MODEL` |
| 3 | the **live file** | `.env.ANTHROPIC_MODEL` in that same settings.json | 🔴 **NO** |
| 4 | the **live file** | `.env.CLAUDE_CODE_SUBAGENT_MODEL` (an adjacent axis) | 🔴 **NO** |

all four answer *"which model does this box run?"*, and no verify in either bundle reads any
other's value — so a box can export one model, declare a second, and hold a third in the very
file the second patches, and pass every claim on the page.

⚠️ and the drift is worse than a plain m.9, because the holders do not merely disagree — they have
different **precedence**, so which one wins is a property of how the session was launched.
a reader who edits the one they found and sees no change has no line anywhere naming the others.

## 🔴 .rows 3 and 4 are UNDECLARED, so they are also UNREAPABLE

`5.3.brains/configure.upsert.sh`'s patch names three env keys — `DISABLE_AUTOUPDATER`,
`DISABLE_UPDATES`, `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` — and no model key at all. the patch
merges, so:

- rows 3 and 4 were placed by some hand and are in **no inventory**
- no verify reads them, so no run reports them
- and the patch only ADDS, so no run removes them either

⇒ that is shape 11 of `rule.require.one-command-provision`: *a bundle that only ADDS, so HISTORY
outranks the tree.* the box holds MORE than the tree declares, and **every declared row still
passes**, which is why a green page cannot see it.

⚠️ so row 3 is the sharpest of the four: it sits **inside the file row 2 governs**, at a
different key, under a different precedence, and the bundle that owns that file does not know it
is there.

## ⚠️ .the precedence question now has a DATA POINT, and it is not yet a claim

measured 2026-09-30 in one session:

| what | value |
|---|---|
| `.model` in the live settings.json | `claude-opus-5-5[1m]` |
| `.env.ANTHROPIC_MODEL` in the live settings.json | `claude-opus-5-5[1m]` |
| the repo's declaration, both holders | `claude-opus-5[1m]` |
| 🔴 what the running session reported itself as | **`claude-opus-5[1m]`** |

the session ran the value NEITHER settings holder carries, and the value the **shell export**
carries. that points at the export as the winner — the opposite of step 2's leading hypothesis.

🛑 **it is a data point and NOT a finding, on purpose.** three causes render alike, and this read
parts none of them: the export won · the session's self-report is not a faithful read of what it
booted · the settings file was edited after the session booted
(`rule.require.trust-but-verify`, `gotcha.my-own-note-became-my-evidence`).

⇒ so it does not settle step 2. what it does is raise the cost of a GUESS at step 2, which is
the whole reason step 2 demands a measured box rather than a read of the docs.

## .why it is not done in this round

the SAFE/CLEAN test (`rule.always.fix-forward-under-scouts-honor`) fails on CLEAN, for a reason
this repo declares as a rule rather than a preference:

> **a bundle that reads another bundle's declaration breaks
> `rule.require.bundle-as-sole-declaration`.**

so `2.7.aliases` cannot reach `GROVE_BRAIN_CLAUDE_MODEL`, and `5.3.brains` cannot reach the
export. the collapse needs a decision about WHERE the fact lives, and that ripples into the
shared runtime (`src/grove.*.sh`) — three files, two bundles, and a new shelf.

🟡 the judgment to defer is recorded at the declaration itself, in `5.3.brains/_.sh`'s block,
so the next reader of the hoist finds it without this file
(`rule.always.itemize-the-fulcrums-you-best-guess` — the record half, with no route bound to
carry an inventory).

## 🔴 .the prior question — is the SHELL EXPORT owed at all?

the collapse is the second question. the first is cheaper and may retire the whole dream:

> **once `.model` is declared in `~/.claude/settings.json`, what does `ANTHROPIC_MODEL` add?**

`define.claude-code-config.md` documents the export as *"the global default model claude code
boots with"* — written before `5.3.brains` declared `.model` at all. if settings.json now
governs, the export is a second answer to a settled question, and the fix is a **delete**
rather than a collapse.

⚠️ **that is a read, not a guess, and it is not free:** the two shelves differ on WHEN they are
read (`configure.upsert.sh`'s own ⚠️ block draws that line for the prompt-suggestion flag), so
the honest test is a box with the export absent and `.model` declared, and a session that
reports which model it booted.

## .the shape of the fix — and the ORDER is load-bear

1. **settle the model VALUE first.** the repo declares `claude-opus-5[1m]`; the laptop's live

   `2026_09_28.claude-pin-sits-below-rhachets-own-brain-cli-floor.dream.md`
