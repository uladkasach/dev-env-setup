# 🌙 dream: one reader per fact across grove.provision — tmux binary, pinned clones, linger, verified fetch

kind: refactor · owner: dev-env-setup · caught 2026-10-23, from `.behavior/v2026_10_23.fix-grove-crew-users-linger` (r11, enroll-impl-arch-defects)

## .the cue that fired

a peer lane (r11) read the 2.8.tmux pin and the new linger bundle and found four seams where one
fact has two or more readers. each is a nitpick on that route; none ships a harm today.

## .the gap, precisely

1. **tmux binary readers** — `2.8.tmux/_.sh`: `binary_state`, `binary_version`, `binary_meets_owed`
   each ask `tmux -V` again. one verify asks it 4 times (6 on an adrift box), each bounded at ~7s,
   so a wedged binary costs ~40s per plan. `unreadable` rides in the version string, not the state
   enum, so each caller must test it (the route added two such guards)
2. **pinned clones** — `tpm_upsert` and `plugins_upsert` each run state → move aside →
   `git_clone --at`; `tpm_state` and `plugin_state` differ by one `-x`. three aside-stamp formats
3. **linger** — `5.8.docker/provision.upsert.sh:126-140` copies the roster loop with its own
   `enable-linger`; `5.18.openhours` reads `$USER` via `loginctl show-user`, which fails for a seat
   with no session (the reader `1.6.7.linger` replaced for that reason)
4. **verified fetch** — `pin_fetch` is one more `web_fetch` + `web_verify_sha256` pair, beside
   starship, yq, usql, nvim, kitty, fonts

## .the shape of the fix

1. `binary_version` stays the one communicator; add pure `binary_state_of <version>` (with an
   `unreadable` state) and `binary_meets_owed_of <state> <server>`. the verify reads once
2. `pinned_clone_state <dir> <sha> [entry]` + `move_aside <path>`, one stamp format
3. no lift is needed: `grove.provision._.sh` sources every bundle file at every depth, and only
   dispatch follows `--what`, so `grove_provision_1_6_7_linger_roster`, `_seat_lingers` and
   `_seat_grant` are always defined. docker and openhours call them in place of their own loop
   and `loginctl show-user`, and still converge when run alone
4. `web_fetch --sha256 <digest>` that refuses to leave unverified bytes
5. `1.6.8.coredump`'s upsert runs `sysctl --system` to set one knob, so any runtime-tuned knob
   reverts to its file value; apply only the package's drop-in via `systemd-sysctl <file>` —
   the drop-in's name and path on jammy are unread
6. `GROVE_LINGER_DIR`, `GROVE_LINGER_PASSWD`, `GROVE_CORE_PATTERN_PATH` redirect production
   readers to fixtures; a ✔ read through one should name the fixture
7. `pin_fetch`, `pin_build`, `pin_install` read `$2`/`$4` by position under named flags
   (`rule.forbid.positional-args`); the play stubs read them the same way, so both move together
8. split the pin into its own root-owned leaf under `2.8.tmux` (the pins, `binary_*`, `pin_*`,
   `pin_floor`, the `cloud@*` gate), so a failed build no longer returns before tpm, plugins and
   conf converge in `$HOME`. `servers_*` stays callable, since every bundle file is sourced.
   🟡 ranked first since i006: phases chain, so a non-zero `provision.upsert` marks `2.8.tmux`
   broken and its `configure.upsert` is skipped on that apply — only a separate slug stops that
9. one `plugin_root_of_conf` reader: `tpm_upsert` and `plugins_upsert` hardcode
   `$HOME/.tmux/plugins`, `provision.verify` reads `dirname(tpm_bin_of_conf)`, and both
   configure phases ask a live server. they coincide while tpm derives its root from its own
   entrypoint; upsert and both verifies should ask the one reader, the asked root a cross-check

10. one walk per live socket: `verify_live_servers` asks each socket six times (version,
    status-right, default-terminal, panes, clients, plus `configure.verify`'s root ask). one
    communicator returns a record per socket; pure readers grade the records; a mute socket is a
    field, so no claim can mis-count another
11. one pin table, a row per pinned clone (name, url, sha, entry): it replaces `plugin_names`,
    `plugin_url`, `plugin_at`, the tpm sha, `tpm_state`, `tpm_upsert`'s URL literal, the
    `tpm=present` carve-out and the `tpm_install` path; items 2 and 9 fall out of it
12. `1.6.4.keyrackd`'s verify asks `grove_provision_1_6_7_linger_seat_lingers "$USER"` again,
    so `--what 1.6.4.keyrackd` alone is not green over an unlingered seat

🟡 i008 sharpened item 8: the cascade also fires on a CREW seat — its `bundle.root.owns`
declines the pin, its verify ✋s `adrift`, the bundle is marked broken, and its
`configure.upsert` (conf, plugin pins, live-server source) is skipped until the ground seat
builds the pin, again on every pin bump. item 5's drop-in is `/usr/lib/sysctl.d/50-coredump.conf`
on noble (read i008: `core_pattern`, `core_pipe_limit`, `suid_dumpable`); jammy's path is unread

each needs its plays re-run red/green, and 3 touches two bundles the route never opened.

## .why it is not done in this round

safe, but not clean: each ripples into bundles and callers the crew-crash route never touched,
on a stone whose commit quota holds one use. the route fixed the false comment in
`1.6.7.linger/_.sh` that claimed no other bundle reads linger.
