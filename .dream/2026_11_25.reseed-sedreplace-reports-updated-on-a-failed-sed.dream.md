# 🌙 dream: sedreplace must fail loud on a failed sed, and keep a symlink a symlink

kind: reseed · owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, `sedreplace`) · caught 2026-11-25

## .the cue that fired

a rename of one bundle slug across this repo, in one session, hit both defects.

## .the gap, precisely

1. **a failed sed reports success.** a `--new @stdin` whose value held a newline made sed print
   `unterminated 's' command` twice. the skill still printed `└─ updated` with `matches: 2`, and
   the file held no change. the header said `💥 failed with an error`, and the tree under it said
   `updated`: two verdicts, one of them false.
2. **a symlink becomes a regular file.** two tracked symlinks matched the pattern through their
   target. after `--mode apply`, git reported each as a type change (`T`): the skill wrote the
   target's edited bytes over the link. the link was lost, and a second copy of the target sat
   in its place.
3. (minor) `--glob '<one path>'` lists that one file twice, so every count reads double.

## .the shape of the fix

- exit non-zero, and print no `updated` line, when any sed call exits non-zero
- skip a symlink (or edit its target once, via the real path) — never write through the link
- dedupe the file list before the count
- clamp each: a newline replacement, a symlink in the glob, a single-path glob

## .why it is not done in this round

the skill lives in another repo; a fix here would be a local patch over a package this repo
consumes. this repo repaired its own two links by hand and continued.
