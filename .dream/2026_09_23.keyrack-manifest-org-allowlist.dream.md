dream = a keyrack manifest declares an ARRAY of eligible orgs, defaults to the first,
        and accepts `--org` for any other member of that allowlist

## ✔ .status = DISPATCHED — ehmpathy/rhachet#559, 2026-09-26

## .the wish

```yaml
# .agent/keyrack.yml
org:
  - ahbode      # the default — what `@this` resolves to
  - aether      # allowlisted; reachable via --org aether
```

- **bare read** → the first entry. every extant call keeps its behavior, so the change is
  additive and no consumer is touched
- **`--org aether`** → permitted, because it is on the allowlist
- **`--org whodis`** → still refused, because it is absent from it

a scalar `org:` stays valid and means a one-member array.

## .why — the defect it closes

`@this` resolves to the manifest's ONE `org:` line, so a repo whose fleet spans orgs can
address exactly one of them. today that is a wall with no legal door:

```
rhx git.grove.wake grove-aether-v20260921
  🔐 ahbode.camp.AWS_PROFILE  ·  status: absent 🫧
```

the rack holds `aether.camp.AWS_PROFILE` the whole time. and the explicit read refuses:

```
rhx keyrack get --owner ehmpath --org aether --env camp --key AWS_PROFILE
  ✋ ConstraintError: --org 'aether' does not match manifest org 'ahbode'
     hint: use an org under 'ahbode', or pass --org @all
```

⚠️ **the verdict is `absent 🫧`, which means "no credential exists"** and here means "you
asked the wrong org". the loud path exists (`--org`) and is absent from the route a human
travels — every `git.grove.*` skill reads with no `--org` at all. so the manifest is the
only lever, and it gives no signal when it is too narrow.

## .why the three workarounds are each a defect

| lever | why it fails |
|---|---|
| flip `org:` to `aether` | silently repoints every OTHER slug. measured: 3 of this repo's 6 declared slugs exist in BOTH orgs — incl. the seaturtle push token — so a swap makes `git.commit.set --push` authenticate as the wrong org, with no error |
| `keyrack set` under the wrong org | a second holder of a fact the right org already holds, and `set` has no entry-only mode — it OVERWRITES |
| refile under `@all` | `@all` means "belongs to NO org" (`rule.require.github-token-at-all-camp`). an aws account profile belongs to exactly one, so `@all` states a falsehood — and can hold only one camp account's value forever |

each encodes a second org in a slot built for one. the allowlist gives the slot a second
seat instead.

## .the shape of the change

1. **parse** — `org:` accepts a scalar or a sequence; a scalar is a one-member array
2. **default** — `@this` resolves to `org[0]`, so every extant call is unchanged
3. **permit** — `--org <x>` succeeds when `x ∈ org[]`; the ConstraintError fires only for
   a non-member, and its message names the allowlist rather than one word
4. **extends** — an extended manifest's orgs presumably UNION into the allowlist; worth a
   decision, since `.agent/keyrack.yml` here extends three manifests that each declare
   `org: ehmpathy`

## .the consumer this unblocks, concretely

a grove record could then carry its org, and the `git.grove.*` credential block would pass
it through:

```sh
rhx keyrack get --owner ehmpath --org "$GROVE_ORG" --env camp --key AWS_PROFILE --value
```

one axis on the record, one flag on the read. that flag is still refused upstream, so the
one-line form above does not work today.

## ⚠️ .a FOURTH door exists, and it is not a defect — measured 2026-09-28

this dream read *"a multi-org grove fleet is unreachable through keyrack"*. that was true
when it was written and is false now. the **scratch gitroot** reaches a foreign org
legitimately, and it is proven:

```
rhx git.grove.rack.unlock grove-aether-v20260921 --org aether --env camp --key AWS_PROFILE
```

both of its arms answered — the foreign-org read through a scratch gitroot, and the native
read when the target org IS the checkout's own. the grove it unblocked went from 7 claims
to 0 on the same rung (`term=keyrack.gitroot`).

⇒ **the mechanism:** keyrack scopes a named-org read to the CHECKOUT it runs in, so the
read is performed from a throwaway gitroot whose manifest declares the target org. no
extant slug is repointed, no value is copied, and no second holder is created — which is
what parts it from the three defects above.

### 🟡 so why the upstream fix is still owed

| the gitroot costs | the allowlist would cost |
|---|---|
| a scratch dir composed per read | no scratch at all |
| a shared operation every caller must reach through (`_rack_get`) | one flag on the plain call |
| a manifest scope still one-org-per-checkout, worked around rather than widened | the slot gains a second seat |

⇒ the door is open and the wall is still there. this dream stays **dispatched**, and its
urgency drops: the capability is in hand, so `#559` now buys ergonomics rather than reach.

⚠️ the raw `aws --profile` call remains shut — `rule.require.reach-credentials-through-keyrack`
calls it a blocker, and it was built and reverted 2026-09-23.

## .where it lands

upstream in **rhachet** — this is keyrack's manifest parser and its org resolver, not a
concern this repo can fix (`rule.require.solve-at-cause`). the adjacent in-repo defect is
already tracked as `ehmpathy/rhachet#502`, which covers the SILENCE (`absent 🫧` for a
wrong org); this dream covers the CAPABILITY (one repo, several eligible orgs).
