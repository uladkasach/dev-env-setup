# 🌙 dream: a laptop's https push has a credential helper after keyrack

- kind: fix
- owner: this repo, `2.2.git`
- caught 2026-11-22

## .the cue that fired

`rhx git.commit.push --mode apply --auth as-human` failed on the laptop: `git-credential-keyrack`
declined (no camp token on a local seat), no helper followed, and git died on a username prompt.

## .the gap, precisely

`2.2.git` declares `credential."https://github.com".helper` = the keyrack helper on every seat. it
serves only a camp grove. on `local@unix` it declines by design, and the bundle declares no next
helper, so an https push from a laptop has no credential path at all, even with `gh auth login` live.

## .the shape of the fix

on `local@*`, add gh's helper after keyrack (`git config --global --add
credential."https://github.com".helper '!gh auth git-credential'`), and let `configure.verify`
grade both values, in order. a clamp in a temp HOME: keyrack declines, gh's stub answers, the
push reaches a local bare remote.

the upstream twin: ehmpathy/rhachet-roles-ehmpathy#1471 (`--auth as-human` never reaches the push).

## .why it is not done in this round

it changes global git config on every laptop, a bundle this PR does not own (seed S6: the PR ships
only this behavior). it is the human's call whether the laptop fix or the upstream fix goes first.
