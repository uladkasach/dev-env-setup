# 🌙 dream: qualify both claude launchers' refusals — the class in the header, the exit code by who fixes it

kind: repair · owner: dev-env-setup · caught 2026-10-23

## .the cue that fired

a peer review of `5.3.brains` (route `v2026_10_20.fix-home-claude-settings-lock`, stone 5.1, i003, lane
`ergo-friction-hazards`) flagged the `claude.latest` shim: its refusals open with a bare `✋` and exit 1,
where `rule.require.qualified-error-headers` wants `✋ ConstraintError:` / `💥 MalfunctionError:` and
`rule.require.exit-code-semantics` wants 2 for a caller fix.

## .the gap, precisely

two launchers carry the same refusal shape, word for word:

- `src/grove.provision/2.shell/2.7.aliases/bash_aliases.sh:587` — the default `claude` launcher
- `src/grove.provision/5.devtools/5.3.brains/_.sh` — the `claude.latest` shim heredoc, which mirrors it

each refusal is a bare `✋ …` and `exit 1`. some name a caller fix (an absent candidate, a sudo-gated
user manager), so their class is `ConstraintError` and their exit should be 2.

## .the shape of the fix

change both launchers in ONE edit, so the default and the candidate never disagree:

- each refusal header gets its class: `✋ ConstraintError:` where the human acts, `💥 MalfunctionError:`
  where the box failed
- each `exit 1` behind a constraint becomes `exit 2`
- the shim's render changes, so `5.3.brains`' verify reports it stale and one apply converges it
- check any caller that reads the launcher's exit (the systemd scope wrapper passes claude's own code
  through — a refusal code of 2 must not collide with a claude exit the caller reads)

## .why it is not done in this round

SAFE: yes. CLEAN: no — the stone is the home settings strip and lock. the default launcher sits in
`2.7.aliases`, a bundle this branch does not touch, and to change one launcher alone would split the
pair the shim exists to mirror. a fulcrum is not owed: the defer is for scope, and the shape is plain.
