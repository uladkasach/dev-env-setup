# 🌙 dream: an unbalanced `--what` payload wedges a duct, and 97 names no cause

- kind  = fix — `.agent/repo=.this/role=any/skills/git.grove.send.sh`
- owner = whoever next touches `git.grove.send --reply`
- caught 2026-09-13

## .the cue that fired

one probe was sent with an **unquoted** brace:

```sh
rhx git.grove.send grove-ahbode-v20260901 --reply --within 90 \
  --what 'tmux -L default display-message -p #{config_files}'
```

`--reply` wraps the payload in `{ … }` to capture it. the payload's own `{`
never closed, so zsh dropped to a **continuation prompt** and stayed there.

every send after it arrived as a continuation LINE rather than a command. five
in a row returned **97**, and the pane held this:

```
∙ mkdir -p "$HOME/.local/state/grove.reply" ; … { uptime ; } > …
∙ mkdir -p "$HOME/.local/state/grove.reply" ; … { uptime ; } > …
∙ …
```

## .the gap, precisely

97 is correct and it is **one word for a class**
(`gotcha.the-duct-returns-the-send-not-the-answer`): *the transport had a fault,
there is no answer*. it does not part these:

| the state | the repair |
|---|---|
| the duct refused the send | retry |
| the box went quiet | wake it |
| `--within` elapsed on a long command | raise `--within` |
| 🔴 **the pane sits at a continuation prompt from a PRIOR send** | `duct.reboot` |

⚠️ the last row is the one that **poisons every later send**, and it is the one
row a caller cannot infer. the message even suggests the wrong repair —
*"the command may simply need longer: `--within <secs>`"* — which is what a
caller reaches for, and it never lands.

⇒ the honest read cost five sends and a `duct.read` to reach. the correct verb
(`duct.reboot`) was one call and it names itself *"THE ANSWER TO A STUCK DUCT"*.

## .the shape of the fix

two moves, and the first is the cheap one:

- **refuse the payload up front.** `--what` is already parsed for control
  operators (`;`, `&&`, `||`); add a brace/quote balance check beside it
  - an unbalanced payload can never succeed, so a refusal costs a caller no
    capability and saves the pane
- **name the state in the 97 message.** before it gives up, read the pane's last
  line; a `∙`/PS2 lead means the shell is mid-construct
  - ⇒ then the fix-text says `rhx duct.reboot --on <uri>`, not `--within`

⚠️ do NOT widen 97 into a table of codes. the contract is deliberate — one code
for every transport fault, so a caller written today cannot misread a code added
tomorrow. the repair belongs in the **message**, never in the number.

## .why it is not done in this round

- **safe?** no — `git.grove.send` is the one reach every grove skill rides, and
  its payload guard exists to keep the pretooluse hooks meaningful. a balance
  check written in haste either refuses valid payloads or opens the guard
- **clean?** no — it touches the arg parser, the reply harness, and the give-up
  message, which is three seams for a defect that fires on a malformed input

⇒ and the round's ask was continuum eradication, which is closed on both boxes.
this wedge was self-inflicted by one unquoted probe and cleared by one
`duct.reboot`.

## .what it costs while open

every measurement taken after the wedge returns 97 with no verdict. a caller who
reads 97 as *"the box is slow"* will raise `--within` and wait, or — worse —
treat the silence as an answer. this round it nearly shipped a report built on
five reads that had already failed.
