# 🌙 dream: infra's backup line reads a first run at work, never `✗ STALE · never`

kind: reseed · owner: ahbode/infrastructure · caught 2026-11-20

## .the cue that fired

the first scheduled run on an ec2 grove outlasted an hour, and `rhx grove.backup.get`
read `✗ STALE · never` over a healthy run. this repo's line now reads `⏳ the first run is at work`;
infra's renderer is a second copy that reads the status file alone.

## .the gap, precisely

`git.grove.stats` and `grove.backup.operations.sh` in ahbode/infrastructure print `status=ABSENT`
when `/var/lib/grove-backup/status.json` is absent. a first run writes that file only at its end, so
the stats line cries wolf for the whole of a first run on a full box.

## .the shape of the fix

in the same remote read, also print `systemctl show -p ActiveState --value grove-backup.service`.
the renderer reads `activating` with no status file as `⏳ the first run is at work`.

## .why it is not done in this round

the renderer lives in another repo; this repo files the ask through infra's radio.
