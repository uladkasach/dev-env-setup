## task 1 — one malformed host record bricks the whole keyrack  (into: ehmpathy/rhachet)

**title:** `keyrack: one malformed host record bricks the entire manifest (no CLI recovery)`

**what:** `keyrack` bricks entirely when the host manifest holds a single malformed host record.
every subcommand that loads the manifest (get / set / del / unlock / list / status / fill) throws
before it does any work — even the `del` that could remove the bad record. unrecoverable via CLI.

**repro:** a stale host entry whose `vault` (or any enum field) is no longer in the schema — e.g.
`ehmpathy.prep.DEMO_PARAM` written by an older version — makes every call throw
`BadRequestError: keyrack host manifest has invalid schema`. `keyrack del --key DEMO_PARAM` fails
with the same error (the loader validates the whole manifest before the delete). chicken-and-egg brick.

**root cause:** `src/access/daos/daoKeyrackHostManifest/index.ts` `get()` does a strict
whole-manifest `safeParse`. `schemaKeyrackHostManifest.hosts` is
`z.record(z.string(), schemaKeyrackKeyHost)`, so ONE bad host entry fails the entire parse. a
per-machine store that accrues records across versions hits this on any enum change / field rename.

**fix (verified locally in the global build):** keep the strict happy path; on failure, salvage —
re-parse the manifest shell with lenient hosts (`z.record(z.string(), z.unknown())`), then validate
each host on its own and drop invalid ones loud (stderr warn line), so every valid credential stays
reachable. verified: `keyrack status` now loads all valid records, warns on the dropped one, and
`set`/`del` work again so the bad record can be removed via the normal CLI.

**severity:** blocker-class — a single stale record from any version skew renders the entire
per-machine keyrack inoperable, with no CLI recovery path.

## task 2 — `@all` (cross-org) credentials are write-only: no read path  (into: ehmpathy/rhachet)

**title:** `keyrack: @all-org credentials can be set but never unlocked or read`

**what:** `keyrack set --org @all` stores a cross-org credential under host slug `@all.<env>.<key>`,
but there is no read path, so the value is write-only:

- `keyrack unlock` has NO `--org` flag. it sources slugs from the cwd repo's `keyrack.yml` and
  resolves the cwd org (e.g. `ahbode.<env>.<key>`), never the `@all.<env>.<key>` host entry. it has
  an env=all fallback (`getEnvAllFallbackSlug`) but NO org=@all fallback.
- `keyrack get` accepts `--org @all` and shows the `@all` slug, but `getKeyrackKeyGrant` only reads
  os.daemon (post-unlock) + os.envvar, never the vault. since unlock cannot populate the daemon for
  `@all` keys, get always reports `absent` — even though the os.secure vault file exists on disk
  (`inferKeyrackKeyStatusWhenNotGranted` would say `locked`, but the daemon path returns `absent`
  first).

net: `set --org @all` succeeds; the credential can never be unlocked or retrieved.

**black-box repro (no internals, re-proven 2026_07_30):** the same slug round-trips as absent —
```
echo "sk-ant-oat-ROUNDTRIP-TEST-VALUE" \
  | rhx keyrack set --owner ehmpath --org @all --env prep --key K --vault os.secure --mech PERMANENT_VIA_REPLICA
# => 🔐 keyrack set (org: @all, env: prep) └─ @all.prep.K   ✅ success
rhx keyrack get --owner ehmpath --org @all --env prep --key K --value
# => status: absent 🫧   ❌ identical slug, immediately after a successful set
```
`keyrack list --json` DOES show the `@all.prep.K` host record — so the manifest write is fine; the
read path is the sole failure. this is reproducible with plain `keyrack set`/`get`, no alias, no
unlock step — the round-trip contract itself is broken.

**internals-level repro:** from a repo whose `keyrack.yml` org is `ahbode`:
```
echo "$secret" | rhx keyrack set --owner ehmpath --org @all --env prep --key K --vault os.secure --mech PERMANENT_VIA_REPLICA   # ok, writes @all.prep.K
rhx keyrack get    --owner ehmpath --org @all --env prep --key K --value                                                        # status: absent (wrong)
rhx keyrack unlock --owner ehmpath --env prep --key K                                                                           # resolves ahbode.prep.K, absent
rhx keyrack unlock --owner ehmpath --env prep --org @all --key K                                                               # error: unknown option '--org'
```

**root cause:** `src/domain.operations/keyrack/session/unlockKeyrackKeys.ts` host-config lookup has
an env=all fallback but no org=@all fallback; and the unlock CLI command
(`src/contract/cli/invokeKeyrack.ts`) exposes no `--org`. combined with `getKeyrackKeyGrant` never
reads the vault, `@all` creds have no read path.

**fix (partial hotfix applied locally in the global build):** added an additive org=@all fallback to
`unlockKeyrackKeys` host-config lookup (symmetric to the env=all fallback): when a key's cwd-org slug
and its env=all variant are both absent from the host manifest, try `@all.<env>.<key>` then
`@all.all.<key>`. purely additive — normal keys (host config present under their org) untouched.
upstream should also: (a) add `--org` to the unlock CLI, and (b) decide whether get should surface a
stored-but-locked `@all` key as `locked` (not `absent`) so the status is honest.

**note for brains.auth:** even with the unlock org=@all fallback, `brains.auth.usage` reads via plain
`keyrack get`, which only hits daemon/envvar — so usage still needs an `unlock` step first (or a
keyrack "read one secret from vault" path). open design point: keyrack is built around
unlock-then-use sessions, not one-shot secret reads.

**severity:** blocker-class for any repo-independent (global) credential use case, which is exactly
what `--org @all` advertises.

### ✅ local fix applied + verified (a verified reference for upstream)

**file (in the rhachet package):**
`src/domain.operations/keyrack/session/unlockKeyrackKeys.ts` — the per-slug host-config lookup.

**the change:** after the extant `env=all` fallback and before the `absent` push, add a symmetric
`org=@all` fallback. purely additive — a normal key (host config present under its own org) never
reaches it.

```js
// try fallback to org=@all version of the key (cross-org global credentials)
// .note = symmetric to the env=all fallback above; lets `set --org @all`
//         credentials (repo-independent) be unlocked from any repo, since the
//         host entry lives under @all.<env>.<key> not <repoOrg>.<env>.<key>
if (!hostConfig) {
    const firstDot = slug.indexOf('.');
    const orgAllSlug = firstDot >= 0 ? '@all' + slug.slice(firstDot) : null;
    if (orgAllSlug) {
        hostConfig = hostManifest.hosts[orgAllSlug];
        if (hostConfig) {
            effectiveSlug = orgAllSlug;
        }
        if (!hostConfig) {
            // org=@all + env=all fallback
            const orgAllEnvAllSlug = getEnvAllFallbackSlug({ for: { slug: orgAllSlug } });
            if (orgAllEnvAllSlug) {
                hostConfig = hostManifest.hosts[orgAllEnvAllSlug];
                if (hostConfig) {
                    effectiveSlug = orgAllEnvAllSlug;
                }
            }
        }
    }
}
```

**verified (2026_07_30) against the live global build (rhachet@1.44.5):** from an `ahbode`-org
repo, `rhx keyrack unlock --owner ehmpath --env prep --key BRAINS_AUTH__…__vladatahbode` now
resolves `@all.prep.…` (was `ahbode.prep.…` absent) and `keyrack get --org @all … --value`
returns the stored token. `brains.auth.usage` then runs end to end for all three subs.

**✅ patch retired (2026-08-30):** stock `rhachet@1.47.3` carries the `@all` read path, verified
live from this worktree under both `rhx` and `npx rhx` — no local edit. the hand-patch of the
compiled `dist/` is dead weight; if this path ever breaks again, **check the installed version
first** and upgrade, never re-patch.

> the reason the patch was never the fix: it lived in `node_modules/…/dist/`, which any upgrade
> replaces. it was lost that way once already (1.44.4 → 1.44.5). a repair that a routine upgrade
> can silently undo is a countdown, not a cure.

**upstream should also** (unchanged from above): (a) add `--org` to the unlock CLI so `@all` can be
targeted explicitly; (b) decide whether `get` should surface a stored-but-locked `@all` key as
`locked` not `absent`; (c) add a regression test that stores an `@all` key and reads it back from a
repo whose keyrack.yml org is NOT `@all` (clamp the edge case).

## task 3 — radio should refer the human to dreams when it is blocked  (into: ehmpathy/rhachet-roles-bhuild)

**title:** `radio: when a push is blocked, point the human at catch.dream as the fallback`

**what:** when `radio.task.push` (or pull) is blocked for ANY reason — global block, org block, local
block, absent auth — its error should teach the human to catch the intended task as a dream instead,
so the intent is not lost. today a blocked push only prints the grant hint
(`radio.uses --global allow`) and drops the task on the floor if the human cannot grant right away.

**why:** a blocked radio is exactly when intent is most at risk of loss. the dreamer role
(`catch.dream`) already exists as the "capture now, build later" mechanism. radio should hand off to
it on every block, so a blocked dispatch becomes a caught dream, not a dead end.

**where:** `rhachet-roles-bhuild` — the repo that owns the `dispatcher` (radio) and `dreamer`
(catch.dream) roles. update the radio block-path output (`radio.uses` / `radio.task.push` blocked
branch) to append a line like:

```
🌙 blocked — catch it as a dream so it is not lost:
   rhx catch.dream --name <slug>
   (dispatch it via radio once the block is lifted)
```

**severity:** nitpick-class ergonomics, but high leverage — it closes the "intent lost while blocked"
gap and makes the radio↔dream handoff a paved path.
