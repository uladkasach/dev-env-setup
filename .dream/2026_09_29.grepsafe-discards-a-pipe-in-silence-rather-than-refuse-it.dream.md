# 🌙 dream: `grepsafe` DISCARDS a piped stdin in silence, where a refusal would cost one line

- kind   = reseed
- owner  = a driver — the guard is four lines, and the repo that owns the skill is not this one
- caught = 2026-09-29

## .the cue that fired

three times in one session, on one box, by one reader who had already read the brief that names
this trap:

```sh
rhx keyrack list --owner ehmpath | rhx grepsafe --pattern 'BEAVER' --context 5
```

the pipe was dropped, the repo was searched, and the rows returned were real hits in the briefs
that discuss the BEAVER credential. **short, on-topic, and about the wrong subject entirely.**

⚠️ the third bite is the measurement that matters. by then the reader KNEW the defect —
`gotcha.grepsafe-ignores-stdin` is a tracked brief in this repo — and still took it, because the
call reads correctly and the output looks like an answer.

## .the gap, precisely

`grepsafe` searches files under `--path` (default `.`) and reads no stdin. so a pipe into it is a
**no-op on the input and a full-tree grep on the output**:

| what the caller asked | what the skill answered |
|---|---|
| does this stdout carry `BEAVER`? | does this REPO carry `BEAVER`? |

⇒ the two questions share a pattern and share no other part, so one verdict cannot serve both
(`gotcha.a-check-that-cries-wolf-gets-silenced`, q7 — one pattern spanning two claims).

🔴 **and the extant brief's tell does not fire on this shape.** it says *"if a line count is wildly
larger than the file you meant to search, the pipe was ignored"* — which caught a 269MB blob read
in 2026-07-31. a domain word like `BEAVER` returns a handful of rows, so there is **no size signal
at all**, and the reader is handed no cue to distrust.

## .why it is not done in this round

**the skill is not this repo's to declare.** `grepsafe.sh` lives under
`repo=ehmpathy/role=mechanic`, and this repo consumes it. a local patch would be a second reader
over another package's contract, which is the braided-trail shape
(`rule.always.reuse-pavement-before-improvise`).

🟡 and the cheap half WAS taken in this round: the brief gained the skill-stdout shape by name, the
reason its size tell does not fire, and the working pattern —

```sh
rhx keyrack list --owner ehmpath | rhx teesafe --into .temp/rack.list.txt
rhx grepsafe --pattern 'BEAVER|vault|mech' --path .temp/rack.list.txt
```

⇒ so the deferral is about OWNERSHIP, never about size. the guard itself is four lines.

## .the shape of the fix

1. 🔴 **REFUSE a piped stdin, loudly. do not read it.** a read is the larger change and invites a
   second question (what does `--path` mean when stdin is present?); a refusal settles the defect
   with no contract growth:

   ```sh
   if [[ ! -t 0 ]] && [[ -p /dev/stdin ]]; then
     echo "✋ grepsafe reads FILES under --path; it does not read stdin" >&2
     echo "   the pipe would be discarded and the whole tree searched instead" >&2
     echo "   land it first —" >&2
     echo "     <cmd> | rhx teesafe --into .temp/out.txt" >&2
     echo "     rhx grepsafe --pattern '<p>' --path .temp/out.txt" >&2
     exit 2
   fi
   ```

2. ⚠️ **the fix-text is the load-bear half**, not the refusal. a bare *"stdin unsupported"* leaves
   the reader to invent the tee hop; the four lines above hand it over
   (`rule.require.errors-name-the-fix`)

3. **prove it BITES.** a refusal that no run exercises is unproven — pipe something in and confirm
   exit 2, then give a real `--path` and confirm exit 0
   (`gotcha.a-check-that-cries-wolf-gets-silenced`, its discriminate-both-directions corollary)

4. sweep the peer: **`globsafe` takes a `--pattern` too.** whether it shares the defect is unread,
   and a guard on one of a pair is the sweep-missed-the-sibling shape

## 🟡 .why a REFUSAL rather than a READ

a read looks more generous and is the worse contract:

| | refuse | read stdin |
|---|---|---|
| the silent wrong answer | 🔴 gone | 🔴 gone |
| `--path` when stdin is present | untouched — the flag keeps one sense | ambiguous: which wins? |
| the change | one guard | an input axis, plus every caller's expectation of it |

⇒ and a refusal is honest about what the skill IS: a **path** searcher. a pipe into it was always
a misread of the contract, so the repair is to say so rather than to widen the contract to absorb
the misread.

## .what this dream does NOT claim

it does not claim a pipe into `grepsafe` is a common need. the landed-file pattern is fine and is
arguably better — the artifact is re-readable. what it claims is narrower: **a discard in silence
is the defect, whatever the right call shape turns out to be.**
