# 🌙 dream: prove.codediff-refresh-stays-quiet's red controls no longer bite

- kind: red-main
- owner: a separate tree (nvim / codediff), never `beav/feat-tailscale-on-every-machine`
- caught 2026-10-31

## .the cue that fired

`prove.codediff-refresh-stays-quiet` is intermittent. on 2026-10-31 it failed in the full suite
(`36 passed · 5 declined · 5 failed`), failed again alone, then passed in the next full suite
(`37 passed · 5 declined · 4 failed`). a red control that bites only some runs is a timer race.

## .the gap, precisely

the live arm holds. the red-control arms do not bite:

```
✋ builds_per_noop_refresh=0, expected gt 0     # the arm before 'old-full-render'
arm 'old-full-render': idle_refreshes=1 window_ms=10000
✋ rows_per_noop_rebuild=0, expected gt 0
```

a red control that reads 0 cannot prove the live arm's 0 means "quiet". the cause is the one
`prove.codediff-single-pane-keeps-the-view` shows (#177): the arm counts on an idle refresh inside a
fixed window. the window now sees one refresh or none, so the old render path never runs.

## .the shape of the fix

- drive the no-op refresh in each red arm on purpose (one explicit `refresh` call), never wait on
  the idle timer inside `window_ms`
- assert `idle_refreshes ≥ 1` as its own claim before the per-refresh counts are read, so a silent
  timer reads as "the arm did not run", never as "quiet"
- fix it together with #177; both rest on the same timer

## .why it is not done in this round

this PR touches no nvim or codediff file. the director ruled out-of-PR reds a red main: catch them as
dreams, fix them in a separate tree, and make no edits here.
