# 🌙 dream: `catch.dream --help` still errors, a month after a brief recorded that it does

- kind   = reseed
- owner  = a driver — the skill is `repo=bhuild/role=dreamer`'s, and the fix is one arg check
- caught = 2026-09-29

## .the cue that fired

`.dream/.readme.md` is the one document that tells a traveler how to catch a dream. it names a
skill. the skill's own help does not answer:

```
$ rhx catch.dream --help
🪨 run solid skill repo=bhuild/role=dreamer/skill=catch.dream
   └─ 💥 failed with an error

⛈️  error: input invalid
   └─ --name must be a string, got undefined
```

⇒ `--help` is parsed as an ordinary flag, so the required `--name` reads as absent and the skill
refuses. a traveler who reaches for help gets a **type error about a flag they did not pass.**

## 🔴 .the gap is not the help. it is that a RECORD did not move it

`philosophy.pavement-saves-nature` (foreign — `repo=bhrain/role=learner`) carries this exact
measurement, dated **2026-08-31**, as its worked example. it states the sharp part in its own words:

> the sharp part is not that the instruction was wrong — it is that the failure was LOUD and the
> defect survived anyway.

re-measured here **2026-09-29**. it is still loud and still alive, **29 days later.**

⚠️ **so this dream's subject is narrower than the absent help.** the brief already diagnosed it
correctly and named the cause — *"it persisted because nobody invoked it"* — and that diagnosis
turned out to be incomplete: it HAS been invoked since, the failure was seen, the brief was read,
and no repair followed.

| the brief's account | what 29 days added |
|---|---|
| an unread brief drifts, because a read is how a pothole is found | 🔴 the pothole was found, recorded, cited, and **still not filled** |

⇒ the cure a record alone cannot supply is an **owner**. a measurement with no owner is a fact, and
a fact does not fix a skill.

## .the gap, mechanically

`--name` is validated before the arg set is inspected for `--help`, so the help path is unreachable
on a skill with any required flag. this is the shape `rule.require.help-on-demand` (ergonomist)
grades a blocker:

> a command with no `--help` (or `-h`) = **blocker**

and `rule.require.skill-help` (enroller) says the same from the author's seat.

🟡 **the skill itself works.** only its help does not — which is the worse half, because a traveler
who cannot read the contract guesses at it, and `catch.dream` WRITES a file under a name it
normalizes. a guessed `--name` leaves an artifact nobody meant to create.

## .why it is not done in this round

**it is not this repo's skill to declare.** `catch.dream` lives under
`repo=bhuild/role=dreamer`, and a local patch would put a second reader over another package's
contract (`rule.always.reuse-pavement-before-improvise`, the braided-trail shape).

🟡 and the cheap half WAS taken here: `.dream/.readme.md` now states the defect inline, quotes the
error, and names the two flags a traveler needs — so the one document that sends a reader at this
skill no longer sends them at a wall. it also lost its
`./node_modules/.bin/rhachet run --skill …` call form, which taught the shape
`rule.require.invoke-rhx-by-its-bare-name` forbids.

## .the shape of the fix

1. **handle `--help` BEFORE required-arg validation.** it is a sequence fix, never a new feature —
   every skill with a required flag has this defect by construction if help is checked second

2. **what the help owes**, per `rule.require.help-on-demand`: the one-line `.what`, the usage shape
   with required vs optional marked, each flag and its default, and one copy-paste example —

   ```
   catch.dream — catch a dream before it fades, into .dream/

     usage:
       rhx catch.dream --name <slug> [--open <editor>]

     inputs:
       --name   the dream's slug, kebab-cased for you   (required)
       --open   open it in an editor after the write     (default: do not open)

     example:
       rhx catch.dream --name one-jq-patch-holds-eight-rows-hostage
   ```

3. 🔴 **sweep the ROLE, never this one skill.** the defect is in the CHECK SEQUENCE, so every
   `repo=bhuild/role=dreamer` skill with a required flag has it. a fix to `catch.dream` alone
   leaves the class open and reads as though it were closed

4. re-prove by a BITE in both directions: `--help` answers and exits 0; a call with no `--name`
   and no `--help` still refuses

## .what this dream does NOT claim

it does not claim the skill is broken. `--name` is honored and the findsert works — the claim is
narrower: **its contract is unreadable from the surface**, so the only way to learn it is to read
another repo's source, which is the detour `--help` exists to retire.

⇒ and it does not claim the brief that recorded this was wrong. it was right and it was not
enough, which is the durable half worth a carry forward: **a measurement with no owner does not
become a repair.**
