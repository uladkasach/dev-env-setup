# 🌙 dream: `trust.gen`'s `--org` cannot be proven to reach the rack on a healthy box

- kind   = prove
- owner  = `.this` (`git.grove.trust.gen`, and a probe beside it)
- caught = 2026-09-28

## .the cue that fired

`--org` was carried onto `git.grove.stop` and `git.grove.trust.gen` in one round. `stop` was
proven in **both** directions on a live box:

| the run | what it showed |
|---|---|
| `--org 'bad;rm'` | the clamp halts, exit 2, and names the character class it wants |
| `--org no-such-org` | keyrack echoes `--org no-such-org` on its own command line — the flag demonstrably reached it |
| `--org ahbode` | the rack answers, and the account guard reads `✔ matches the registry` |

`trust.gen` reached only the first two rows, and the second is **weaker there**: the run
completed with no keyrack read at all, because the skill short-circuits first.

## .the gap, precisely

the credential read sits behind a precondition a converged box does not present:

```sh
# every scanned key is already trusted, and none changed → findsert is a no-op
if [[ -z "$ABSENT" && -z "$CHANGED" ]]; then
  echo "   └─ 🌊 already trusted ($TRUSTED_ALREADY) — no change"
  exit 0
fi
…
if [[ "$TRUST" == "verified" ]]; then
  if [[ -z "${AWS_ACCESS_KEY_ID:-}" ]]; then
    …rhx keyrack get --owner ehmpath --org "$ORG" …     # ← the line under test
```

so the `--org` axis is exercised on a box **only** where a host key is absent or has changed —
which is a first trust, or a rebuild. every healthy box exits at `🌊 already trusted`.

⇒ what IS proven today: the flag parses, the clamp bites and passes, the two-rung ladder runs
without error, and the skill completes unchanged. what is NOT: that `$ORG` reaches the keyrack
command line **in this skill**, and that the `🌙` beneath it renders.

### 🛑 .why an argument from the sibling is not a proof

the two call sites are byte-identical in shape, and `stop`'s is proven live. that is a real
reason to expect `trust.gen`'s to work and **not** evidence that it does —
`gotcha.a-check-that-cries-wolf-gets-silenced` names the whole family of defects where a reader
is correct about one subject and wrong about the one in front of it.

⚠️ and the cost here is the subtlest of the three org sites: the credential feeds the
**boot-record read**, and that branch is **tolerant by design**. a wrong or absent org finds no
boot record, so the attestation is **skipped rather than failed** — the run proceeds, writes a
`known_hosts` entry, and grades the key on a weaker basis than the caller asked for. no row
reddens.

## .why no ordinary run can close it

each cheap route was tried and each fails for its own reason:

| the route | why it does not serve |
|---|---|
| a `--force` / `--rescan` flag | none exists, and to invent one adds a lever whose only caller is a test |
| a second seat (`<grove>.ground`) | a seat RIDES ONE TUNNEL, so it dials the same `localhost:<port>` and hits the same entry |
| a temp `$HOME` with an empty `known_hosts` | `KNOWN_HOSTS="$HOME/.ssh/known_hosts"` is hardcoded, so the fixture must also stand in `.ssh/config`, `.aws`, `.git.forest`, and the checkout — and the raw `mkdir`/`cp`/`ln` that would build it are not paved (`rule.forbid.adhoc-shell`) |
| remove the live entry, re-run, restore | the restore needs a WRITE to a file outside the repo, and every paved writer here is repo-bound, so the only path left is shell redirection |
| a second registry entry dialing `127.0.0.1` | a new `[127.0.0.1]:<port>` key WOULD read absent — and it costs a registry write, an ssh-config write, and a brush with the one-port-one-grove guard |

⇒ **the honest instrument is a discrimination probe** — `rule.forbid.repair-plays`, exception 2:
break the subject on purpose, watch the check, restore on a `trap … EXIT`.

## .the shape of the fix

a tracked, permanent probe — `prove.trust-gen-reads-the-rack-with-its-org` — under exception 2's
four conditions:

1. the restore is a `trap … EXIT`, never a last line
2. it REFUSES to run if the entry it means to remove is already absent, so it restores only what
   it found
3. the break is MINIMAL — drop the ONE `[localhost]:<port>` entry for the named grove, leave every
   other line of `known_hosts` untouched
4. it reports whether the restore took

the arms:

| arm | the run | it must |
|---|---|---|
| 0 | entry absent, `--org no-such-org`, `--mode plan` | print the keyrack line carrying `--org no-such-org`, then the `🌙` naming `env=… org=…` |
| 1 | entry absent, correct org, `--mode plan` | reach the box read with no `🌙` at all |

⚠️ both arms are `--mode plan`, so the skill itself writes no entry; the probe's own removal is the
only write, and the trap owns it.

### 🛑 the one design question a human owes first

every extant discrimination probe in this repo runs against a **grove**. this one's subject is the
**laptop's own `~/.ssh/known_hosts`** — the file that decides whether every ssh on this machine
trusts what it dials. a probe that removes a line there, on the box that holds the rack, is a
different blast radius from one that breaks a package on a disposable box.

⇒ so the probe is owed a decision, not merely a write: does it run here at all, or only against a
grove seat whose `known_hosts` is expendable? `prove.keyrack-peer-probe-bites` already carries the
precedent — *"writes destructively; it needs a grove and must not be aimed at a laptop"*.

## .why it is not done in this round

- **SAFE?** no. the probe's subject is this machine's trust store, and the question above is
  unsettled. a probe written before that decision would encode the riskier answer by default.
- **CLEAN?** no. it is a new tracked play plus its four conditions, and the round's diff is three
  edited reach skills.

⇒ so it is a **catch**, and the local remedy is that the next `trust.gen` run against a **fresh or
rebuilt** grove exercises this path for real — `#3`'s ahction grove is exactly such a box, and it
is the cheapest place to watch the line before the probe exists.
