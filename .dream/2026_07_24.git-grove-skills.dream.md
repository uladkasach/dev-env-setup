## .what

add a `git.grove` skill family — `git grove wake|list|add|del|get` — as a globally-installed
rhachet skill, dispatched from a thin git alias, to sit beside this repo's `git tree *`.

grove = a machine (host) that holds trees. see the glossary:
`.agent/repo=.this/role=any/briefs/grove/reach/define.git-forest-grove-tree.md`.

## .why

- the grove box exists (`ssh -p 2222 ec2-user@localhost`) but no skill manages its lifecycle
- `git tree *` manages branch workspaces on the local machine; `git grove *` is the missing
  sibling that manages the machines themselves
- wake/hibernate/ssm-auth is declastruct/typescript — it must live as a skill, never as bash
  in `bash_aliases.sh` (that would be a symptom-level reimplementation of the infra logic)
- global rhachet skills ride to every machine, including the groves — the parity goal needs
  the logic portable, not trapped in a synced dotfile

## .the dispatch shape

thin git alias → global rhachet skill, one skill with subcommands (mirrors
`git.branch.rebase begin|continue|abort` and `git.commit.uses set|get|del`):

```sh
# install_env.pt2.shell.git.aliases.sh — thin registration only
git config --global alias.grove '!rhx git.grove'
```

```bash
git grove wake grove-1     # → rhx git.grove wake grove-1
git grove list             # → rhx git.grove list
git grove add grove-1 --at ec2-user@host:port
git grove get grove-1
git grove del grove-1
```

`rhx <skill>` already resolves globally-installed roles — no `-g` flag needed.

## .the layering

| piece | home |
|-------|------|
| `alias.grove = '!rhx git.grove'` | `dev-env-setup` (this repo) — registration only |
| `git.grove` skill (`wake/list/add/del/get` + registry) | **ghlitch** role package (global) |
| wake / hibernate / ssm-auth primitive | **infra** (declastruct), composed by the ghlitch skill |
| forest/grove/tree glossary | `dev-env-setup` briefs (done) |

dependency direction: ghlitch's `git.grove` composes the infra wake primitive; bhuild's
dispatcher (`radio.task.*`) later composes `git.grove` to send clone work to a grove. grove
is the primitive; dispatcher depends on it, never the reverse.

## .the subcommands

| subcommand | what | needs aws? |
|------------|------|------------|
| `add <name> --at <user@host:port>` | register a grove in the local registry | no |
| `list` | forest view: all groves + status | no |
| `get <name>` | show one grove + how to reach it | no |
| `del <name>` | unregister a grove | no |
| `wake <name>` | wake a hibernated grove, wait-until-ssh-ready | yes — infra primitive |

## .the registry

one file per grove (matches the ductwork-hosts dream — no write conflicts):

```
~/.git.forest/
└── groves/
    └── <name>.json     # { user, host, port, type, status, addedAt }
```

lines up with `~/.ductwork/hosts/` so the grove⇄host correspondence stays clean.

## .migration note

once `git grove` proves the thin-dispatch pattern, lift the legacy bash outliers the same
way: `git_alias_tree`/`git_alias_grab` bash functions → `rhx git.tree`/`rhx git.grab`
skills. then the whole `git.*` family is uniform thin dispatchers, and `git tree` can gain
grove-awareness (the `git-forest` dream) because it becomes a portable skill.
