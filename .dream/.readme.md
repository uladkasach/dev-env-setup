# .dream/ 🌙

this folder catches dreams — transient visions that strike in flow state.

the shape a dream owes, its four kinds, and WHEN to catch one rather than fix it now all live in
the **`repo=bhrain/role=driver`** briefs — `term=artifact.dream`,
`rule.always.fix-forward-under-scouts-honor`, and its pair
`rule.always.catch-dreams-for-followups`. ⚠️ those three are FOREIGN: they are booted into a
session, and no path in this checkout reaches them. a dream is the second-best outcome — first ask
whether the fix is safe and clean enough to do now.

## how to use

catch a dream:
```sh
rhx catch.dream --name "my-idea"
```

⚠️ **`--help` does not answer on this skill** — it reads as an absent `--name` and errors:

```
$ rhx catch.dream --help
⛈️  error: input invalid
   └─ --name must be a string, got undefined
```

the skill itself works; only its help does not. `--name` is the one required flag, and
`--open <editor>` is optional. ⇒ the defect is `repo=bhuild/role=dreamer`'s to fix, and it is
dreamt at `.dream/2026_09_29.catch-dream-answers-no-help-a-month-after-it-was-recorded.dream.md`.

review dreams: browse this folder — no index is kept, deliberately, so no second holder can drift
from the filenames.

graduate to behavior:
```sh
rhx init.behavior --name "my-idea"
```

🛑 **`rhx <skill>`, never `./node_modules/.bin/rhachet run --skill <skill>`.** both forms stood
here until 2026-09-29, and the long one is the one a reader copies
(`rule.require.invoke-rhx-by-its-bare-name` · `rule.require.install-via-procedures` — an example
that contradicts its own rule teaches the opposite, with the rule's authority behind it).
