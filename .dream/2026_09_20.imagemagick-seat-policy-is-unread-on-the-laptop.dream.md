# 🌙 dream: make `4.5.nvim`'s imagemagick policy REACH the reader, or drop the claim that it does

- kind  = repair — `src/grove.provision/4.terminal/4.5.nvim/`
- owner = whoever next touches `4.5.nvim`'s imagemagick half
- caught 2026-09-20

## .the cue that fired

`rhx grove.provision --what 4.5.nvim --mode apply` raised, on the laptop:

```
✋ imagemagick hands a postscript file to ghostscript
   it said: probe.eps PS 8x8 8x8+0+0 16-bit sRGB 192B
   ⇒ a policy IS installed at /home/vlad/.config/ImageMagick/policy.xml; imagemagick
     does not consult it — read where it does: identify -list policy | grep '^Path:'
   🌙 this build wrote NONE of the 6 declared format(s), so the policy's cost is
      UNMEASURED — never zero
```

## .the gap, precisely

the file is written, `cmp`-clean against the checkout, and **inert**.

```
$ identify -list policy          # → two Paths, and the seat file is neither
Path: /etc/ImageMagick-6/policy.xml
Path: [built-in]

$ XDG_CONFIG_HOME="$HOME/.config" identify -list policy   # → identical
```

so on this box:

| the policy declares closed | what is actually true |
|---|---|
| rule 1 — the ghostscript class (PS/EPS/PDF/XPS) | **open.** the verify read a `.eps` as coder PS |
| rule 2 — MSL/MVG/MAGICK, the ImageTragick class | open |
| rule 3 — TEXT/SHOW/WIN/PLT/LABEL/CAPTION/EPHEMERAL | open |
| rule 4 — every delegate | open. `/etc` closes three (URL, HTTPS, HTTP) and no more |

⚠️ **the file's own header asserts the opposite**, dated 2026-08-31: *"a policy at the seat
path BITES with no env var that names it, on both the `$XDG_CONFIG_HOME` route and the
`$HOME/.config` fallback."* that claim is annotated in place now; it is not deleted, because
it may well have held on the box and build it was taken on.

⇒ this is `gotcha.a-check-that-cries-wolf-gets-silenced`, q13 in its sharpest form: the reader
was right, the SUBJECT had two stores — a file on disk and the list of paths im6 consults —
and a `cmp` against the first says not one word about the second.

## 🛑 .what it is NOT

a delegate refusal seen on this box is **not** evidence rule 4 bit. measured the same day:
`nvim readme.md` raised `not allowed by the security policy 'inkscape'` on a shields.io badge
while rule 4 was unread. `inkscape` and `rsvg-convert` are both absent from the box, and im6
reports that dead reach in the vocabulary of a policy error.

⇒ so the refusal that LOOKS like proof the policy works is proof of the opposite. that is why
this is caught rather than waved past: the next reader will find the same sentence and draw
the same wrong conclusion.

## .the shape of the fix

two halves, and the second is the one that matters.

1. **find the path im6 DOES read on this build**, and write there.
   `identify -list configure` names `CONFIGURE_PATH` and `SHARE_PATH`; `MAGICK_CONFIGURE_PATH`
   is the env override im6 honors unconditionally. a seat-scoped answer likely means an export
   from `~/.zshenv` (`2.5.zsh` owns that file) — which makes this a TWO-bundle change, so read
   `rule.require.seam-claims-have-an-owner` before you cut it.
   ⚠️ and `MAGICK_CONFIGURE_PATH` reaches a PROGRAM only where a program reads that rc —
   `gotcha.a-tool-found-by-path-answers-only-a-human` governs the grove case.

2. **keep the verify's question, and add the clamp it lacks.** it already probes with a real
   `.eps` rather than a `cmp`, which is what found this. the clamp owed is a `prove.*` that
   plants the policy, asks `identify -list policy`, and demands the seat path appear — so a
   build whose search path differs reddens rather than reports a green `cmp`.

## .why it is not done in this round

the round was a `fix asap` on `nvim readme.md`, and that break is closed at its own cause in
`4.5.nvim`'s `init.lua` — it never depended on the policy and does not wait on this.

- **safe?** no — half 1 writes a box-wide search path, or an env var every imagemagick call on
  the seat inherits. a wrong value disarms the /etc policy too, which is strictly worse than
  the extant state
- **clean?** no — it ripples into `2.5.zsh` (the rc that would carry the export) and into the
  grove seats, whose builds may search different paths than the laptop's

⇒ and the fulcrum this defers: the policy may belong at `/etc` on a grove (`ground` holds sudo)
and at the seat on the laptop. that is a divergence, and
`rule.forbid.divergence-without-a-physical-reason` wants it argued before it is written.
