`git.grove.wake`, `git.grove.list`, and `duct.{open,send,read,list,reboot,refresh,stop}`.

contract (`rule.forbid.two-writers-on-one-artifact`): a fix lands in one and the other drifts.

upgrades this route made that the upstream copies must receive (verify each upstream first;
some may already exist there):

1. the seat gate: `grove_ssh_seat_ready` (heal a tailnet seat to the registry's
   `user@host:port`, refuse an `--alias` seat that dials another user), and the bash
   resolver's `ssh -G` read-back. clamps `prove.seat-ready-heals-or-refuses`,
   `prove.send-refuses-a-misrouted-seat`
2. `ssh -n` on every ssh that reads no stdin, so ssh never flips O_NONBLOCK on a shared
   description
3. `__grove_send_stdout_set_sync`: send clears O_NONBLOCK on its stdout before it relays,
   since a node parent hands it a non-blocked pipe and a large reply was cut at ~8KB
4. the tailnet reach (no ssm, no hibernate), which `git.grove.wake.tailnet` may already
   hold upstream; diff before the port
