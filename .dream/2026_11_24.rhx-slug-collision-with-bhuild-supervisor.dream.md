# 🌙 dream: settle the slug collision with the bhuild supervisor role

kind: fix · owner: this repo (and bhuild upstream) · caught 2026-11-24

## .the cue that fired

`rhx git.grove.provision boot <grove> --what 5.26.backup` halted at step 1: its own call to
`git.grove.wake` refused as ambiguous, since `repo=bhuild/role=supervisor` ships a skill of the
same slug.

## .the gap, precisely

- the supervisor role ships `git.grove.send`, `git.grove.wake`, `git.grove.list`, `duct.*`,
  `term.list`, `term.open` — each a slug this repo's role=any also declares
- `boot`'s own invocations now ride `rhx_run`, scoped to `.this/any`; that part is fixed
- every printed fix-text (`rhx git.grove.wake <grove> --mode apply`, and many across the
  `git.grove.*` and `duct.*` skills) still names the bare slug, so a human who copies one
  meets the same refusal
- any other skill that calls a colliding slug through bare `rhx` has the same latent defect

## .the shape of the fix

one of, in order of preference:
1. rhachet resolves a bare slug to `repo=.this` when `.this` declares it (dispatch upstream)
2. this repo renames none; every internal call and fix-text carries `--repo .this --role any`
3. the supervisor role is not enrolled here, if this repo needs none of it

## .why it is not done in this round

the round was the backup cadence; option 1 is another repo's decision, and option 2 touches
dozens of strings across skills outside this pr's scope.
