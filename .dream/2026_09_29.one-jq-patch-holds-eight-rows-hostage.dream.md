# 🌙 dream: one `jq` merge patch holds eight declared rows hostage to its least-settled one

- kind   = fix
- owner  = a driver — the split is mechanical, and each half keeps its own verify
- caught = 2026-09-29

## .the cue that fired

`5.3.brains` raised three claims on the laptop, and only ONE of the three is a human's to settle:

```
$ rhx grove.provision --what 5.3.brains --mode plan
✋ every self-update path is NOT declared — .env.DISABLE_UPDATES reads null, want "1"
✋ the accept-edits default mode is NOT declared — .permissions.defaultMode reads "auto", want "acceptEdits"
✋ the default model is NOT declared — .model reads "claude-opus-5-5[1m]", want "claude-opus-5[1m]"
```

the first two are ordinary drift the repo already owns. the third is the **repo behind** a live
choice, so WHICH holder is stale is a judgment.

⇒ and the apply cannot take the two and leave the one, because all eight declared rows are a
single merge patch in a single phase — `configure.upsert.sh:78`:

```sh
local patch='{"env": {"DISABLE_AUTOUPDATER": "1", "DISABLE_UPDATES": "1", …}, …, "model": "claude-opus-5[1m]", "cleanupPeriodDays": 36500}'
```

so `--what 5.3.brains` is the narrowest reach this repo offers, and it carries all eight.

## .the gap, precisely

the bundle's granularity is the BUNDLE, and its declared rows sit on **two different axes**:

| the rows | who settles them | an apply is… |
|---|---|---|
| `DISABLE_AUTOUPDATER`, `DISABLE_UPDATES`, `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION`, `disableClaudeAiConnectors`, `cleanupPeriodDays`, `permissions.*` | the REPO. each is a hazard this repo decided about, with its reason on record | a plain convergence |
| `model` | the HUMAN. it names which brain they want to think with | a judgment about their environment |

⇒ one unsettled row of the second kind holds every row of the first kind unconverged, **for as
long as the judgment stands open.** and the updater row is the expensive one to leave open: its
absence is what let claude float ~190 releases in place, which deleted a package tree a live
process still read from (`…claude-pin-sits-below-rhachets-own-brain-cli-floor`).

⚠️ **the hostage is invisible in the plan.** three ✋ rows read as three peers; no line says two
of them are blocked on the third. a reader who defers the model question has, with no signal,
also deferred the updater.

## .why it is not done in this round

**SAFE/CLEAN, and it fails CLEAN.** the fix is a split of one patch into two phases, which
ripples: a second `configure.*` pair needs its own name, its own dispatch line in `_.sh`, and its
own half of the verify's `for pair in` table — and that table is the bundle's one reader over both
halves (`…cries-wolf`, m.9 is exactly what a careless split would create here).

⇒ so it earns a fulcrum too: the deferral is a judgment about ripple, not about size
(`rule.always.itemize-the-fulcrums-you-best-guess`).

🟡 and the cheap half was taken in this round: the blocker was narrowed from *"an apply would
change your environment"* to **one question with two symmetric branches**, each of which ends in
an apply. that removes the hostage's cost without the split.

## .the shape of the fix

1. **split by WHO SETTLES, never by what the key does.** two phases under `5.3.brains`:
   - `configure.upsert.sh` — the repo's own hazards. seven rows, a plain convergence
   - a second phase for the rows that name a human's preference — `model` today
2. ⚠️ **keep ONE reader over both halves.** the verify's `for pair in` table is the discriminator;
   do not fork it. let each phase read its own slice of one declared table, or the two drift on
   exactly the input the verify exists to catch
3. **say the dependency in the PLAN.** a row blocked on another row should print as blocked —
   otherwise the hostage stays invisible, which is how the updater sat un-applied unnoticed
4. re-prove: `rhx grove.provision --what 5.3.brains --mode plan`, then apply twice
   (`rule.require.prove-each-bundle-plan-apply-apply`)

## .what this dream does NOT claim

it does not claim the atomic patch was wrong when written. one `jq` merge is the right shape for
a set of rows that share an owner, and seven of the eight do — `rule.forbid.two-writers-on-one-artifact`
is precisely why they are one patch rather than eight writes.

⇒ what it claims is narrower: **a preference row and a hazard row do not share an owner, so they
should not share a phase.** the defect is the mix, never the merge.
