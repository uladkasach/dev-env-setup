# 🌙 dream: the tracked `.radio` link names a human's home, and dangles on every grove

kind: fix · owner: this repo (dispatcher seam) · caught 2026-11-21

## .the cue that fired

`rhx dox.verify` on `beav/fix-grove-idle-counts-every-crew` read 1385 files with zero hits, then
refused a verdict: *"1 tracked file(s) are ABSENT from disk"*. `git ls-files --deleted` named no path.

## .the gap, precisely

- `.radio` is a tracked symlink (mode 120000, last touched in #136) whose target is an ABSOLUTE
  path under one human's home dir: `/home/<user>/git/.radio/ehmpathy/rhachet-roles-bhuild`
- on any box with no such dir (every grove, every camper seat) the link dangles, `[[ -e ]]` fails,
  and `dox.verify` counts it GONE — so the sweep refuses on every box but one. a check that always
  refuses gets silenced (`gotcha.a-check-that-cries-wolf-gets-silenced`)
- the target string carries a real username in a PUBLIC repo (`rule.forbid.dox-in-public-repo`)
- and `dox.verify`'s refusal does not name the path it could not read — the reader had to find it
  by hand via `git ls-files -s` + `file -L`

## .the shape of the fix

1. untrack `.radio` (gitignore it); the dispatcher's `radio.task.push` records into
   `$route/.radio/` or `.behavior/.radio/`, so a repo-root link may not be load-bear — confirm first
2. `dox.verify`: name each GONE path in `say_gone`; and treat a link whose target is absent (`-L`
   true, `-e` false) as its own class — present in the tree, so not an index/tree split, but owed a line
3. a clamp in `dox.verify --prove`: plant a tracked link at an absent target, assert the path is named

## .why it is not done in this round

safe, but not clean: step 1 changes how the dispatcher's radio dir is reached, which ripples past
the idle-check route's diff (`rule.always.fix-forward-under-scouts-honor`, the CLEAN question).
