# 🌙 dream: grove.provision's exit names the class of its failures

- kind: fix
- owner: dev-env-setup (`src/grove.provision._.sh`, `src/bundle.upgrade.sh`)
- caught 2026-11-21

## .the cue that fired

5.3.verification, the frictionless review of the live hetzner run. 5.26 ends on one
`✋ ConstraintError` (the commander's grant is owed), and the run then closes with:

```
✋ grove.provision finished with failures — each is named above, with its fix
🪨 run solid skill repo=.this/role=any/skill=grove.provision
   └─ 💥 failed with an error
```

## .the gap, precisely

`grove.provision._.sh:639-641` exits 1 on any bundle failure. rhachet renders exit 1 as
`💥 failed with an error`. so a run whose only failures are ✋ (a caller fixes) closes on 💥 (the
system is broken), against `rule.require.exit-code-semantics`. every ✋ in the tree has this
shape; 5.26 did not introduce it, it only made it visible on every fresh grove.

## .the shape of the fix

1. each bundle phase reports its failure class to the runtime (`✋` → 2, `💥` → 1), the way
   `BUNDLE_FAILED` is set today
2. the outcome exits 1 if any 💥, else 2 if any ✋, else 0
3. read every caller of the exit — the boot's gate, `git.grove.provision test`, the plays that
   assert `rc=1` — and move each to the new codes; a clamp per class

## .why it is not done in this round

it changes the exit contract of the one entrypoint, which the boot, the gate, and several plays
branch on. that is a ripple across callers this work does not own, so it fails CLEAN. no harm
ships: the ✋ above it names the fix, and a caller that reads `rc != 0` still stops.
