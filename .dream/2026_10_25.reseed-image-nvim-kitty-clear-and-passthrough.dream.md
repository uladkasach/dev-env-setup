# 🌙 dream: report three image.nvim kitty-backend defects upstream (3rd/image.nvim)

kind: reseed · owner: 3rd/image.nvim · caught 2026-10-25

## .the cue that fired

`4.5.nvim/init.lua` now carries two local patches to image.nvim internals, and
rule.require.report-leaks-upstream says a local patch to a foreign defect owes a report.

## .the gap, precisely

1. **has_passthrough misreads tmux < 3.3.** `utils/tmux` reads `tmux show -Apv allow-passthrough`.
   that option does not exist before 3.3, where passthrough is unconditional, so setup throws.
   the lazy backend survives the throw, so images render, but the VimLeavePre clear is never
   registered and images outlive nvim. measured on tmux 3.2a.
2. **clear forgets data it kept.** `backends/kitty` `clear` sends `d=i` (lowercase: placement
   deleted, data kept), yet sets `transmitted_images[id] = nil`. every re-render re-sends the
   whole file. over ssh that is base64 in 4096-byte chunks: 1.5MB per return to a tab.
3. **the cleanup loop returns after its first image**, so only one stale image per event is
   reaped.
4. **over ssh it sends a window-sized png.** the normal placement names a source rect in
   pixels and no cell box (`c`,`r`), so the transmitted png must match the pane's pixel size.
   a 200x50 pane of 20x40 cells is a 4000x2000 png: 9.5MB for a photo, base64 on the wire.
   measured 2026-10-26 (prove.image-send-capped).

## .the shape of the fix

1. treat a tmux older than 3.3 as passthrough on (parse `tmux -V`)
2. keep `transmitted_images[id]` on a `d=i` clear; drop it only on `d=I` or on a terminal reset
3. `goto continue` in place of `return` in the cleanup loop
4. a `max_transmit_pixels` option: cap the transform target, scale `w,h,x,y` to match, and
   send `c,r` so kitty stretches the png over the same cells

then delete the local patches in `4.5.nvim/init.lua` once a release carries the fix.

## .why it is not done in this round

it lives in another repo; a reseed needs an issue there, a human choice of account.
