# 🌙 dream: rhachet enroll inherits the grove's claude settings and trust

kind: reseed · owner: ehmpathy/rhachet · caught 2026-09-26

## .the cue that fired

a human asked for auto mode on by default, and for `~/git/ehmpathy`, `~/git/ahbode`,
`~/git/more`, `~/git/nheuron` to be trusted by claude. both were blocked on enroll.

## .the gap, precisely

`rhx enroll claude` (rhachet 1.48.0) relocates the cli:

- `asBrainCliSpawnEnv` sets `CLAUDE_CONFIG_DIR=<repo>/.agent/.actors/<actor>/brain/.claude`
- `asBrainCliSpawnArgs` passes `--setting-sources user,local --settings settings.enroll.<hash>.local.json`
- the actor dir symlinks ONE file back to the human: `.credentials.json -> ~/.claude/.credentials.json`

so an enrolled clone reads:

| what | from | reaches the human's config? |
|---|---|---|
| auth | `.credentials.json` symlink | ✔ |
| settings (user layer) | actor `settings.json` — rhachet's generated role file | ✋ |
| trust, `/config` toggles | actor `.claude.json` | ✋ |

measured: `~/.claude/settings.json` held `permissions.defaultMode: "auto"` (and model, env,
`deny: [Agent]`), and a clone spawned via `rhx enroll claude --await -p …` reported it had
been told no permission mode, i.e. not auto.

observed too: the actor `settings.json` and `settings.enroll.<hash>.local.json` carry the
SAME hooks and permissions, so the role config is already written twice.

## .the shape of the fix

1. **settings** — lay the human's settings UNDER the role config, the same way
   `.credentials.json` is already shared:

   ```
   <actor>/brain/.claude/
     settings.json        -> settings.grove.json      # the fixed name claude reads (user layer)
     settings.grove.json  -> ~/.claude/settings.json  # the box's defaults
     settings.repo.json                               # role hooks + perms, passed as --settings
   ```

   - `--settings` outranks `user`, so role config wins any conflict
   - permission rules and hooks CONCATENATE across layers, so neither side is lost
   - `settings.repo.json` needs a per-role-mix key (today's `<hash>`) if one actor dir can
     hold several `--roles` mixes — confirm whether `actor.via.hash=…` already scopes that
   - the "never boot from the human's `~/.claude`" guarantee still holds for the part that
     matters — the boot corpus (`CLAUDE.md`) and memory stay in the actor dir
   - to decide: the human's own hooks would then fire in clones
   - to check: whether claude ever rewrites user `settings.json` by atomic rename, which
     would replace the symlink with a plain file (the `.credentials.json` link has the
     same exposure)

2. **trust** — seed it, never share the file:
   - `.claude.json` holds per-actor project state and is written by concurrent clones, so
     a symlink would race
   - at enroll: if the clone's cwd or any ancestor has `projects[<dir>].hasTrustDialogAccepted`
     in the human's `~/.claude.json`, write `projects[<cwd>].hasTrustDialogAccepted = true`
     into the actor's `.claude.json` before spawn

then dev-env-setup's half is small: `5.3.brains` writes the trusted roots into
`~/.claude.json` (no sudo), and `~/.claude/settings.json` stays the one home of every
brain knob.

## .why it is not done in this round

it lives in another repo — a tree adopts only what is scoped to itself. the in-repo
alternative (`/etc/claude-code/managed-settings.json`) needs root on every box and makes
the policy file writable only by an admin; the human declined that route.
