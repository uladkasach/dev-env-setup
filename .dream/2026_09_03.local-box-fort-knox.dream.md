# dream: the local box is locked down like fort knox

## .the wish

> **a local box declares NO inbound reach, and a check proves it on every apply.**

a grove is reached over ssh, by design — that is its front door. a **laptop** is reached by a
human at its keyboard, and every inbound port it holds is a surface nobody asked for.

today the repo declares that intent in a comment and enforces it nowhere.

## 🛑 .the measurement that started it — 2026-09-03, redteam round 22, class 5

`2.3.ssh/provision.upsert.sh` ran `pkg_install ssh` with no tier gate.

- `ssh` on debian is a metapackage over `openssh-client` + `openssh-server`
- `openssh-server`'s maintainer scripts **enable and start** `ssh.service` at install time
- this repo writes no `sshd_config`, so the daemon runs under the stock one —
  `PasswordAuthentication` at its compiled default of `yes`
- this tree declares no host firewall at all: zero matches for `ufw|iptables|nftables`

⇒ a laptop that did not already carry `openssh-server` came out of ONE
`grove.provision --mode apply` with a password-authenticated port on `0.0.0.0:22`, enabled at
boot, on every network it joins.

⚠️ and the verify beside it said the opposite — *"a local laptop deliberately keeps its daemon
down"* — a sentence held by a comment, made true by no code, asked by no reader.
`gotcha.my-own-note-became-my-evidence`, in a security control.

**shipped 2026-09-03, at cause:** the upsert now asks for `openssh-client` on `local@*` and the
metapackage only on `cloud@*`. the verify now has a third rung that reddens when a laptop holds
a live daemon. that closes the SOURCE. it repairs no box that already carries one.

## .what this dream wants, beyond that fix

### 1. the repair bundle — a box already converged is still exposed

apt removes none of what it installed. a laptop provisioned before 2026-09-03 still holds a
live `openssh-server`, and the new verify reports it with a hand fix.

⇒ **a hand fix is a fourth step, and `rule.require.one-command-provision` forbids one.** the
repair is machine state, so it is a BUNDLE:

```
stop → disable → mask
```

⚠️ **mask, not merely disable.** an `apt install` of any package that pulls `openssh-server`
back re-enables the unit. mask is the only state apt cannot walk over.

⚠️ **and it needs an opt-out that is DECLARED, never silent.** some boxes are deliberately
reachable. that intent belongs in the repo as a declaration the bundle reads — never as a
comment, and never as a silenced check (`rule.forbid.exemption-as-habit`).

### 2. the LISTENER CENSUS — the general form of the defect

ssh is one member of a class. the class is:

> **a package or unit this repo installs that OPENS A PORT, on a tier that declares none.**

reviewer A's round-22 sweep censused it by hand and found ssh was the only one. that census
must become a check, because a hand list cannot report the member nobody added
(`rule.require.one-command-provision`).

what the census must ask, per tier:

| question | today |
|---|---|
| what sockets does this box hold open? | unasked |
| which of those did this repo cause? | unasked |
| which does its tier DECLARE? | undeclared |

⚠️ **the hard half is the third row.** the first two are a `ss -tlnp` and a package map. the
third needs a **declared socket set per tier**, and this repo has never written one. without
it the check has no bar to grade against and becomes a report nobody reads.

⇒ so the deliverable is two artifacts, in order:
1. a **declaration** — the ports each tier may hold, and why each is there
2. a **reader** — a play that reads the live sockets and grades them against it

### 3. the CLASS SCANNER — install-and-serve, found by source

the census reads a live box. a scanner reads the TREE, and it is the one that catches the next
one before it ships.

the shape to hunt:

> **a `pkg_install` of a package whose install ENABLES A UNIT, on a phase with no tier gate.**

`2.1.toolkit` already states the rule this violates, in the repo's own words: a grove HOLDS
xclip fine, it just has no selection to move — **install-and-stay-inert**, so one package list
serves every tier. `openssh-server` is the exception, because to HOLD it IS to RUN it.

⚠️ **q7 applies hard here.** a blanket ban on ungated `pkg_install` is a false ✋ on nearly
every bundle in the tree — most packages genuinely are inert. the reader needs the
**daemon-package** discriminator, and that is a fact about debian, not about this repo.

candidate discriminators, none yet measured:
- `dpkg -L <pkg>` names a file under `/lib/systemd/system/*.service`
- the package sits in a known daemon set
- `apt-cache show` names a `systemd` dependency

⇒ **this is the piece most likely to be un-writable in the medium first reached for**, exactly
as the relay-verb reader was. measure the discriminator before you promise the check.

### 4. the harden bundle — beyond ssh

if a local box must hold a socket, it should hold it under a config this repo writes:

- `sshd_config.d/` — `PasswordAuthentication no`, `PermitRootLogin no`, `AllowUsers`
- a host firewall — default-deny inbound, declared per tier
- ⚠️ **and a firewall is a hazard of its own on a grove**: a wrong rule on a headless box
  locks out the duct, and the box has no console. so this is `local@*` first, and `cloud@*`
  only with a rollback that survives the lockout.

## 🛑 .the lesson the guardian owes, stated plainly

21 rounds swept this repo and not one asked what sockets it makes a box hold open.

⇒ the guardian's redteam dispatch enumerates ENTRYPOINTS as seams in code — a fetch, a file
read, an accepted value. **an open socket is an entrypoint too**, and it is the only one that
exists because of what a bundle INSTALLED rather than what a bundle WROTE.

that is the generalizable half: **an entrypoint can be created by a package's own postinst,
with no line of yours to grep for.** a source-only enumeration cannot see it.
