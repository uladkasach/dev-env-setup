# domain.term: disposition

term.chosen   = disposition
term.kind     = noun
term.synonyms.forbidden:
- verdict         (EXTANT TERM, and the sharp one: a verdict is what a COMMAND judged at run
                   time. a disposition is what a HUMAN judged at authorship time. different
                   judge, different moment — see the pairing below)
- status          (already taken twice over: a systemd unit, a pr check, a duct pane each
                   have one — `term=verdict._.choice._.md` refused it for the same reason)
- classification  (names the BUCKET a site landed in, and says none of who judged it or that
                   the judgment was written down. the record IS the term)
- annotation      (a note carries no obligation. a disposition is CHECKED, and the tree
                   reddens when it stops fitting)
- exemption       (EXTANT TERM, and the opposite: an exemption is a carve-out FROM a rule.
                   a disposition waives no part of one — a dispositioned site is still measured)
- allowlist       (an allowlist SILENCES its members. a disposition keeps them loud: the
                   count still moves, the row still reddens)
- waiver          (same defect as exemption, in a legal register)
- review          (the ACT of looking. a disposition is what the look left behind)

## .what

a **disposition** is a human's recorded judgment about one site, which a reader later holds
the tree to.

it is what you write down when a property is real and **no reader can express it**.

## .the pairing the word exists to keep apart

```
verdict      → a COMMAND judged its subject, at RUN time
disposition  → a HUMAN judged a site, at AUTHORSHIP time
```

so a reader over dispositions never re-judges the site. it asks the narrower question it can
actually answer:

> is the record still a fit for what is there?

## 🛑 .why it exists — the honest close for an inexpressible property

`term=reader._.choice._.md` states the constraint that forces this word:

> a reader written to hold a **dataflow** property flagged several hundred CORRECT lines on
> its first run, and was deleted the same hour. no grep over source can see where a value
> came from.
>
> ⇒ when a property has no expressible reader, the honest close is to **narrow the CLAIM** —
> never to widen the reader until it bites correct code.

a disposition IS that narrowing, made checkable. "does this consumer write the secret down?"
is dataflow, so no grep can answer it. "has a human looked at this site and written down what
it does?" is a fact about a RECORD, and a grep answers it exactly.

## .a disposition reddens THREE ways, and all three are load-bear

| the drift | why it must bite |
|---|---|
| a site with **no row** | a new consumer inherits a judgment nobody gave it |
| a row whose **count moved** | a call added to a judged file rides in under the old verdict |
| a row whose **site is gone** | a record that resolves to no site reads as coverage |

⚠️ the third is the one a first cut always omits. an absent row is visibly a gap; a **stale**
row is invisibly one, and it reads as diligence (`gotcha.a-check-that-cries-wolf-gets-
silenced`, m.10).

## ⚠️ .a KNOWN-BAD disposition must not fail the run

a site whose recorded judgment is *"this one is wrong, and its fix is blocked"* is a standing
finding, not a regression. a reader that failed on it would be red on every run — and a check
that is always red gets silenced, taking every row beside it down too.

⇒ print it, every run, as a standing 🛑. never let it go quiet, and never let it fail.
