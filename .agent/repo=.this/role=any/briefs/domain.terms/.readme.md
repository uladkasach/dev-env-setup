# domain.terms

## .what

this repo's glossary. one cluster per **term** — a noun, verb, or adj that composes the domain
objects and operations this repo declares. a term is itemized once and reused everywhere.

## .the cluster shape

```
term=<x>._.choice._.md              # say-level: chosen word, kind, forbidden synonyms, refs
term=<x>._.choice.reason.md         # ref-level: etymology, disputes, evidence — REQUIRED
term=<x>._.choice.example=<abc>.md  # ref-level: one per notable example — optional
```

the say file is lean and always booted into context. the reason file is deep and surfaced on
demand. see `template.domain-term.md` (bhrain learner) for the full template.

## .the rules that rule this dir

- `rule.require.domain-term-itemization` — a term that composes a declared dobj/dop must be
  itemized here
- `rule.forbid.domain-term-synonyms` — contracts use the canonical word; a comment may use a
  synonym for an alternate perspective. to disagree, open a dispute — never drift
- `rule.require.persist-domain-term-evidence` — the `.reason` file is required, and must carry
  etymology plus the evidence behind the choice

## .how to disagree

do not quietly rename a contract to your preferred word. open a dated dispute in the term's
`.reason` file, under `## .disputes`. see `howto.domain-term-disputes.[guide].md`.

## .what does NOT belong here

- generic english that is not domain vocabulary (`file`, `run`, `data`)
- vocab imported from a dependency (bhrain's `stone`, `guard`, `route` are the tool's terms)
- a local variable that names no domain concept
