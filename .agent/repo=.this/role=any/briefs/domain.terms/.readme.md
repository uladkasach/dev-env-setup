# domain.terms

## .what

the glossary for this repo's domain vocabulary. one cluster per term, reused across every
domain object and operation that term composes.

## .the cluster shape

```
term=<x>._.choice._.md              # say-level: chosen word, kind, forbidden synonyms, refs
term=<x>._.choice.reason.md         # ref-level: etymology, disputes, evidence — REQUIRED
term=<x>._.choice.example=<abc>.md  # ref-level: one per notable example — optional
```

the say file is lean and always booted into context. the reason file is deep and surfaced on
demand. see `template.domain-term.md` (bhrain learner) for the full template.

## .the rules that rule this dir

- `rule.require.domain-term-itemization` — every declared term is itemized here
- `rule.forbid.domain-term-synonyms` — a contract uses the canonical word, or opens a dispute
- `rule.require.persist-domain-term-evidence` — the `.reason` file is required, and must carry
  etymology plus the evidence behind the choice
- `template.domain-term.md` — the `term=<x>._.choice.*` cluster shape
- `howto.domain-term-disputes.[guide].md` — the dispute pattern

## .how to disagree

do not quietly rename a contract to your preferred word. open a dated dispute in the term's
`.reason` file, under `## .disputes`. see `howto.domain-term-disputes.[guide].md`.

## .what does NOT belong here

- generic english that is not domain vocabulary (`file`, `run`, `data`)
- vocab imported from a dependency (bhrain's `stone`, `guard`, `route` are the tool's terms)
- a local variable that names no domain concept

## .scope — a term names its bounded context

a term is itemized **within the bounded context it applies to**, and that context is carried
in the term as a **prefix**: `grove.stop`, never a bare `stop`.

### .why

a bare verb silently claims the whole repo. `stop` reads as *the* stop — but this repo could
stop several distinct things:

| term | the operation | the domain object |
|------|---------------|-------------------|
| `grove.stop` | take a machine down | grove |
| `duct.stop` | close a session | duct |
| `tree.stop` | end a branch workspace | tree |

each is a different act on a different object. to record them all as `stop` is the exact
overload `rule.forbid.domain-term-synonyms` and `ubiqlang.ambiguous-from-overload` warn
against — one word, several concepts. worse, the glossary then LOOKS settled while it is
ambiguous, and a later traveler trusts it.

the prefix also makes the glossary compose: `grove.wake` / `grove.stop` read as a pair within
one context, where `wake` / `stop` read as global claims that collide the moment another
context needs either word.

### .the test

> could another domain object in this repo take this same word?

- **yes** → the term MUST be prefixed with its context
- **no** → a bare term is legitimate

### .when a bare term is right

- **a domain object itself** — `grove`, `tree`, `forest`, `bundle`. these ARE the contexts, so
  they need no prefix
- **a word that spans every context** — the sanctioned verb family (`get`/`set`/`gen`/`del`)
  means the same in each, so each stays unprefixed (and is sanctioned by the mechanic canon,
  not re-itemized here)

## .terms

### bounded context: grove — a machine that holds trees

- `grove` — a machine (host) that holds trees
- `grove.wake` — drive a grove to reachable (egress, box, duct, alias)
- `grove.stop` — drive a grove down; `--how hibernate|halt` picks the mode
- `grove.push` — move content from here to a grove
- `grove.pull` — move content from a grove to here
- `grove.send` — give a grove a command to run (duct by default, `--bare` for bootstrap)
- `grove.read` — ⚠️ DISPUTED (open): look at what a grove's duct holds. the read half of
  `grove.send`; the open dispute asks for `grove.snapshot` — see its `.reason`
- `grove.alias` — the ssh Host that reaches a grove (distinct from the grove's name)
- `grove.trust` — our recorded belief that an endpoint IS a given grove (its known_hosts entry)

### bounded context: provision — what this repo puts onto a machine

⚠️ this context was named for a NOUN that is now forbidden repo-wide (2026-09-02). no
replacement noun was coined, because three live terms already carry every part of it —
`grove` (the machine), `bundle` (one unit), `tree` (the whole set). the context is named
for its core VERB instead. see `term=devenv._.choice._.md`, the family tombstone.

- `grove.bootstrap` — put the REPO onto a bare machine, so `grove.provision` can run at all.
  the one step that cannot be a step of the run it starts (`grove.bootstrap.sh`, at repo root)
- `grove.provision` — converge a machine's extant tree to the state this repo declares. THE
  core verb: no machine is ever blank, so every run — the first one too — converges an extant
  tree. THE entrypoint is `src/grove.provision._.sh`, and it is the only one — a forwarder
  under an old name would be a second entrypoint, so `install_env` was deleted outright
  (see `retired`). it is ONE verb at TWO addresses: `rhx grove.provision` on this box,
  `rhx git.grove.provision boot <name>` on a remote one
- `git.repo.pull` — update this repo on this machine from its remote
- `provenance` — how a tree src ARRIVED on a machine, and so how it refreshes; values
  `cloned` (git clone → `git.repo.pull`) | `pushed` (`grove.push` rsync → another push). a
  pushed src has no `.git` BY DESIGN; it is never a broken clone
- `--for` — which KIND of machine an operation is for; values `local` | `cloud`, plus the tag
  value `any`. it IS `$server`'s tier under a cli name, so `src/grove.for.sh` DERIVES it from the
  environment rather than probe the box again. spelled as the FLAG, because that is the contract a
  human types
- `grove.provision.inventory` — the ordered roll of dispatch lines the entrypoint drives. exactly
  ONE exists, repo-wide. named by the human, who corrected the robot's "procedure": a procedure is
  a sequence you walk, so two machine kinds sound like they need two of them — which is how four
  duplicate drivers grew. an INVENTORY is a declared set that the environment FILTERS, and two of
  those read as a ledger error, which is what they always were
- `bundle` — a member of the inventory: a named composite of the packages and configs one concern
  needs, held as a directory under `src/grove.provision/`. named by the human — *"they're
  bundles, because they're typically composites of packages and configs"* — which retired the
  robot's `entry`, a word that named a POSITION in a list rather than what the member is. two node
  kinds, each DECLARED by the driver its `_.sh` calls: a **composite** (`bundle_composite`) holds
  subbundles, propagates the env, and claims none of it; a **leaf** (`bundle_leaf`) holds the four
  phases and READS the env to decide whether it applies. turtles all the way down: one `step`
  dispatch, at every depth
- `claim` — one assertion about THIS MACHINE that a bundle leaf is accountable for, and that its
  `verify` either proves or declines to prove. the unit the roll counts: a leaf makes claims, a
  composite makes none, so `ran: 1` means one claim converged and never one node visited. the word
  exists because `exit 0` is not a claim — exits `3` (unproven), `4` (inapplicable), and `5`
  (composite) are the three readings that would otherwise collapse into it and read as coverage
  forever. `check` is the ACT and stays its own word; `guarantee` is a property of the FILE
- `bin` — the file on `$PATH` a name resolves to, read with every shell FUNCTION and alias of that
  name unset. composes `bundle.bin.of`, the sole reader. the word exists because `command -v` is
  answered by `src/bash_aliases.sh`, not by the box: five aliases there share a name with a real
  binary (`nvim`, `usql`, `npm`, `npx`, `tsx`), and on 2026-07-30 `5.11.usql.provision.verify`
  reported *"on PATH at the WRONG version"* where the binary was ABSENT (exit 127) — the wrong
  defect, so the wrong fix. `which` is FORBIDDEN: it names the tool that HAS the bug
- `bundle` — one act, and the primitive the dispatch is named for. a `bundle`
  composites steps; it could not reuse the word without overload of one term onto two tree levels
- `grove.provision` — ⛔ FULLY SUPERSEDED (2026-07-29). retired as a VERB on 2026-07-27, and its
  two remaining open questions closed on 2026-07-29 — see `retired` below. the step functions
  stay `install_*` / `configure_*`, because at step level `install` is often literally true
  (`install_zsh` runs `apt install zsh`); it is the TREE as a whole, which always already
  exists, that is upgraded

### bounded context: duct — a named durable terminal a command is sent into

- `duct` — a named, durable terminal a command can be sent into and read back out of, here or
  on a grove. survives disconnect: a send and a much later read still find each other
- `duct.uri` — the ONE format that names a duct: `duct://<host>/<tree>/<role>`, or
  `duct:///<tree>/<role>` when the empty authority means this machine. what `--on` takes is
  exactly what every message prints. retires the scp-shaped `slug` (`grove-1:main/mechanic`)
- `duct.uri.scope` — a duct uri read as **as much of the address as you know**:
  `duct://grove-1` = the grove, `duct://grove-1/main` = one tree. a segment-aware prefix, so
  no `*` and no quotes. READ verbs only — a verb that ACTS keeps the strict parser, so
  `duct.stop --on duct://grove-1` stays an error rather than a mass kill
- `duct.open` — make a duct exist (idempotent; a duct already open is returned)
- `duct.idle` — whether a duct will RUN what it is sent; `idle` (a shell holds the pane) vs
  `busy` (any other program holds it, so a send lands in THAT program's stdin). observed from
  tmux, never tracked
- `duct.send` — give a duct a command to run. refuses a busy duct; `--await <secs>` waits for
  idle, `--anyway` types into the held program on purpose
- `duct.read` — look at what a duct holds
- `duct.list` — what ducts exist
- `duct.stop` — close a duct (idempotent; an absent duct is already stopped)
- `duct.reboot` — replace the program the pane holds with a fresh shell; the duct, its name, its
  scrollback and its cwd all survive. NOT idempotent by design: an absent duct has no pane to
  respawn, so it fails and names `duct.open`. the escape hatch whose ABSENCE was used to excuse
  ~10 raw ssh calls on 2026-07-29
- `duct.refresh` — ⚠️ DISPUTED (open): tell attached clients to repaint; kills no program. the
  free rung of the repair ladder (`refresh` → `reboot` → `stop`). the dispute: `refresh` is
  OVERLOADED — `duct.list --refresh` already means "re-probe hosts over ssh". leans toward a
  rename of the FLAG to `--reprobe`

### bounded context: forest — every grove together

- `forest` — all groves together
- `tree` — a branch workspace (git worktree + session) on a grove
- `main` — the trunk of a repo: the branch trees are carved from, and the checkout that
  tracks it. paired with `tree` as the where-does-this-code-live axis on one machine
  (`--from main|tree`); retires `--version local|global`, whose `local` collided with
  `--for local`

### bounded context: the box a human sits at — split across TWO nouns on purpose

the shell aliases a human types at their own machine. the split is by **what the act
changes**, and it is the rule that says where a new member goes:

| namespace | changes | members |
|---|---|---|
| `power.*` | the machine's POWER STATE | `power.off`, `power.restart`, `power.suspend` |
| `machine.*` | the SESSION on a machine that stays powered | `machine.lock`, `machine.logout` |

- `power.restart` — take the machine down and back up, **and snap the kitty window/pwd map
  first**. the snap is half of what the verb means, not a decoration on it. forbids
  `machine.reboot`, which shipped beside it as a bare `systemctl reboot` — one act, two
  words, and only one of them brought the terminals back
- `machine.lock` — lock the session, machine still powered and awake. the idle timers are
  off by design, so this and the COSMIC keybind are the ONLY two locks this box has

⚠️ `machine.*` also carries `machine.usage.*`, the diagnostic family. that is a third
sense of the noun and it has not been argued; it does not collide today because no
diagnostic member could be read as a power transition.

### credential provenance — a property of any credential, so bare by design

these two are a pair, and they ask one question in every context: **did we place this, or
was it already here?** like `declared` / `live`, they qualify uniformly, so they stay
unprefixed.

- `rack` — a credential a human placed, held in a vault, ours to rotate. its absence is a
  fillable gap (`@all.camp.GITHUB_TOKEN`)
- `ambient` — an identity the box carries by virtue of what it IS, unplaced and unrotatable
  by us. its absence is a fact about the machine, not a gap (`<camp-grove-role>`, named
  on disk as `[profile ambient]`)

⚠️ code that treats one like the other fails in a way that reads as a credential problem
when it is a vocabulary problem. that is exactly what happened on 2026-08-07: an ambient
identity was reported as a rack entry `absent 🫧`, and the real defect — one absent POINTER
— stayed invisible for as long as the vocabulary could not express it.

### state qualifiers — a property of any state, so bare by design

these two are a pair, and they ask the same question in every context: does a boot replay this
state, or forget it? they qualify state uniformly, so like the sanctioned verb family they
stay unprefixed.

- `declared` — state as written in a durable declaration a boot replays (`/etc/fstab`, a
  systemd unit, a kernel cmdline, a repo manifest). the cause
- `live` — state as the machine holds it this instant (`swapon --show`, `ps`, `ss`). the
  consequence, rebuilt at every boot — so it may be reported as context, never as a verdict

governed by `rule.require.judge-declared-state-not-live-state`, with the test:
*"if i reboot this box right now, does my verdict still hold?"*

### caller qualifier — a property of any file, so bare by design

- `driven` — a file this repo's runtime, or another PROGRAM, executes with no human at the
  keyboard: the bundle tree, the shared runtime it sources, `grove.bootstrap.sh`, and
  `src/git-credential-keyrack.sh` (git invokes that one, on every fetch). its opposite is an
  INSTALLED ARTIFACT a human types — `bash_aliases.sh`, `ductwork.sh`, `zshrc.sh`

⚠️ the DIRECTORY does not decide membership; the CALLER does. `git-credential-keyrack.sh` and
`bash_aliases.sh` are one directory apart and land on opposite sides, so a sweep scoped by path
is a claim about the wrong axis.

⇒ the boundary is load-bear because **the same demand is correct on one side and a REGRESSION
on the other**: `GIT_TERMINAL_PROMPT=0` saves a headless box from a duct wedge and would remove
the only way a laptop human authenticates. measured twice on 2026-08-15, hours apart — the
second play reused the boundary rather than re-argued it, which is what earned a term over a
comment.

### artifact kinds — a kind, not an operation, so bare by design

- `play.verify` — the verb of a play that JUDGES a claim and asserts a verdict. the family is
  THREE verbs and **every one of them only READS**: `diagnose` (reads, asserts no verdict),
  `verify` (reads, asserts a verdict), `prove` (runs the claim's subject, then judges). what
  splits them is the VERDICT
  > 🛑 **`play.repair` may never be itemized.** it would canonize a play that WRITES, which
  > `rule.forbid.repair-plays` forbids outright: a play that writes is a second entrypoint,
  > and machine state belongs in a bundle
- `play.prove` — the verb of a play that DRIVES the box and then judges the result. the third
  split of the family: a `verify` reads, a `prove` writes first, because a claim about a first
  apply cannot be read off a box that already holds what the apply would install
- `play.rollback` — the one VERB whose play may write outside a call into `grove.provision`,
  and it writes **BACKWARD**: it un-converges a test box so a bundle's first apply can be
  re-tested. the axis that defines it is DIRECTION (forward = a bundle, always), it is bounded
  by four conditions, and its healthy population is **zero** — condition 4 deletes it when the
  experiment ends, so an empty `.refs` is evidence the word works. it replaces the deleted
  `repair`, and the two are opposites, not neighbors
  > ⚠️ it is the one write VERB and **not** the only write. a `prove.*` play may also write as
  > a **discrimination probe** — break a subject, confirm the check reddens, restore through a
  > `trap … EXIT`. that is a ROUND TRIP (net zero) rather than a one-way backward move, which
  > is why it keeps the `prove` verb and why it is PERMANENT where a rollback is disposable.
  > `rule.forbid.repair-plays` exception 2 carries it; do not read rollback's condition 4
  > across onto it
- `play.await` — the verb of a play that WAITS for a run somebody else started, then reports
  its roll. the only verb whose subject is a RUN rather than the machine, so it asserts no
  verdict and owes two bounds: bounded in time, and honest at the bound. it is also the one
  verb used in a SKILL slot (`git.grove.play.await`), where the position flips: a play is
  `<verb>.<subject>`, a skill is `<subject>.<verb>`
- `playbook` — a multi-step command, written down as a reviewed file, so it can be read before
  it touches a machine and re-run by name. adopted from
  `ehmpathy/rhachet-roles-bhrowser`; lives at `.play/temporary/<name>.play.sh`
- `asset` — a file under `src/` that a bundle phase copies onto a box UNCHANGED, so a verify
  can `cmp` the live copy against the checkout. the alternative to a heredoc: the same bytes
  written inline in a phase have no second copy to diff, so a verify can prove PRESENCE and
  never CURRENCY. `payload` is BOUNDED beside it — allowed only where a mechanism EXECUTES the
  file (the systemd guard, firefox's autoconfig parser)
- `marker` — a fixed `# grove: <claim>` line a bundle appends into a file it does NOT own,
  so a later run can ask "is my block already here?" without a read of the block itself. it
  is what makes an append idempotent. the `grep` is the **guard**; the line it finds is the
  marker — two halves whose confusion IS the defect. keyed on the CLAIM, never on the code
  (which changes) and never on the slug (which moves)
- `shim` — a file at a path callers already know, whose whole body finds the one real
  implementation and `exec`s it. how ONE writer survives TWO callers when a concern is reached
  from both the `rhx` skill dir and `src/`. `wrapper` is FORBIDDEN beside it: a wrapper ADDS
  behavior, a shim adds none
- `exhibit` — an artifact whose whole value was to MEASURE one argument once, and whose result
  now lives elsewhere. it is **spent when the result lands**, not when it breaks — it usually
  still runs perfectly, and that is what makes it costly rather than surplus: it reads as
  coverage while it is a second home for a fact (`term=drift`). its peers are `tool` (reached
  for when a fault appears) and `clamp` (re-proves a claim forever, INHERITED from
  `rule.require.clamp-edge-cases`, so never re-itemized here). `one-off` is FORBIDDEN beside
  it: that names run-FREQUENCY, which is orthogonal — a tool that ran once must be kept, and an
  exhibit that ran fifty times is still spent
- `hazard` — a brief that names a property of a subject which HOLDS RIGHT NOW and will bite
  whoever forgets it. the present-tense half of an axis whose past-tense half is `gotcha.` — *has
  it fired?* a hazard can EARN a gotcha the day its property fires; a gotcha can never become a
  hazard, because a measurement does not un-happen, and that asymmetry is what proves the two are
  not synonyms. `gotcha` is FORBIDDEN as a synonym for exactly that reason: `briefs/.readme.md`
  requires a gotcha to carry *"the measurement that found it"*, so to merge them would demand
  evidence that several hazards do not have — and the pressure to invent it is
  `gotcha.my-own-note-became-my-evidence`. ⚠️ one dispute stays OPEN: prefix (`hazard.…`, 11
  files) vs infix (`nvim.hazard.…`, 2 files). it is a corpus-wide question about the SUBJECT
  prefix, not a hazard question, so it is deliberately not settled here

### bounded context: aws — the account a box acts in

- `aws.reach` — a box's ABILITY to act in one org+env's aws account: the whole chain from the
  badge it holds, through the profile that names the hop, to a call that answers there. it is
  the CHAIN, never one link — a box with valid credentials and no profile has no reach

### bounded context: brains.auth — which claude subscription this box spends

- `brains.auth.reach` — the email address an oauth token reports as its own identity, and so the
  name a subscription is filed under. DERIVED from the token on every call, never remembered, so
  a login made behind our back is noticed. ⚠️ it arrived from another branch as a bare `reach`
  and was prefixed on arrival: `aws.reach` already held that word for a CAPABILITY where this
  one is an IDENTIFIER. `sub`, `slug`, `account-name`, `handle` are forbidden — each is a second
  name for a thing that already has one
- `park` — file the live account's refresh token into the keyrack, so the account survives a
  swap about to overwrite the only copy it has. paired with `strand`: a swap that cannot park
  first is refused rather than driven. `stash`, `save`, `store`, `backup`, `archive` forbidden

### unsettled

- `grove.read` — ⚠️ DISPUTED (open): `grove.snapshot` proposed, to match bhrowser. hinges on
  whether the operation retains an artifact; contracts keep `read` meanwhile
- `duct.refresh` — ⚠️ DISPUTED (open, raised 2026-07-29): `refresh` is overloaded inside the duct
  context. `duct.list --refresh` re-probes hosts over SSH; `duct.refresh` repaints a local client.
  one word, two concepts, one context. leans toward a rename of the flag → `--reprobe`, since the
  flag is younger, has one caller, and `reprobe` names what it does. both ship meanwhile.
  **found by enumeration of the term's own `.refs`** — the clash appeared only when the two sat
  in one list, which makes ref-enumeration a cheap overload check worth deliberate reuse
(the provision context holds no open dispute — `grove.provision`'s last two closed 2026-07-29, and
`grove.provision.grove` plus both `for`-axis questions closed 2026-07-27; see `retired` below)

### retired

- `install_env._.sh` as THE entrypoint — ⛔ DEPRECATED 2026-07-29 (human), then **DELETED
  2026-07-30** in the hard cut, along with `install_env.pt*.sh` and every `stepfn` line.
  `src/grove.provision._.sh` is canonical and sole.

  🛑 **do not keep a forwarder at the old path**, however many briefs point there. **a
  forwarder that still works IS a second entrypoint**, and two entrypoints must be kept honest
  with each other forever (`rule.require.grove-provision-as-the-only-entrypoint`). the cost it
  saves — a reader who follows a dead path — is paid once and loudly; the cost it creates is
  paid silently, on every future divergence.

  the human's close: *"make it clear that
  upgrade is the future term, and install is the deprecated term, for the same thing, now that
  we have the idempotency mandate"*. the reason the word changed: an INSTALL is done once, so
  it invites a procedure correct only the first time; an UPGRADE is re-driven whenever the
  declaration moves ahead of the machine
- `grove.provision`'s SCOPE overload — ⛔ CLOSED 2026-07-29, **and it was a DEFECT, not a term
  question**. the dispute recorded two artifacts under one name with different scopes
  (entrypoint = configs AND tools, 60 steps; skill = configs only, 7 files) and asked which one
  the name meant. the truth was worse: the skill carried its own hardcoded array — a SECOND
  implementation of a verb the repo already owned, and a strict subset of it. on a fresh grove
  it copied dotfiles onto a box with no node, no nvim, and no claude, then printed a full-green
  `cowabunga! … installed`. the fix was to delete the list and rename none of it; it now `exec`s
  the root driver. **an overload recorded as a term dispute can be a defect in disguise** — the
  glossary asked *"which of these two does the name mean?"* when the right question was
  *"why are there two?"*
- `this` — ⛔ RETIRED 2026-07-29 (human). the second value of `git tree set --from
  main|this`, while `grove.provision --from main|tree` said `tree` — two words for "the one
  i am in now". the robot logged it as an open dispute and argued it *might* be honest,
  since one flag takes a git ref and the other a directory. the human closed it: "its tree;
  we should use tree". both flags ask the same question — which of the two places on this
  machine? — so both take `main|tree`. `--from this` now errors with the fix
- `duct.uri`'s `*` — ⛔ RETIRED 2026-07-29 (human). `duct.list --on 'duct://grove-1/*'`
  demanded a star that disambiguated no second sense, cost quotes against the shell's
  globber, and implied a glob engine that never existed. replaced by `duct.uri.scope`, a
  plain segment-aware prefix: `duct://grove-1`
- `slug` — ⛔ RETIRED 2026-07-29 (human). the scp-shaped duct address,
  `grove-1:main/mechanic`, taken by `--on` while a `duct://` uri was printed back. two forms
  of one address, so a human could not paste the output into the flag that produced it.
  replaced by `duct.uri` as the only format. the shape was borrowed from scp and never
  earned — `--on` addresses a duct, not a file over ssh
- `sync` — ⛔ RETIRED 2026-07-27 (human). one word, two OPPOSITE directions, and it collided
  with the core verb. its push half became `grove.provision.*`, its pull half `git.repo.pull`.
  the rename landed the same day, so no live contract speaks `sync`; the record is kept
  because a reader who types the old name needs a place that says what it became
- `grove.provision` — ⛔ RETIRED 2026-08-31 (human): *"Full rename — I did mean everywhere"*.
  it beat `install` on the right argument (a machine is never blank) and lost on a wrinkle it
  had already recorded against itself: `upgrade` asserts a DIRECTION the act does not have.
  `provision` carries none, and it is the word `ahbode/infrastructure` already uses — so the
  two halves of one lifecycle now share one verb, and `git.grove.provision` no longer forbids
  the word for the very act it drives. ⚠️ **`bundle.upgrade` is exempt**: `provision` is already
  a phase name inside a bundle
- `grove.provision.grove` — ⛔ RETIRED 2026-07-27 (human). a MACHINE in a slot that names TREE
  SLICES, and a hand-kept second list beside the main one. replaced by
  `grove.provision --for cloud|local`, with the subset DERIVED from per-slice tags. it had
  already drifted: it omitted `brains`, so every grove ran the robot brains with no config
- `grove.provision.for`, and a second dotted form under the now-forbidden noun — ⛔ RENAMED
  2026-07-27 to **`--for`**. both dotted forms
