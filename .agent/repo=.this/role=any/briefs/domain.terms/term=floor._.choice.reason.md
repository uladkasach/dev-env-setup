# domain.term.choice.reason: floor

## .etymology
a floor is what a value may not fall below. the word is already the plain english for a
one-sided bound, and that one-sidedness is the whole design: a discovered set that GREW is
not this gate's concern, because growth is what a healthy tree does when a bundle lands.

`minimum` was the near miss. it is arithmetically identical and it names only the number —
so a reader who meets it learns the count and not the OBLIGATION. every floor in this repo
carries the same two sentences under its halt (*"an empty read is NOT a pass"*, *"either a
bundle changed shape, or this play's reader is broken"*), and those sentences are the term.

`threshold` was declined for symmetry: it reads as a level crossed in either direction, which
would invite an upper bound nobody wants. a set too large is a real defect and it is caught by
a different move entirely — a read of the rows themselves.

## .disputes
### dispute: guard  —  raised 2026-08-14  —  status: RESOLVED (keep `floor`)
- raised.by  = the mechanic
- claim      = "guard" is the plain word for a check that halts, and this repo already says
               "the floor guard" in prose
- counter    = `term=gate._.choice._.md` already refused `guard`, because bhrain's route
               vocabulary binds it to a stone's validation file — one word across two repos'
               contracts. and the objection is stronger here: `guard` would name the ROLE,
               which `gate` already holds, so the specific gate this term is about would go
               unnamed again.
- resolution = keep `floor`; record `guard` as a forbidden synonym. the prose phrase "floor
               guard" is fine — it reads as *a gate of the floor kind*, which is exactly right.

## .evidence

### the measurement that earned the detect/attribute split — 2026-08-14

`prove.flathub-apps-serve` discovered ONE app id where four are declared. its floor fired,
correctly, and printed this and no more:

```
✋ discovered only 1 flatpak app id(s); at least 4 are declared
   found: org.mozilla.firefox
```

the cause was in the play, not the tree. two edits had landed between the reader and its
subject and **neither touched the play**:

| what moved | effect on the reader |
|---|---|
| `flatpak install` → `web_flatpak install` (`src/grove.web.sh`) | spared by luck — the new call HOLDS the old text |
| three ids moved from a `for` loop in an upsert into a `declare -gA` map in `_.sh` | fatal — a map is not a loop, and `_.sh` is not an upsert |

⇒ the floor did its job perfectly and still left a human to guess which of two repairs to
make. that is not a defect in the floor; it is the boundary of what a count can say.

⚠️ and the first row is why the boundary matters. that half still answered, so the reader
**degraded** rather than died — and a reader that fails PARTWAY reads as a subject that
shrank rather than as a broken eye. a total failure is found the same hour; a partial one is
argued with.

### the same shape, the same day

`prove.registry-packages-serve` reported `discovered 0 npm spec(s)` from the same cause —
`web_pnpm install`, plus a `corepack` that had been in no tool set at all. two plays, one
boundary, one class of blindness (`gotcha.a-check-that-cries-wolf-gets-silenced`, m.2 — a
THIRD file changes the shape of the text between a reader and its subject).

### what the repair was, and what it was not

the repair was NOT a lower floor, and not a skip-list. it was a `fixture` — a `direction 0`
that hands the reader one file per declared shape and demands the right verdict on each, with
prose arms that name subjects the real tree does NOT declare, so no arm can pass by collapse
onto a true one (`gotcha.a-check-that-cries-wolf-gets-silenced`, m.8).

⇒ the floor stayed exactly where it was. it is what told a human to go read direction 0.
