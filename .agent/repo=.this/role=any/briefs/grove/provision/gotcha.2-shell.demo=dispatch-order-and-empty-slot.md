# gotcha.2-shell.demo=dispatch-order-and-empty-slot

## .what

the dated measurements behind `2.shell/_.sh`'s dispatch order (why `2.7.aliases` runs
before `2.2.git`) and its empty `2.4` slot.

## m1 — a seam check declined on a fresh box, and the box still converged

measured 2026-08-14, a grove built from scratch, the ground seat's first and only apply.
with `2.2.git` before `2.7.aliases`, `2.2.git/configure.verify.sh` opened `~/.bash_aliases`
to prove its six delegates before `2.7.aliases` had written that file:

```
🌙 whether the 6 delegates are defined cannot be observed —
   no ~/.bash_aliases to read. that absence is 2.7.aliases's ✋
```

`~/.bash_aliases` held the delegates by the end of that same run — the BOX converged; only
the report ran early. "either order lands" was true of the UPSERT and said no word of
the VERIFY. the defect was a claim unproven on every fresh box
(`rule.require.seam-claims-have-an-owner`). the dispatch now runs `2.7.aliases` before
`2.2.git`, against its own number, so the read always follows the write.

## m2 — gh's auth phase failed on every grove run, ~40 bundles before its first consumer

`gh` lives at `5.4.gh`; its real dependency is a CREDENTIAL — the only source of one is
keyrack, which arrives with `5.3.brains`. a number in section 2 would assert a shell
dependency and hide the one that matters. an empty `2.4` slot is what remains after that
bundle moved: a number is an ordinal claim about dependency, never a census. to close
the hole would renumber four bundles no dependency asked to move. a new bundle never
takes `2.4` merely because the slot is free.
