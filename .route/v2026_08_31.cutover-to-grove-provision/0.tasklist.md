
## 🛑 .the ONE unsettled collision — `bundle.upgrade`

a cutover retires `upgrade` as this repo's convergence verb. `bundle.upgrade` is the runtime
that drives one bundle's four phases, and it cannot simply follow:

> **`provision` is ALREADY a phase name inside a bundle.** the four phases are
> `provision.upsert`, `provision.verify`, `configure.upsert`, `configure.verify`.

so `bundle.provision` would name the whole runtime after ONE of the two phase pairs it drives —
a word that means "half of what this does" at the exact site where both halves run. that is an
overload, not a rename (`rule.forbid.domain-term-synonyms`).

| candidate | for | against |
|---|---|---|
| keep `bundle.upgrade` | its subject is a BUNDLE, not a box; the cutover is about the box verb | leaves one `upgrade` alive, so the cut is not total |
| `bundle.provision` | total cut | collides with the `provision.*` phase pair it drives |
| `bundle.drive` | no collision; `driven` is already an itemized term here | a third verb to learn |

⇒ **best guess: keep `bundle.upgrade`.** the cutover's subject is the verb a human types at a
BOX. `bundle.upgrade` is an internal runtime whose subject is a bundle, and no human types it.
⚠️ flagged for the end-of-road council, per `rule.always.defer-fulcrums-to-last` — the rework is
clean either way, since it is one function name with a known call set.

### 🛑 .a FALSE ✋ in boot's own WATCHER — measured 2026-08-31, on the fresh grove

ground's apply **completed** and wrote its success line:

```
🌲 grove.provision done — access prep · server cloud@aws.ec2 · commit none@none
```

and `boot`'s watcher polled past it for the full 2700s, then halted with *"step 2 (ground) does
not hold"*. the marker was in the file the watcher greps, in the last 4 lines it reads.

⇒ the watcher's read is `_ask_at "$seat" "tail -4 $log"`, which rides `--reply`. **every
`--reply` this session returned the BANNER and no payload** — so `tail` was empty on each of
~1350 polls, the grep matched no line, and the loop ran to its bound.

⚠️ the pane shows why the payload is expensive: each poll spawns `zsh -ic`, an INTERACTIVE zsh
that sources this repo's `.zshrc` — starship, fnm, the alias suite. a reply that costs an
interactive shell start, asked every 2s, is a race the reply loses.

⇒ so this is `gotcha.the-duct-returns-the-send-not-the-answer` **one layer in**: `--reply` was
built to stop a send's exit code standing in for a command's, and here it hands back a banner
where the command's stdout belongs. the 97 arm never fires, because the transport did not fault
— it succeeded and carried an empty answer.

⚠️ **and the bound's message is what saved it.** it reads *"that is a BOUND, not a verdict. it
may still be at work"* and prints the read-the-box command. a watcher that had claimed FAILED
would have condemned a converged box (`term=bound._.choice._.md`).
